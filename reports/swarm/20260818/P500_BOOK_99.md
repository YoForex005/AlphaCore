### 1.1 Trade copiers are listed, then immediately downgraded

Quoted in full from “Typical application methods of FIX API in the industry” → **Trade copiers** (https://help.ctrader.com/fix/ , fetched this slot):

> Systems that will automatically replicate trades on multiple trading accounts across multiple brokers or on the accounts of traders are connected to the copier. **However, we believe other Spotware APIs are more suitable for this.**

The same page applies the same “other Spotware APIs are more suitable” sentence to **custom trading interfaces**.

That sentence is **not**:

- a Pepperstone / Spotware license for *this* lab to fire market orders;
- a claim that FIX-copy of 8,463 MT5 challenge logins is +EV;
- a waiver of Architecture §41 / §68 / §70;
- a fill.

It is vendor prose that FIX *can* be used to replicate trades, plus an explicit preference for **other Spotware APIs** for copy.

### 1.2 Why Spotware points away from FIX-only copy

Limitations page (fetched this slot):

> FIX API serves two primary purposes: 1. Receive live market data 2. Perform trading operations

> with FIX API they will not be able to access cTrader account information such as current balance, leverage, margin and more.

> it does not support requests for historical market data.

That page points at **Open API** (https://openapi.ctrader.com/) “to request market data, account information and additional functionality.”

Product implication: `RiskLimits.MaxMarginUsage = 0.70` **cannot be evaluated from FIX**. A FIX-only copier that sprays thousands of source books onto one retail login is flying blind on dest equity. That is worse than the already-downgraded vendor use-case.

Benefits page (fetched this slot) lists lower latency, multi-broker, flexibility, privacy. It does **not** list “copy every prop-challenge login.” Latency is not expectancy.

### 1.3 Official protocol still has `35=D` — on TRADE only

https://help.ctrader.com/fix/specification/ (fetched this slot) lists **New Order Single (Client → cTrader)** among application messages.

Official New Order Single `MsgType(35)=D`:

| Tag | Field | Official note |
|---|---|---|
| 11 | `ClOrdID` | Client unique id |
| 55 | `Symbol` | **Long** — “Instrument identifiers are provided by Spotware” (not the string `XAUUSD`) |
| 54 | `Side` | `1` Buy / `2` Sell |
| 38 | `OrderQty` | Qty; max precision 0.01 |
| 40 | `OrdType` | `1` Market IOC, `2` Limit, `3` Stop |
| 57 | `TargetSubID` | Official examples use **`TRADE`** |

Official market-order example (RoE, fetched this slot):

```text
8=FIX.4.4|…|35=D|…|56=CSERVER|57=TRADE|11=876316397|55=1|54=1|40=1|38=10000|…
```

Server replies with Execution Report `35=8` on TRADE. A living copy system would also need Order Status `H`, Mass Status `AF`, Positions `AN`/`AP`, Cancel `F`/`G`, Security List `x`/`y`, Heartbeat `0`. Official RoE is a **protocol**, not a copier, not a license, not this repo.

Official header `TargetCompID` valid value is **`CSERVER`**. Product POCO default is `cServer` (UI-form spelling). This slot did not send either.

Logon is explicitly not a fill. Official success Logon example is `35=A` both ways. Product hop stops there.

### 1.4 The “other API” is also not a copy-all license

Open API getting started (fetched this slot):

- Trading-oriented apps, demo-then-live recommendation.
- Rate limits: **50 req/s** non-historical, **5 req/s** historical.
- Can access real-time MD, trading ops, **and** past/current/pending operations (the account facts FIX lacks).

Open API terms (fetched this slot) grant a **limited, non-exclusive, non-assignable, non-transferable** license to develop/test/support an app. They also say:

Copying **8,463 other people’s** Achiever/Starwave challenge logins onto one Pepperstone book is not “the trader’s explicit prior approval.” Switching from FIX to Open API does **not** mint an edge and does **not** authorize spray-copy.
