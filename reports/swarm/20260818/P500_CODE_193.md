## Angle

Are the martingale and averaging **filters** in (or specified by) `docs/ctrader-fix.md` strong enough to cut the left tail of copied or would-be-copied XAU books — same-position grid / double-down / add-at-worse-price blow-ups — given live census **8463** accounts, Achiever scoring, Starwave deals-done scored **0**, SHADOW-all-demo, dest real P&L **0**, FIX LoggedOn, `REAL_COPY` **false**?

“Filter” here means a gate that **removes** that book from dest size or `35=D`. A FIX logon, a 30-point slippage flag, or a global `REAL_COPY=false` kill is not a martingale/averaging filter. Copying **winning** MT5 trades (this file’s stated purpose) without a recovery-pattern reject **selects** the left tail: recovered grids look like winners until the next add does not recover.

## Verdict

**FAIL — no. Martingale and averaging filters in this file are not strong enough to cut the left tail, because they do not exist.**

What the FIX doc actually specifies:

- **Copy policy:** copy **winning** challenge trades onto a real-money cTrader hedge. That is an execution intent, not a left-tail screen. A recovered martingale/grid is a “winner” on the source tape.
- **Pre-trade check:** local order book for **price** validation only. No lot-path, no add-count, no VWAP-worse add, no sequential 1.25× after a closed loss.
- **Recon:** fill price / volume / timing vs MT5; **30-point** slippage flag. That is venue-quality, not behavior.
- **Unknown state:** never re-submit a lost `ExecutionReport`. Prevents double-send, not grid blow-ups.
- **Live-send lock:** `REAL_COPY_EXECUTION_ENABLED=false` **simulates** orders. That is a global dest-capital lock. It is **not** a martingale filter and **not** an averaging filter. Flip the flag and this runbook still has nothing that refuses a doubled-down winner.

Adjacent product (not this file; quoted so the FAIL is not a docs-only nit):

- `docs/scoring.md` (10 lines): “Martingale / large sequential size-up after losses ⇒ `RISK_BLOCKED`.” No averaging reject. No thresholds.
- `docs/risk.md`: daily/total loss, 50-lot / 25-position / 100-trade / 30-point slippage, kill switch, flatten, 100–2000 ms copy window. **Zero** martingale / averaging identifiers.
- `docs/trade-reconstruction.md`: VWAP IN/OUT, first-3 completed. **Zero** `was_averaged_down`. Adds are just more IN volume.
- `BaselineScorer`: inter-**completed-trade** 1.25× after a **closed** loss → `Martingale`; `AveragingDown = Any(WasAveragedDown)`. Risk **+35 / +20**. `RISK_BLOCKED` only if `risk >= 80` **or** `(Martingale ∧ MaxDrawdown > 0 ∧ NetPnl < 0)`. Averaging alone = risk **20**, never 80. A **winning** recovered grid is often `Martingale=false`, `AveragingDown=true`, `risk=20`, and can land **`SHADOW`** (`quality >= 70 && risk < 40`).
- `RiskEngine`: `BlockMartingale` on a caller-supplied `MartingaleFlag`. **No** averaging field on `RiskEvaluationRequest`. Averaging is invisible to dest risk.
- `CopyTradingService`: dest qty = `Normalize(trade.MaxVolumeLots, …)` (the **basket** after adds). `MartingaleFlag = score.Martingale` (inter-trade, not intra-position). Persist `AllowFixSend = false` on that path today.

- Achiever scoring can tag some books; Starwave **deals-done scored 0** means that broker’s left tail is **unscored**, therefore unfiltered by the scorer, and this FIX doc has no substitute filter.
- SHADOW all demo + `destinationRealPnl` **0** + `REAL_COPY` **false** means dest left tail is cut by **not sending**, not by anything in `ctrader-fix.md`.
- FIX **LoggedOn** is session state. A logged-on TRADE session with no behavior reject is readiness to send, not a left-tail cut.
