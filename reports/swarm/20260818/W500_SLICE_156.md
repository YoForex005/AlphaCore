## 0. Verdict

## 4. No-loss implication

**No capital at risk from this angle.**

- `DemoSeeder` does not send FIX, does not build `NewOrderSingle`, and does not flip copy on. Seeded FIX rows in this file are `FixSessionStatus.Disconnected` with “NewOrderSingle off.”
- Dashboard visibility cannot execute a copy. An operator who never sees a login cannot size or approve a live intent from this seeder.
- Empty / not-yet-scored accounts stay on `/traders` as `INSUFFICIENT_DATA`. They are not silently treated as WATCH/SHADOW/LIVE.
- State machine: `N == 0` cannot become `LIVE`. Integration lock: 10001 “not LIVE”; 10002 `RISK_BLOCKED`.
- Hiding (if it existed) would be an **observability** miss on the demo leaderboard, not a fill. The live path scores every `ListLoginsAsync` login before the dashboard is the operator’s census.

Residual (honesty, not a capital FAIL):

1. Seeder score set is a literal, not `ListLoginsAsync` — factory drift could leave a demo account **unscored** (still listed).
2. Overview Watch/Shadow/Live tiles ignore no-score / `INSUFFICIENT_DATA` — counts can look “empty” while `totalAccounts` is not.
3. A92 L7 still open: `N<3` publishes numeric early/risk (10003 `EarlyScore=40` in C23), so the empty account is **over-ranked**, not hidden.
4. A005 “traders = scores only” is stale and must not be reused as current evidence.
