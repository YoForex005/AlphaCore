## 3. Why Starwave can sit at `scored=0` with 91,966 deals

This is a **pipeline queue**, not a “Starwave has no XAU” fact.

### 3.1 Three sequential waves, Achiever first

`LiveMt5Registration.CreateConnectors` returns `{ ACHIEVER, STARWAVEFX }` (`LiveMt5Registration.cs` L49). DI registers those two as singletons in that order (`DependencyInjection.cs` L47–50). `BrokerRegistry` `ToDictionary` then `All()` preserves insertion order on net8. `LiveIngestHostedService.ExecuteAsync` then runs **three** `foreach (var connector in connectors)` loops:

1. **Catalog** both brokers (`phase=catalog` → `catalog-done`).
2. **Deals** both brokers, 90-day window (`phase=deals` → **`deals-done`**, writes `DealsInserted`).
3. **Score** both brokers (`phase=scoring` → `done`).

Starwave finished loop 2 (`dealsInserted=91966`, `phase=deals-done`). Loop 3 is still on Achiever.

`BrokerLiveStatus.Scored` is an `int` defaulting to **0** (`LiveRuntimeStatus.cs` L14) and is **only assigned inside loop 3** (every 25 logins, then the final count):

```109:125:D:\Prop\src\Infrastructure\Hosting\LiveIngestHostedService.cs
                    var scored = 0;
                    foreach (var login in logins)
                    {
                        stoppingToken.ThrowIfCancellationRequested();
                        await scoring.RebuildTraderAsync(connector.BrokerCode, login, stoppingToken);
                        scored++;
                        if (scored % 25 == 0)
                        {
                            st.Scored = scored;
                            st.UpdatedAt = DateTimeOffset.UtcNow;
                        }
                    }

                    st.Scored = scored;
                    st.Phase = "done";
```

Until Starwave enters that loop, `Scored` stays **0** and `Phase` stays **`deals-done`**.

**Slot-89 discriminator (do not misread a lagging counter):** `st.Phase = "scoring"` is written **before** the login loop (`LiveIngestHostedService.cs` L107). `st.Scored` is **not** written until `scored % 25 == 0`. So `scored=0` *alone* could theoretically mean “0–24 logins in, counter not flushed.” **`phase=deals-done` rules that out.** The pin is a **queue stall**, not a stale counter.

Hosted scoring walks `ListLoginsWithDealsAsync` = `Mt5Deals.Where(BrokerId).Select(Login).Distinct()` (`EfTradingStore.cs` L343–345). After 91,966 Starwave upserts that set is **non-empty**. `scored=0` is **not** “zero deal logins.” Sibling notes that treat it as an empty tape are **wrong for this snapshot**.

Manual `POST /api/ops/resync` is a **different grain**: it scores `ListLoginsAsync` (all catalog accounts), Achiever then Starwave, and would block the HTTP request for the full book (`Program.cs` L114–146). It was **not** invoked this slot.

`GET /api/ingest/status` is `LiveRuntimeStatus.Snapshot()` (`Program.cs` L60) — that is where `dealsInserted=91966` / `scored=0` / `phase=deals-done` were measured.
