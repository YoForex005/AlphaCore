## 0. Verdict (ADMIT / REMOVE / FLATTEN)

**Required (T2 / this topic):** a completed-XAU streak of **≥ 3** (`NetRealizedPnl < 0` on the newest closed tickets) must **not ADMIT**, must **REMOVE** the login from the dest copy set (latch; stop new dest opens), and must **FLATTEN dest remaining** for that login only. **Never flatten the MT5 source.** `CloseExposure` after remove must stay legal. This is a per-login dest loss-cut, not `KillSwitchMode.EmergencyFlatten`.

**Implemented today:** domain **REMOVE+dest-flag** exists **only if already on roster**. The 20 s hop **does** persist `REMOVED:CONSECUTIVE_LOSSES_N` and mint `FLATTEN_LOSS_CUT` close intents. It does **not** pause `TraderState`. It does **not** latch. After REMOVE, `alreadyOnRoster` becomes **false**, so the same still-green L-L-L book is **AUTO_ADMIT** on the next tick. `RiskEngine` has **no** streak field. Live dest send is **absent**.

## 1. What “pause and flatten” is (and is not)

Architecture §39 lets risk **pause trader**. §40 / A48: `STOP_NEW_EXECUTION` leaves dest inventory; `EMERGENCY_FLATTEN` is SuperAdmin dest-book panic. P503_S03 T2 is the binding cut for this slot:

| Id | Trigger | Effect |
|---|---|---|
| **T2** | Last **3** completed XAU trades have `NetRealizedPnl < 0`. Scratch `== 0` **breaks** the streak. `n ≥ 3`. | Remove + dest flatten this login. Allow dest close after. **No MT5.** |

That is **not**:

- `RiskEngine` `MAX_LOSS_PER_TRADER` ($500 dest realized on **every** action, including close — L117–118). That **freezes** flatten if it ever sees honest dest loss.
- `KillSwitchMode.EmergencyFlatten` (blocks **new** only: `EMERGENCY_FLATTEN_BLOCKS_NEW`).
- Source `CLOSE_EXPOSURE` when the MT5 ticket happens to close.
- Operator `TraderState.PAUSED` (S03 §3.1: pause is temporary; T2 is a **risk latch**, prefer `RISK_BLOCKED`).

Pause of **new dest opens** and flatten of **existing dest remaining** are two verbs. Topic requires **both**. Remove without flatten leaves dest gold to bleed (P503_S01). Flatten without a latch + ADMIT-forbid lets the hopper put it back on.

## 6. ADMIT / REMOVE / FLATTEN implication (slot 26)

For a login whose **last three completed XAUUSD reconstructions lost money**:

| Verb | Do | Do not |
|---|---|---|
| **ADMIT** | Refuse `AUTO_ADMIT` / `KEEP` while streak ≥ 3 **and** while a T2 latch is set. | Treat “net still +$365” as permission to copy the next ticket. Re-admit off a `REMOVED:` row without a new sample + human reclaim. |
| **REMOVE** | Evict dest membership. Stop `OPEN`/`INCREASE`. Persist a **latch** (`RISK_BLOCKED` + `LOSS_CUT_THREE_CONSECUTIVE_XAU_LOSSES`). | Call that `TraderState.PAUSED`. Use `RiskEngine.PauseTrader` as if it closed dest. Use desk `EMERGENCY_FLATTEN`. |
| **FLATTEN** | Queue dest `CLOSE_EXPOSURE` for **mapped dest remaining** of this `source_login` only. Persist-before-send. Allow that close after remove. | Flatten Achiever/Starwave. Size from source lots / `AllocationFactor=1`. Spray the whole Pepperstone login. Send `35=D` from this slot. |

`CopyRosterEngine` already **names** REMOVE+dest-flatten. `TickRosterAsync` already **writes** the strings. The implication of this slot is that those names are **not** the control: **ADMIT is still legal on a hot streak**, **REMOVE does not stick**, **FLATTEN does not hit a venue**, and **the trader is not paused**.
