`D:\Prop\src\Domain\Reconstruction\TradeReconstructor.cs`

Rebuilds MT5 deal streams into position lifecycles. Same-side `DealEntry.In` calls `OpenTrade.ScaleIn`. Averaging-down is a **boolean latch** (`WasAveragedDown`) when the add is worse than current entry VWAP. ## Angle

Are the martingale and averaging “filters” in this reconstructor (and the only downstream consumers of its flags) strong enough to cut the left tail of XAU books — intra-ticket grids, size-up-after-loss, recovered martingales — on a measured book of ~8463 accounts (Achiever scoring, Starwave deals-done scored 0), with SHADOW demo-only, `destinationRealPnl` 0, FIX LoggedOn, `REAL_COPY` false?

---

## Verdict

**FAIL — no. The filters are not strong enough to cut the left tail.**

This file is a **netting book with two latches** (`WasScaledIn`, `WasAveragedDown`). It is **not** a martingale detector and **not** an averaging rejector. Every same-side add is booked. The averaging bit has no size, count, or distance. Downstream scoring treats averaging as **+20** risk and martingale as **+35**, and only hard-blocks a **losing** martingale (or `risk >= 80`). Intra-position doubling never becomes `Features.Martingale`. Production scoring scores **all** completed XAU, including averaged tickets. Shadow persist copies those tickets at **`MaxVolumeLots`**.

Destination capital is unhurt **today** because `REAL_COPY` is false, SHADOW is demo, and `destinationRealPnl` is 0 — **not** because these filters work. Starwave’s 1948-login book is not even feeding the flags (`deals-done scored 0`).

        public void ScaleIn(NormalizedDeal deal, decimal lots)
        {
            // Averaging down: add to a long after price fell, or to a short after price rose.
            var worse = Direction == TradeDirection.Long
                ? deal.Price < EntryVwap
                : deal.Price > EntryVwap;
            if (worse)

## Profit implication

These flags cannot harvest a clean XAU book.

- Averaging winners and recovered grids still reach `SHADOW` (`risk` 20 or 35, quality boosted by `NetPnl > 0` / PF). Those are the first names a later `REAL_COPY` flip would copy.
- Win rate on averaged books is **manufactured**: losers are added-to until they scratch. Destination would take **`MaxVolumeLots`**, so the unrecovered grid is also the largest copied size.
- Starwave scored **0** means ~1948 logins contribute **no** ranked edge. Achiever scores that survive the soft +20/+35 nudge are not dest-proven (`destinationRealPnl` 0).
- Binary `Any(WasAveragedDown)` also **kills ranking**: one 0.01 add-in-loss equals a 20-rung grid. A usable scale-in of 10% after 0.1 point is scored like a martingale. That parks real edge in extra risk points and keeps true grids in `WATCH`/`SHADOW` instead of `RISK_BLOCKED`.
- `docs/scoring.md` says “Martingale / large sequential size-up after losses ⇒ `RISK_BLOCKED`.” The implemented surface only does that for **net-losing** books. Operators who trust the doc will treat green martingales as copy candidates.

Turning copy on without an intra-position peak/initial lot reject monetizes the **right** tail of grid traders and eats the **left**.

## Lower-loss implication

**Today’s left-tail cut is the execution pin, not this file.**

`REAL_COPY false` + SHADOW demo + `CanPromoteToLive => false` + `destinationRealPnl` 0. If those pins move, `TradeReconstructor` will **not** stop:

| Failure | Why this file / chain lets it through |
|---|---|
| Unbounded same-ticket adds | `ScaleIn` always `RemainingLots += lots`; no cap |
| Intra-position 2×/4×/8× | Never becomes `Features.Martingale` |
| Multi-ticket grid / hedge | Grouped by `PositionId`; tickets never merge; often not averaged |
| Recovered martingale | `NetPnl > 0` skips `RISK_BLOCKED`; can `SHADOW` |
| Open averaged loser | Features use **completed** trades only; next add would copy before DD updates |
| Averaging + no SL | `SlUseRate < 0.3` is +10 risk; still far from 80 |
| Equal-price grid | `worse` is strict `<` / `>` |
| INOUT reverse-and-reload | New `OpenTrade.Start` is clean; average flag does not carry |
| Starwave left tail | Deals-done scored 0 → flags never computed |

XAU left tail is inventory explosion on one idea. This reconstructor **records** that inventory and **labels** worse-price adds, then hands the lifecycle to a scorer that treats the label as a 20-point nudge. That is a dashboard badge (`MG` / `AVG` on `TradersPage`), not a tail cut.

Keep `REAL_COPY` false until intra-position `MaxVolumeLots / InitialVolumeLots` is a **hard** dirty/reject, averaging is a copy block (not +20), and recovered martingales cannot `SHADOW`. Do not treat Achiever score volume as evidence the tail is cut.
