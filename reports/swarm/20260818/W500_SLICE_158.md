## 1. What the assigned file actually is

`CTraderFixSession` is a **FIX 4.4 logon probe**. One public method: `TryLogonAsync`. It:

1. TCP-connects to `host:sslPort` with a **20-second** linked CTS.
2. TLS 1.2/1.3 handshake (`SslStream`).
3. Sends a single Logon (`35=A`) with sender/target/sub IDs, username, password.
4. Reads one 4 KiB reply.
5. Returns `LoggedOn=true` only if `35=A`; otherwise `LoggedOn=false` with `35` + tag 58 text, or `Disconnected` on exception.

Supporting private helpers: `BuildLogon`, `Assemble` (FIX.4.4 body + checksum tag 10), `Extract` (pipe-split tag lookup). Result type: `CTraderFixSessionResult`.

There is **no** Manager API, **no** `DealRequest*`, **no** history range, **no** group mask, **no** deal DTO, **no** ingest window, **no** `NewOrderSingle` / `35=D`.

Sole production caller is the FIX logon host, which probes QUOTE then TRADE and explicitly leaves real copy off:

## 4. No-loss implication

**None from this angle on this file.**

`CTraderFixSession` does not pull 90 days of group deals, does not call Manager `DealRequestByGroup`, and does not send FIX order or trade-capture messages. A slow or failed logon returns `LoggedOn=false` / `Disconnected` and cannot leave a partial deal book, skip a chunk, or time out a 90-day history dump.

Capital path: the only live caller sets `RealCopyEnabled = false` and states NewOrderSingle is still disabled. This file cannot size, send, or omit a copy order because of an unchunked Manager request.

The omission/timeout risk named by the angle (Manager `DealRequestByGroup` on an unsplit 90-day span → request death → missing source deals → reconstruction/copy on an understated book) **cannot fire from `CTraderFixSession.cs`**. That risk, if any, belongs to the MT5 ingest connector — which already iterates 14-day windows.
