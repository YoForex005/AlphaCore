## 3. Spec vs product (why the name lies)

Architecture §39 lists `max loss per selected trader` as a hard limit. A23 §3.4 wants `trader_realized_pnl` / `trader_unrealized_pnl` **per selected trader** and `trader_open_exposure` **per copied trader**. A23 §6.4: `REJECT` + optional `PAUSE_TRADER` on the book/account/trader caps. A71 G21:

| Action | Required |
|---|---|
| OPEN / INCREASE | Block + `PAUSE_TRADER` |
| REDUCE / CLOSE | **Approve** — do **not** trap a losing dest position |

Product inverts G21: the cap applies to **every** action, the input is **not** per-trader dest PnL, and `PauseTrader` does not persist.

`KillSwitchMode.EmergencyFlatten` (engine L81–82) only blocks `IsIncreasing`. It does **not** emit dest close orders. If flatten later calls `Evaluate(CloseExposure)` after dest is already `<= -500`, **this line fires first** and rejects the flatten.

## 4. ADMIT / REMOVE / FLATTEN implication (slot-2 contract)

This slot sits on the P503 admit/remove/flatten wave (see `P503_S01_no_auto_remove.md`, `P503_S02_auto_add.md`).

### ADMIT

- Implicit admission is **score state** `{SHADOW, LIVE_CANDIDATE, LIVE}` on the 20 s poll (P503_S02). `MaxLossPerTrader` is **not** on that gate.
- A `MAX_LOSS_PER_TRADER` decision does **not** un-admit the login. The same name is still copyable next poll.
- A second open from the same login is a **new** Evaluate with that ticket’s PnL. Ticket A at −$500 does not stop ticket B.
- **Do not ADMIT this check as “per copied trader protection.”** If a sender is ever built: ADMIT it as an **open-family only** dest-per-login loss cap, after the caller is rewritten to pass dest realized + unrealized for that `SourceLogin`. Until then it is a label.

### REMOVE

- Outcome `PauseTrader` ≠ remove dest copies. No roster row to delete (P503_S02: no roster table).
- Do **not** write `TraderState.PAUSED` from this outcome: `IsTraderEligible` would then reject **closes** (`TRADER_BLOCKED_PAUSED`) and trap dest (P503_S01 + A71 G20/G21).
- Correct later-fail shape (already in the hopper): `IsTraderEligible` false → `continue` the trader → **skip new opens**, leave existing dest (and existing shadow rows) alone.

### FLATTEN

- **This cap must never trigger flatten.** $500 already spent is not a reason to market-dump dest (and **never** source MT5).
- **This cap must never block flatten.** REMOVE `TraderRealizedLoss` / `DailyExecutionPnl` / `PortfolioDrawdown` from the reduce/close/emergency-flatten path (`IsIncreasing` only, G21–G23).
- Product flatten is **MISSING**. Wiring `Evaluate` onto a future dest flatten without that guard is dest-ruin (inventory stuck after the loss).
- `docs/risk.md` “Total loss → Emergency Flatten” is **not** implemented and is **not** this $500 line.
