## Angle

**Are martingale and averaging filters strong enough to cut the left tail?**

**No.**

Left tail here means the fat losing side of a copied book: size-up after losses, add-to-losers, grids that print a few winners then a blow-up. Cutting it requires (1) detect the pattern, (2) refuse new dest exposure, (3) refuse even when the source book is **net profitable so far**.

`docs/ctrader-fix.md` implements **none** of those three. The TRADE recipe is an unfiltered copy:

> 1. **NewOrderSingle** (MsgType=D) — market or limit order with ClOrdID, symbol, side, quantity, price
> 2. **ExecutionReport** (MsgType=8) — cServer confirms fill with ExecType, AvgPx, CumQty, LeavesQty
> 3. Match ExecutionReport.ClOrdID back to the originating MT5 copy-trade request

That is size-and-send. A source martingale ticket would be copied 1:1 if this hop were armed.

The only send inhibit in this file is global simulation, not a pattern filter:

> 5. `REAL_COPY_EXECUTION_ENABLED=false` disables live execution; orders are simulated for testing

That switch also kills the **right** tail. It is not a martingale/averaging filter.

Post-fill recon in the same file (30-point slippage flag, unreconciled alert, never re-submit unknown state) is **after** dest risk is already on. Recon cannot cut a left-tail fill that already happened.
