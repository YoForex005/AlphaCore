## Verdict

**YES — a copy-every-scored-XAU policy is expected to lose money if it were live.** `RiskEngine.Evaluate` never sees `TraderState`. There is no request field and no reason code for `RISK_BLOCKED`. Spec token `TRADER_RISK_BLOCKED` is **never emitted**. The engine cannot refuse a name *because scoring already labeled it a martingale loser / risk ≥ 80*.

Martingale is blocked **only if the caller sets `MartingaleFlag=true`**. Caps (`MaxXauGross=20`, `MaxXauNet=10`, `MaxOpenPositions=20`, `MaxPositionQuantity=5`) are last-ditch size brakes on caller-supplied snapshots, not a quality screen. `MAX_XAU_NET` is labeled `ReduceSize` but goes through `Reject()` → `ApprovedQuantity=0` (hard stop, not a clip). `MaxSlippage=1.5` is declared and **never read**. Loss/DD checks apply to **every** action, so a red dest day **cannot exit** through this method.

**Current dest is not losing.** `AllowFixSend` requires `RealExecutionEnabled` (live `REAL_COPY false`). The empty `if` on lines 90–93 does not reject — it still `APPROVE`s. Unit `Real_flag_false_never_allows_fix_send` asserts `Outcome=Approve` and `AllowFixSend=false`. Product persist (`CopyTradingService`) hard-writes `AllowFixSend=false`, keeps `VenueReconciled=false` (so increasing intents fail `VENUE_NOT_RECONCILED` *if* they reach `Evaluate`), and only *selects* `SHADOW` / `LIVE_CANDIDATE` / `LIVE` — **not** `RISK_BLOCKED`. SHADOW is all demo. `destinationRealPnl` is constructor literal **0**. FIX LoggedOn is session, not send. Starwave scored **0**.

Do **not** flip `REAL_COPY` and spray every Achiever score onto one Pepperstone gold book. That is the losing path this file fails to stop by state.

## Profit implication

**Copy-every-scored-XAU is not a profit path.** The scored class that is **blocked** is defined as a losing martingale (or risk ≥ 80). A book whose left tail is −$241,580 and whose **all-scored** sum is −$154,425 is a **negative-expectancy** source tape. Putting every Achiever score onto one Pepperstone/cTrader XAU dest would:

1. Align dest with **one** correlated metal (no Phase-2 concentration cap in this engine).
2. Include the `RISK_BLOCKED` dollar-majority as if they were `SHADOW` quality — unless the caller happens to set `MartingaleFlag`.
3. Size up after source losses whenever that flag is forgotten (copy service passes `score.Martingale` today; a copy-all rewrite that skips scores would not).
4. Hit 10 net / 20 gross lots of the **same** metal, then hard-zero further adds — leftover dest stays long/short the losing cluster.
5. On the first −500 / −2_000 / 3_000 dest day, **refuse to close** (loss/DD checks are not increase-only).
6. Ignore slip (`MaxSlippage` unread) and hold time (scorer computes `AverageHoldSeconds` and does not use it). Gold scalps + 15s `MaxSourceSignalAge` + dest spread destroy the remaining “good” names.
7. Copy **demo challenge** SHADOW (`demo\yo-2step` / `demo\yo-payp`) that exist to pass a profit target — not OOS dest edge.

Starwave deals-done scored **0** adds **no** XAU edge. Achiever scoring of thousands of catalog logins is observation, not 8463 copy candidates. FIX LoggedOn does not monetize scores. With `REAL_COPY false` and `destinationRealPnl` **0**, there is **no** live dest profit and **no** live dest loss from this file.

Even a “smarter” copy of only SHADOW+WATCH is **not** proven dest-positive: SHADOW is 100% demo; quality can be 95.5 with **negative** dashboard PnL; first-3 XAU is not future dest PnL.

## Lower-loss implication

**Lower dest loss = do not copy every score. Filter `RISK_BLOCKED` (and `INSUFFICIENT_DATA` / `EARLY_SCORE`) before any intent.** Keep `REAL_COPY` false until a state-aware gate exists **and** this engine reads that state.

What this file already does that limits loss **if** a naive copy-all were wired with honest book snapshots **and** honest flags:

- `AllowFixSend=false` when `RealExecutionEnabled=false` (today’s measured floor).
- `MARTINGALE_BLOCK` / `ABNORMAL_SIZING_BLOCK` if the caller actually sets the flags — and **all** current `RISK_BLOCKED` names are martingale, so an honest flag would stop *that* cohort’s **new** size.
- Gross 20 / net 10 / 20 slots / 5 lots per ticket — a size ceiling, not a quality filter.
- `Reject` always `AllowFixSend=false`.
- Product copy set already **excludes** `RISK_BLOCKED` (`SHADOW`/`LIVE_CANDIDATE`/`LIVE` only). Keep that. Do not widen it to “every score.”

What this file does that **worsens** dest loss once a copy-all book exists:

- Ignores `TraderState.RISK_BLOCKED` (the dominance signal).
- Freezes reduce/close at trader-loss / daily-loss / portfolio-DD.
- `MAX_XAU_NET` “reduce” is a zero-qty reject (no clip to remaining cap).
- No dest identity — cannot flatten what it approved.
- `MaxSlippage` is decoration.
- Caller today zeros `DailyExecutionPnl` / `PortfolioDrawdown` / `CurrentGrossXau` / `CurrentNetXau` / `OpenPositions` and uses **per-ticket** `NetRealizedPnl` as `TraderRealizedLoss` — so the caps this file advertises **do not run** on a real dest book.

Today’s dest loss floor is **absence of send** (`NewOrderSingleImplemented=false`, persist `AllowFixSend=false`, `VenueReconciled=false`, `REAL_COPY false`, `destinationRealPnl=0`), not this gate. That matches SHADOW-all-demo. Do **not** enable live copy of the scored book to “use” this engine.
