## 0. Verdict (binding)

**On-roster: YES REMOVE + dest-FLATTEN. Off-roster ADMIT: DD is ignored, so REMOVE is not sticky.**

Peak-to-trough is **completed XAU closed-trade equity**, start `eq=0`, `peak` = running max, `drawdown` = max(`peak − eq`). Default cut is **`drawdown / peak >= 0.40`** (`RosterLimits.MaxDrawdownVsPeak`). Reason `DRAWDOWN_FROM_PEAK`. Action `RosterAction.RemoveAndFlatten`.

| Verb | What the code does | Implication |
|---|---|---|
| **ADMIT** | `alreadyOnRoster == false` **skips** the DD predicate. If `IsTraderEligible` still passes (net `> 0`, n≥20, SHADOW+, not demo, no size-pattern), `Decide` returns `Admit` / `AUTO_ADMIT`. `TickRosterAsync` writes `CopyIntent.Status = "ADMITTED"`. | A 70% lifetime giveback that is still net-green is **admitted**. After a DD remove, `onRoster` becomes false (`Status != "ADMITTED"`), so the **same** book is **re-admitted on the next 20 s tick**. |
| **REMOVE** | `alreadyOnRoster && peak > 0 && drawdown/peak >= 0.40` → `Remove("DRAWDOWN_FROM_PEAK")`. Hop sets `Status = "REMOVED:DRAWDOWN_FROM_PEAK"` and `Action = CloseExposure`. `GenerateShadowIntentsAsync` then `continue`s unless `Status == "ADMITTED"`. | Stops **new** copy while the row stays `REMOVED:*`. Does **not** stay removed: see ADMIT flicker. Net `<= 0` is a **different** reason (`XAU_BOOK_TURNED_NEGATIVE`) and fires first. |
| **FLATTEN** | `Remove()` always sets `FlattenDestination = true`. Hop calls `FlattenOpenCopiesAsync` and inserts dest `CloseExposure` intents (`Status = "FLATTEN_LOSS_CUT"`, key `copy:{broker}:{login}:{pos}:close`). Class comment: dest-only. ## 3. ADMIT hole — why REMOVE does not stick

Worked sequence for the **tested** curve (net still **+300**, ratio ≥ 40%):

| Tick | `Status` | `onRoster` | `Decide` | Copy hop |
|---|---|---|---|---|
| T0 (no row) | — | false | **ADMIT** (`AUTO_ADMIT`; DD skipped) | Opens any still-open source XAU 1:1 |
| T+20s | `ADMITTED` | true | **REMOVE** `DRAWDOWN_FROM_PEAK` | `FLATTEN_LOSS_CUT` closes for `copy:` opens; no new opens |
| T+40s | `REMOVED:DRAWDOWN_FROM_PEAK` | **false** | **ADMIT** again | New source tickets (new `copy:` keys) are copied |

`XAU_BOOK_TURNED_NEGATIVE` **is** sticky by accident: after remove, `onRoster=false` skips `net<=0`, then `IsTraderEligible` fails `XAU_BOOK_NOT_PROFITABLE` → `Keep` / `NOT_YET_*` and the row stays `REMOVED:*`.

`DRAWDOWN_FROM_PEAK` is the case that **keeps net > 0**, so eligibility still passes. **This slot’s reason is the flicker.**

Same flicker applies to `CONSECUTIVE_LOSSES_*` when the book is still green. Not this topic, same `alreadyOnRoster` guard.
