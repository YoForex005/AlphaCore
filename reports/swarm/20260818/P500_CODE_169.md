## Verdict

**SCORER_NOT_A_PROFIT_GATE.**

Negative `netSourcePnl` on a SHADOW row is **allowed by construction**. The API host never filters on source PnL. The scorer it calls treats `NetPnl > 0` as a **+15 quality bonus**, not a veto. `FromBaseline` emits `SHADOW` when `quality >= 70 && risk < 40`. A disciplined losing book (3+ completed XAU, no martingale / average-down / lot-escalation, SL used, low lot CV) scores:

`quality = 50 + 0 (neg net) + 0 (PF < 1.2) + 100×0.2 − 0 = 70` → **SHADOW**.

That is the opposite of a profit gate. SHADOW here means “behavior looks copyable,” not “source book made money.”

| Question | Answer |
|---|---|
| Is the scorer a **profit** gate? | **No.** Sign of `NetPnl` / `netSourcePnl` does not block SHADOW. |
| Can SHADOW + negative source PnL coexist? | **Yes.** State and PnL are independent columns. |
| Does this host refuse losers? | **No.** Resync scores every login. `/api/traders?state=SHADOW` does not require `netSourcePnl > 0`. |
| Does this create dest profit? | **No.** `destinationRealPnl` is 0. `REAL_COPY` false. No `35=D`. |
| Does this spend dest capital today? | **No.** NewOrderSingle still off. SHADOW is demo / `SHADOW_ONLY`. |
| Empty PASS? | **No.** 160 lines read. Finding is a missing gate, not an empty file. |

One-line: **this host will score and list a losing Achiever book as SHADOW; that proves scoring is a behavior/risk classifier, not a profit filter.**

## Profit implication

**The scorer does not select profitable books. It cannot create destination profit either.**

| Path | Profit effect now |
|---|---|
| `POST /api/ops/resync` | Scores **all** catalog logins (8463-class census). Losers and empty books included. No dest fill. |
| Achiever scoring | A disciplined losing XAU book can land **SHADOW** (`quality==70`, `risk==0`). Source edge is **not** required. Source edge is **not** copied to cTrader. |
| Starwave deals-done scored 0 | Empty deal-login set on the worker path. Host resync would still call `RebuildTraderAsync` per catalog login and persist `INSUFFICIENT_DATA`. **Zero** dest opportunity from that book. Not a profit refuse. |
| `GET /api/traders?state=SHADOW` | Can list `netSourcePnl < 0`. Operator must not read SHADOW as “this login is +EV.” |
| SHADOW all demo | `SHADOW_ONLY` intents + simulated slippage. `TraderRowDto.ShadowPnl` is hardcoded **0**. Overview shadow tile is `SUM(SourceVsShadowSlippage)`, not cash. |
| `destinationRealPnl` | Literal **0**. Dashboard cannot show dest profit if a loser (or winner) is SHADOW. |
| FIX LoggedOn + `REAL_COPY false` | Session may be up. Host still prints `NewOrderSingle still off`. LoggedOn ≠ P&L. |

If someone later arms `REAL_COPY` and implements `35=D` **without** adding a source-PnL / expectancy gate, SHADOW losers become the copy set. That would **destroy** dest capital, not harvest source winners. Do **not** treat SHADOW count as a profit pipeline. There is no profit gate behind this door.

Adding `if (NetPnl <= 0) skip SHADOW` would change the classifier. It is **not** present. Flipping `REAL_COPY` to true would still leave dest PnL at the dashboard literal 0 until a fill ledger exists.
