## 0. Verdict (binding) — ADMIT / REMOVE / FLATTEN

**Law (should):** a completed-XAU streak of **≥3 losses** (`NetRealizedPnl < 0`, scratch `== 0` breaks) **must REMOVE** the trader from the copy set, **pause new opens**, and **FLATTEN dest copies of that login only**. Never flatten MT5 source. Close after remove must remain legal. Latch: a later print must not silently re-ADMIT (P503_S03 T2).

**HEAD (is):** domain + hop implement **REMOVE + dest-flatten intent** only while `alreadyOnRoster`. They do **not** pause `TraderState`. They do **not** latch. They do **not** send.

### 3.1 REMOVE on streak

`TickRosterAsync` L116–120: roster membership is `CopyIntents` row `IdempotencyKey == roster:{broker}:{login}` **and** `Status == "ADMITTED"`. Then `Decide`. On `RemoveAndFlatten`:

- insert or update that row to `Status = "REMOVED:" + decision.Reason`, `Action = CloseExposure`
- if `FlattenDestination`, call `FlattenOpenCopiesAsync`

That is **REMOVE** of a **synthetic roster row stored as a CopyIntent**. It is not `TraderState.PAUSED`.

Grep of `src/` for `CurrentState =` writers: ingestion (`SuggestedState`) and `EfTradingStore` (persist scorer). **`CopyTradingService` never assigns `CurrentState`.** A streak cut leaves the score in `SHADOW` / `LIVE_CANDIDATE` / `LIVE`. Architecture §39 `pause trader` is a **RiskEngine outcome**, not this hop.

### 3.2 ADMIT latch hole (binding defect)

Next tick after REMOVE:

```
onRoster = (row != null && row.Status == "ADMITTED")  → false
Decide(..., alreadyOnRoster: false)
  consecutive-loss branch skipped
  if still eligible (green book, n≥20, not martingale) → Action = Admit
  else branch sets row.Status = "ADMITTED"
```

So **REMOVE does not pause**. It **toggles**. A still-green L-L-L name will be `REMOVED:CONSECUTIVE_LOSSES_3` then `ADMITTED` on the following 20 s tick, forever, until a winner or T1/T4 fires. P503_S03 §4 latch (`loss_cut_latched_at`, human clear only) is **not implemented**.
