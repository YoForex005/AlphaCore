    public decimal Normalize(decimal sourceLots, decimal allocationFactor, InstrumentQuantitySpec dest)
    {
        if (sourceLots <= 0)
            throw new ArgumentOutOfRangeException(nameof(sourceLots));
        if (allocationFactor <= 0)
            throw new ArgumentOutOfRangeException(nameof(allocationFactor));
        if (dest.StepSize <= 0)
            throw new ArgumentOutOfRangeException(nameof(dest.StepSize));

        var raw = sourceLots * allocationFactor;
        var steps = decimal.Truncate(raw / dest.StepSize);
        var qty = steps * dest.StepSize;
        qty = decimal.Round(qty, dest.Precision, MidpointRounding.ToZero);

        if (qty < dest.MinQuantity)
            return 0m;
        if (qty > dest.MaxQuantity)
            return dest.MaxQuantity;
        return qty;
    }

## Profit implication

- **No dest-book profit signal.** Operators looking at “Dest. real P&L” always see `0.00` even with 8463 accounts, Achiever scoring, and FIX LoggedOn. You cannot rank or size a live Pepperstone book from this KPI.
- **Shadow P&L is a lie if read as copy profit.** It is Σ print slippage vs source entry VWAP on a **stale 2399.xx demo** gold print. With live XAU far from that seed, any non-zero shadow number is a **spread/VWAP artifact**, not captured edge. Promoting Achiever SHADOW names off that number would select the wrong book.
- **Sizing gap kills later copy fidelity.** Shadow (and any future live path) copies `MaxVolumeLots` without `allocationFactor`, dest step, or min floor. When REAL_COPY is eventually armed, dest OrderQty will not match the unit-tested Pepperstone spec. That is missed profit *and* oversize risk, not a feature of this file today.
- **`MarkToMarket` is dead.** Unrealized dest P&L cannot accumulate on open shadow positions; only entry `SimulateEntry` rows exist. Closed-source trades are not even `SimulateExit`’d. You cannot measure whether a SHADOW candidate would have paid after dest spread.

## Lower-loss implication

- **This file cannot lose Pepperstone capital.** No socket, no `35=D`, no ClOrdID, no destination account. `REAL_COPY` remains false in DI and after FIX logon. Measured `destinationRealPnl = 0` is **honest for the live dest book**: there is no live dest position to lose.
- **Zero dest P&L is a safety tell, not a healthy book.** Do not treat “0.00 dest P&L + QUOTE LoggedOn” as flat-and-hedged. It is “never queried.” A later wiring bug that copies source MT5 PnL into `DestinationRealPnl` would hide dest losses.
- **Demo shadow can create false comfort.** If Overview Shadow P&L is non-zero (seed slippage, historically 248.20 in demo), an operator may think dest risk is already being measured and loosen kill-switch / promote to LIVE. That increases future loss. Trader-row `ShadowPnl = 0` vs overview slippage sum is a second inconsistency.
- **Unused `QuantityNormalizer` is a future loss hole.** Below-min should return `0` (no send). Persist ignores that and writes full source lots onto `SHADOW_ONLY` intents. If anyone later flips those intents to TRADE without the floor, dest min-lot rejects or accidental oversize both raise loss vs the written spec.
- **FIX LoggedOn ≠ quote freshness for shadow.** Logon without `destination_quotes` updates means even a correct future `MarkToMarket` would mark to 2399.xx. Adverse selection vs real 2026 gold is unbounded paper loss (still not cash, because copy is off).
