## File

`D:/Prop/apps/api/Program.cs` is the ASP.NET Core composition root for Trader Intelligence API (156 lines). It is the only product host that calls `WebApplication.CreateBuilder`. This slot can therefore succeed or fail the assigned angle: a dotenv / `.env` file must be applied to the **process environment** *before* `WebApplication.CreateBuilder(args)` so the default host configuration sources (and the later `AddEnvironmentVariables()` call) see file-backed keys (`REAL_COPY_*`, `MT5_*`, FIX, connection strings, risk flags).

The file was read in full. This is **not** an empty PASS.

## Angle

Assigned defect: the env file is **not** loaded before `WebApplication.CreateBuilder`, so `IConfiguration` / `IHostEnvironment` / DI would miss keys that exist only on disk.

That would be **FAIL** if:

- `CreateBuilder` ran first (or with no loader at all), or
- `FindAndLoad` only returned a path without writing process env, or
- load happened only after `builder.Build()` / `app.Run()`.

Observed order on disk is the **opposite** of the defect.

```5:20:D:/Prop/src/Mt5/Env/EnvFile.cs
    public static string? FindAndLoad()
    {
        var cwd = Directory.GetCurrentDirectory();
        var candidates = new[]
        {
            Path.GetFullPath(Path.Combine(cwd, ".env")),
            Path.GetFullPath(Path.Combine(cwd, "..", ".env")),
            Path.GetFullPath(Path.Combine(cwd, "..", "..", ".env")),
            Path.GetFullPath(Path.Combine(cwd, "..", "..", "..", ".env")),
            @"D:\Prop\.env"
        };
        var path = candidates.FirstOrDefault(File.Exists);
        if (path is null)
            return null;
        Load(path);
        return path;
    }
```

## No-loss implication

The assigned defect is absent: process env is populated from `.env` (when a candidate exists) **before** `WebApplication.CreateBuilder`. Host configuration therefore sees file-backed flags and connection keys at the same time as other environment sources. `AddEnvironmentVariables()` after the builder is a second, later layer — not a substitute for the pre-builder load.

This host itself has no live send path. Mapped routes are health, dashboard reads, and `/api/ops/resync` (catalog + deal ingest + reconstruction scoring). Settings expose `REAL_COPY_EXECUTION_ENABLED` from `LiveRuntimeStatus` and hard-code `FEATURE_COPY_TRADING_ENABLED = false`. No `NewOrderSingle`, `OrderSend`, or flatten is constructed here.

No-loss: a missing `.env` is reported as `envFile: "missing"` / `envLoaded: false` and leaves process env unchanged — it does not invent size or place orders. A present `.env` is applied before the builder, so feature flags and risk-related keys are not silently dropped due to load order. Capital cannot be lost *by this ordering bug* because the ordering bug is not present in `Program.cs`.

Empty-PASS justification: **not used**. The assigned file was fully read (156 lines); the angle was evaluated against the actual call order (`FindAndLoad` → `CreateBuilder` → `AddEnvironmentVariables`), which is correct.
