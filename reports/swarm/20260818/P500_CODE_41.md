## Angle

Would **copying every scored XAU trader** lose money, given that `RISK_BLOCKED` dominates the scored book?

“Scored” = a `BaselineScore` / `TraderScore` exists. Achiever scoring is live on the measured book. Starwave deals-done scored **0**, so those logins are **not** an XAU completed-trade tape and are not “scored XAU” for this angle.

`RISK_BLOCKED` is a **scoring state** (`TraderState = 7`), **not** a `RiskEngine` reason or outcome. The question is whether this engine would stop a copy-every-score policy from putting that modal losing cluster onto one dest gold book.

---

## Verdict

**YES — if that policy were live, it would be expected to lose money.** `RISK_BLOCKED` dominance is a **warning the scorer already computed**, not a filter this engine applies.

`RiskEngine.Evaluate` never sees `TraderState`. `RiskEvaluationRequest` has no field for `RISK_BLOCKED` / `LIVE` / `SHADOW` / `CompletedXauTrades` / quality / risk score. `BrokerId` and `SourceLogin` are accepted and **never read**. Spec reason `TRADER_RISK_BLOCKED` (A23 §4.3, A71 G20) is **never emitted** (0 hits in this file).

Copy-every-scored therefore includes the modal scored class: martingale + drawdown + **negative NET**, or `risk >= 80`. Those are the books `TraderStateMachine.FromBaseline` labels `RISK_BLOCKED`. Copying them is copying a losing, size-up-after-loss XAU cluster onto one dest metal book.

Martingale is blocked only if the **caller** sets `MartingaleFlag=true`. Caps (`MaxXauGross=20`, `MaxXauNet=10`, `MaxOpenPositions=20`, `MaxPositionQuantity=5`) are last-ditch size brakes on caller-supplied snapshots, not a quality screen. Against **8463** source logins they are a few lots of the **same** XAUUSD, not a diversified book. `MAX_XAU_NET` is labeled `ReduceSize` but goes through `Reject()` → `ApprovedQuantity=0` (hard stop, not a clip). Side-blind `abs(net)+qty` treats a hedging add as more net. Loss/DD checks apply to **every** action, so a red dest day **cannot exit** through this engine.

**Current dest is not losing.** `AllowFixSend` requires `RealExecutionEnabled` (measured `REAL_COPY false`). Product `Evaluate(` callers = this definition + five unit facts only (`tests/Unit/RiskEngineTests.cs`). SHADOW is all-demo. `destinationRealPnl` is **0**. FIX LoggedOn is session, not send. Starwave scored **0** deals-done.

Do **not** flip `REAL_COPY` and copy every Achiever score. That is the losing path this file fails to stop by state.

## Profit implication

**Copy-every-scored-XAU is not a profit path.** The class labeled `RISK_BLOCKED` is defined as a **losing martingale** (or risk ≥ 80). A book dominated by that class is a **negative-expectancy** source tape. Putting every Achiever score onto one Pepperstone/cTrader XAU dest would:

1. Align dest with **one** correlated metal (no Phase-2 concentration cap in this engine; §65 is Phase 2).
2. Include the `RISK_BLOCKED` majority as if they were `SHADOW` quality. The engine cannot tell them apart.
3. Size up after source losses whenever the caller forgets `MartingaleFlag` (the scorer already knows `features.Martingale`; this file does not read it).
4. Hit 10 net / 20 gross lots of the **same** metal, then hard-zero further adds — leftover dest stays long/short the losing cluster. `ReduceSize` does not clip to remaining room.
5. On the first −500 per trader / −2_000 daily / 3_000 portfolio-DD dest day, **refuse to close**. Residual dest risk is then a defect, not a hedge.
6. Approve requested qty on any remaining open that still fits the caps (`Reason = "APPROVED"`). There is no edge filter, no `LIVE` requirement, no score floor.

Starwave deals-done scored **0** adds **no** XAU edge and is not a scored tape. Achiever scoring of thousands of logins is **observation**. FIX LoggedOn does not monetize scores. With `REAL_COPY false` and `destinationRealPnl` **0**, there is **no** live dest profit and **no** live dest loss from this file.

Do not treat “8463 accounts” as 8463 copy candidates. Most of a `RISK_BLOCKED`-dominated scored book is the class you would **pay** to copy.

## Lower-loss implication

**Lower dest loss = do not copy every score.** Filter `RISK_BLOCKED` (and `INSUFFICIENT_DATA` / `EARLY_SCORE` / `WATCH`) **before** any `CopyIntent`. Keep `REAL_COPY` false until a state-aware gate exists and `Evaluate` is actually on the hop.

What this file already does that limits loss **if** a naive copy-all were wired with honest book snapshots:

- `AllowFixSend=false` when `RealExecutionEnabled=false` (today’s measured floor; matches `REAL_COPY false`).
- `MARTINGALE_BLOCK` / `ABNORMAL_SIZING_BLOCK` **if** the caller actually sets the flags from the scorer.
- Gross 20 / net 10 / 20 slots / 5 lots per ticket — a **size ceiling**, not a quality filter.
- `Reject` always `AllowFixSend=false`, `ApprovedQuantity=0`.
- Quote/spread/move/signal age reject **increasing** only (correct family for those guards).

What this file does that **worsens** dest loss once a copy-all book exists:

- Ignores `RISK_BLOCKED` — the dominance signal the angle is about.
- Freezes reduce/close at trader-loss / daily-loss / portfolio-DD (lines 117–124).
- `MAX_XAU_NET` “reduce” is a zero-qty reject (no clip to remaining cap).
- No dest identity — cannot flatten what it approved (`EmergencyFlatten` only blocks new; does not emit closes).
- Empty shadow `if` — does not fail closed on `RealExecutionEnabled=false`; relies on the later conjunction.
- Unwired: absence of send is the real loss floor, not this method.

Today’s dest loss floor is **absence of send**, matching measured `destinationRealPnl=0` and SHADOW-all-demo. Do **not** enable live copy of the scored book to “use” this engine.
