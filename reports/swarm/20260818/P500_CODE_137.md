```1:36:D:/Prop/src/Domain/Volume/VolumeConverter.cs
namespace TraderIntelligence.Domain.Volume;

/// <summary>
/// Converts MT5 native integer volume to lots.
/// IMTDeal::Volume() / SMTMath::VolumeToDouble uses MTAPI_VOLUME_DIV = 10_000
/// (4 decimal places). IMTDeal::VolumeExt() uses 100_000_000.
/// The comment in mt5-sdk mt5_types.h ("hundredths of lots") is incorrect.
/// Existing mt5_manager.cpp copies deal-&gt;Volume(), so the default scale is 10_000.
/// </summary>
public sealed class VolumeConverter
{
    public const decimal ManagerVolumeScale = 10_000m;
    public const decimal ExtendedVolumeScale = 100_000_000m;
    public const decimal HundredthsScale = 100m;

    public decimal Scale { get; }

    public VolumeConverter(decimal scale = ManagerVolumeScale)
    {
        if (scale <= 0)
            throw new ArgumentOutOfRangeException(nameof(scale), "Volume scale must be positive.");
        Scale = scale;
    }

    public decimal ToLots(ulong native) => native / Scale;

    public ulong ToNative(decimal lots)
    {
        if (lots < 0)
            throw new ArgumentOutOfRangeException(nameof(lots));
        return (ulong)decimal.Round(lots * Scale, 0, MidpointRounding.AwayFromZero);
    }

    public static VolumeConverter Manager => new(ManagerVolumeScale);
    public static VolumeConverter Extended => new(ExtendedVolumeScale);
}
```

## Protecting profit vs blocking it

### Protecting profit — **NO**

Profit on the destination (Pepperstone / cTrader) requires a LIVE (or otherwise approved) copy that actually fills. Measured live:

| Fact | Meaning |
|---|---|
| 8463 accounts | Source universe is large enough that a real ranker *could* find edge. This pin never lets that edge become a live fill. |
| Achiever scoring | Scores exist. Scores are not fills. |
| Starwave deals-done scored 0 | Empty completed-XAU book ⇒ `FromBaseline` lands `INSUFFICIENT_DATA`. Nothing to promote. |
| SHADOW all demo | Copy intents that exist are demo shadow, status `SHADOW_ONLY`. |
| `destinationRealPnl` 0 | No destination realized P&amp;L. Hard-false is consistent with this, not a profit protector. |
| FIX LoggedOn | Session-up ≠ send. LoggedOn + hard-false still yields dest PnL 0. |
| `REAL_COPY` false | Independent arming flag is off. Two gates, both closed. |

A hard-false promotion API cannot “protect profit.” It can only refuse to take it. Leaving 8463 scored (or scoreable) accounts off LIVE means **forgone destination P&amp;L**, including any winners that would have copied profitably.

That is **not** a defect versus architecture. Trade #3 / §69 / `docs/scoring.md` require SHADOW ceiling until an audited R6+RBAC+risk gate exists. Forgone profit is the **price of the floor**, not evidence the floor is “protecting profit.”

### Blocking profit — **YES (destination only)**

`CanPromoteToLive => false` plus `FromBaseline` never emitting `LIVE` means:

- No automatic LIVE traders at any N (vacuous lock: live was never implemented).
- Persist will not see `SuggestedState == LIVE` today.
- Copy worker’s LIVE conjunction (`AllowFixSend && LIVE && NewOrderSingleImplemented && VenueReconciled`) cannot fire even if someone later sets `REAL_COPY` true — sender is unimplemented.
- Destination real PnL stays 0 while FIX sits LoggedOn.

Source-trader profit on Achiever/Starwave is **unaffected**. This pin does not flatten source books, does not cancel source deals, and does not change `VolumeConverter` lots.

### Protecting capital / lower-loss — **YES**

This is the honest positive of the hard-false:

- Trade #3 cannot become LIVE even on three disciplined winners (unit-locked SHADOW).
- An operator cannot “promote from score quality” because the named API cannot return true.
- Combined with `REAL_COPY` false and `NewOrderSingleImplemented` false, a LoggedOn TRADE session cannot become a 35=D from this pin.

Honesty (D97 class, reconfirmed this slot): it is a **vacuous lock** (“we forgot live”), not A22 R5-before-R6. Persist copies `SuggestedState` blindly. If a later coder adds `return TraderState.LIVE` inside `FromBaseline` and forgets this pin, Application will write LIVE. Keep the pin false at N≤3 when the real R6 function is written; do not treat today’s body as that function.

## Profit implication

**Assigned file:** none. Scale math cannot capture or refuse destination edge.

**Real pin:** **blocks destination profit**. Hard-false + no LIVE emission + SHADOW-only persist + unimplemented NOS ⇒ dest PnL stays 0 on a LoggedOn FIX session across 8463 accounts. That is forgone copy P&amp;L, not protected P&amp;L. Source PnL is untouched.

Do not flip `CanPromoteToLive` to `true` to “unlock profit.” Profit after a flip would still require: `FromBaseline` (or an audited promote command) emitting LIVE, persist consulting the pin + risk + RBAC, `REAL_COPY` true, `NewOrderSingleImplemented` true, and a real 35=D sender. None of those exist.

## Lower-loss implication

**Assigned file:** **neutral / slightly protective as sizing hygiene.** Default `10_000` prevents the hundredths 100× oversize on recon lots. No send path, so no live loss from this file even if scale were wrong (wrong scores, not wrong fills).

**Real pin:** **protective.** Auto-LIVE is impossible at the named API. Combined with measured `REAL_COPY` false and `NewOrderSingleImplemented` false, Pepperstone capital cannot be filled from scoring. Lower-loss value is the **absence of automatic live copy**, which is exactly why dest PnL is 0.

Residual (not a FAIL of either file): persist does not call `CanPromoteToLive`. The pin is dead API. Capital safety today is **SAFE_BY_ABSENCE** of a sender, not this boolean.
