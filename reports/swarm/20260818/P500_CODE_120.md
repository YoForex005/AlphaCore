    {
        if (features.CompletedXauTrades == 0)
            return TraderState.INSUFFICIENT_DATA;

        if (risk >= 80 || (features.Martingale && features.MaxDrawdown > 0 && features.NetPnl < 0))

## Profit implication

**None from this file. Dest profit cannot originate here.**

- `NetPnl` / `GrossProfit` / `ProfitFactor` in `FeatureSnapshot` are **source-account** reconstructed realized PnL (Achiever / Starwave MT5 deals), not Pepperstone dest PnL.
- Achiever scoring in this wave ranks those source books. Ranking a winner does not open a dest position.
- Starwave **deals-done scored 0** hits the empty-book floor (`CompletedXauTrades == 0` → `INSUFFICIENT_DATA`). Those 1948-class names contribute **0** suggested SHADOW and **0** dest tickets.
- SHADOW is **all demo**. Even the best `quality >= 70 && risk < 40` path only labels SHADOW. `CanPromoteToLive => false` blocks auto-LIVE, so no dest clip can harvest source edge.
- Measured `destinationRealPnl` **0** is consistent: a scorer that never sends cannot earn.

Implication: do **not** treat high `EarlyQualityScore` / SHADOW labels as live-book profit. They are research ranks. Turning them into Pepperstone PnL would require a different file (unimplemented NewOrderSingle) plus `REAL_COPY` true plus LIVE promotion — none of which this unit provides.

## Lower-loss implication

**This file cannot lose Pepperstone money either. It also cannot stop a send that some other file might add later.**

Protective effects that **do** exist, all advisory:

- Martingale / averaging-down / lot-escalation inflate `RiskScore` and can land `RISK_BLOCKED` (`risk >= 80` or martingale ∧ DD ∧ `NetPnl < 0`). That is a **label**, not a FIX reject.
- `CanPromoteToLive => false` is a vacuous live lock: it prevents this unit from suggesting LIVE. Application grep shows **zero product callers** of `CanPromoteToLive` (definition only). Downstream persist copies `SuggestedState` blindly — safe today only because SuggestedState cannot be LIVE.
- Empty / N<3 books stay `INSUFFICIENT_DATA`. That keeps Starwave scored-0 and thin Achiever names out of SHADOW persist.

What this file does **not** do for lower loss:

- It does not evaluate `RiskEngine`, does not set `AllowFixSend`, does not check `REAL_COPY`, does not require venue reconcile, does not cap dest lots.
- If a future sender copied every scored XAU name (including `RISK_BLOCKED` martingale losers) this scorer would have **already labeled** many of them — but the label is ignored unless a send path consults `CurrentState`.
- FIX LoggedOn + `REAL_COPY` false is the live capital fence **outside** this file. Session-up does not become a send because of BaselineScorer.

Lower-loss takeaway: keep `CanPromoteToLive` false and keep `FromBaseline` from emitting LIVE. That is the only capital-relevant contract this file owns. Loss reduction vs a hypothetically armed copy-all book is **state labeling**, not a wire block.
