## Verdict

**PASS.** `BaselineScorer.cs` is a pure in-memory scoring module. It computes features and suggested `TraderState` from already-reconstructed XAU trades. It has no FIX session, no socket, no HTTP, no ClOrdID factory, no order builder, and no call into a TRADE sender. FIX being LoggedOn plus REAL_COPY false is consistent: session up does not imply this scorer can arm a send. Destination PnL 0 is the expected capital outcome of a file that only scores.

## What the file actually is

Three types, no I/O:

1. `FeatureSnapshot` — completed-XAU counts, net/gross PnL, PF, lot/loss CVs, martingale / averaging-down / lot-escalation flags, hold, SL use, max DD, frequency, unused MAE/MFE placeholders.
2. `BaselineScore` — features + risk/behavior/early-quality + `SuggestedState` + eligibility.
3. `BaselineScorer` — `ComputeFeatures` + `Score` + CV helper.
4. `TraderStateMachine` — maps scores to `INSUFFICIENT_DATA` / `RISK_BLOCKED` / `WATCH` / `EARLY_SCORE` / `SHADOW` only.

`Score()`:

- features from completed XAUUSD reconstructed trades
- `EarlyScoreEligible` iff `CompletedXauTrades >= 3`
- risk 0–100 from martingale/averaging/escalation/lot-CV/SL/DD
- behavior 100 down, quality blended and capped at 40 when ineligible
- state = `TraderStateMachine.FromBaseline(...)`

No side effects. No persistence. No broker.

    public static TraderState FromBaseline(bool earlyEligible, decimal quality, decimal risk, FeatureSnapshot features)
    {
        if (features.CompletedXauTrades == 0)
            return TraderState.INSUFFICIENT_DATA;

        if (risk >= 80 || (features.Martingale && features.MaxDrawdown > 0 && features.NetPnl < 0))
            return TraderState.RISK_BLOCKED;

        if (!earlyEligible)
            return TraderState.INSUFFICIENT_DATA;

        if (quality >= 70 && risk < 40)
            return TraderState.SHADOW;

        if (quality >= 55)
            return TraderState.WATCH;

        return TraderState.EARLY_SCORE;
    }

    public static TraderState AfterHighEarlyScore() => TraderState.SHADOW;

## Profit implication

**None from this file.** Pepperstone destination profit requires a live fill (`35=D` accepted, position, realized PnL). This module never constructs MsgType D, never sizes destination qty, never attaches a venue account. Achiever/Starwave scores can only change leaderboard / shadow rows. `destinationRealPnl` remaining 0 is the honest profit statement for slot 20.

A high Achiever score (`quality >= 70 && risk < 40`) is the *best* outcome this file can produce and that outcome is still `SHADOW`, not a live ticket.

## Lower-loss implication

**Capital-protective, not PnL-generating.** Lower-loss on Pepperstone is preserved because this file cannot open a losing destination trade:

- live promotion is unconditionally false
- `LIVE` / `LIVE_CANDIDATE` are unreachable from `FromBaseline` / `AfterHighEarlyScore`
- empty / Starwave-0 books stay `INSUFFICIENT_DATA`
- martingale + DD + negative net → `RISK_BLOCKED` (still no send)
- consumer writes demo shadow only

This is **non-participation**, not a measured edge. It does not reduce losses on trades that were never sent. It also does not prevent some *other* file from sending if REAL_COPY were armed later — but that path is not in `BaselineScorer.cs`.

Any of: building/sending FIX `35=D`; calling a TRADE session; returning `TraderState.LIVE` / `LIVE_CANDIDATE`; `CanPromoteToLive` becoming true for any state; writing a live CopyIntent that a dispatcher would send. **None present after reading the file.**
