## 1. Domain/Copy — remove exists, is not sticky

`RosterAction` is `{Admit, Keep, RemoveAndFlatten}`. `Remove` always sets dest flatten + no new opens:

```128:135:D:\Prop\src\Domain\Copy\CopyRosterEngine.cs
    private static RosterDecision Remove(string reason) =>
        new()
        {
            Action = RosterAction.RemoveAndFlatten,
            Reason = reason,
            FlattenDestination = true,
            AllowNewOpens = false
        };
```

Loser predicates that **do** fire `Remove`:

| Predicate | When | Reason |
|---|---|---|
| `RISK_BLOCKED` / `DISQUALIFIED` / `PAUSED` | always | `STATE_*` |
| Martingale / averaging / lot-escalation | always | `SIZE_PATTERN` |
| Not demo/contest (`CopyGroupFilter`) | always | `NOT_DEMO_OR_CONTEST_GROUP` |
| Completed XAU net ≤ 0 | **only if** `alreadyOnRoster` | `XAU_BOOK_TURNED_NEGATIVE` |
| Newest-XAU loss streak ≥ 3 | **only if** `alreadyOnRoster` | `CONSECUTIVE_LOSSES_{n}` |
| Peak-to-trough DD ≥ 40% of peak | **only if** `alreadyOnRoster` | `DRAWDOWN_FROM_PEAK` |
| `IsTraderEligible` false | **only if** `alreadyOnRoster` | `NO_LONGER_ELIGIBLE_{reason}` |

Off-roster + not eligible → `Keep` / `NOT_YET_*` / `AllowNewOpens=false` (never `Admit`). That keeps **never-admitted** names off the seat.

The hole is the `alreadyOnRoster` conjunct on streak / DD / net:


After REMOVE, hop computes `onRoster = row is not null && row.Status == "ADMITTED"` (`CopyTradingService` L136). `REMOVED:*` is **not** on roster. Next `Decide(..., alreadyOnRoster: false)` **skips** those three gates. If `IsTraderEligible` is still true (n≥20, net>0, SHADOW+, demo/contest, clean size flags), action is **`Admit`**. `TickRosterAsync` L160 writes `Status = "ADMITTED"` on the **same** unique `IdempotencyKey`. Oscillation:

```text
ADMITTED → REMOVED:CONSECUTIVE_LOSSES_3 + paper FLATTEN_LOSS_CUT
        → (20 s) AUTO_ADMIT → ADMITTED again
        → ExecuteDemoCopyAsync opens dest for that seat
```

Net≤0 does **not** oscillate: off-roster `IsTraderEligible` fails `XAU_BOOK_NOT_PROFITABLE` (policy L99–103). Size-pattern / blocked / real-group `Remove` even when off-roster, so they stay `REMOVED`. Those three classes are the only losers the hop actually keeps off the seat.

`ShouldFlattenOpenCopy` is Domain-only and **dead** on the hop (grep `src/` = definition only):

## 2. CopyTradingService — persist REMOVE, paper flatten, dest send ignores both

### 2.1 TickRoster — wired

Hosted (`CopyTradingHostedService` L28–30): `TickRosterAsync` then shadow hopper then `ExecuteDemoCopyAsync`.

On `RemoveAndFlatten` (L165–192):

1. Insert or update `roster:{broker}:{login}` to `Status = "REMOVED:" + reason`, `Action = CloseExposure`.
2. If `FlattenDestination`, call `FlattenOpenCopiesAsync`.
3. Single `SaveChangesAsync` after the whole score loop (L195–196). An exception mid-loop **rolls back every REMOVE** in that tick. Those names stay `ADMITTED` until a later successful save.
