## Angle

Are the martingale and averaging **filters** in (or produced by) `TradeReconstructor` strong enough to cut the left tail of gold books — same-position add-down, hedge-account grid, recovered 2×/4×/8× baskets that later blow — given live census 8463 accounts, Achiever scoring, Starwave deals-done scored 0, SHADOW-all-demo, dest real P&L 0, FIX LoggedOn, `REAL_COPY` false?

“Filter” means a gate that **removes** the book from first-three, scoring input, copy-intent generation, or dest size. A boolean that still flows into `CompletedXauUsdTrades` is detection, not a left-tail cut.

## Verdict

**FAIL — no.** Martingale and averaging filters in this file are **not** strong enough to cut the left tail, because they do not exist as filters.

What the reconstructor actually does:

| Mechanism | Present? | What it does | Cuts left tail? |
|---|---|---|---|
| Intra-position martingale detect | **No** | `Martingale` string does not appear | No |
| Averaging **reject** | **No** | `ScaleIn` latches `WasAveragedDown` on a strictly worse fill vs pre-fill VWAP | No — trade still completed / first-three eligible |
| Same-price / hedge grid | **No** | New `PositionId` → `OpenTrade.Start`; `==` VWAP is not “worse” | No — `WasAveragedDown` stays false |
| First-three cut | Cancel dirt only | `EligibleForFirstThree = false` iff cancel action on that `PositionId` | Not a behavior cut |
| Size cap on adds | **No** | `RemainingLots += lots`; `MaxVolumeLots` tracks peak remaining | No — peak size is the dest qty later |

Three holes that dominate gold challenge left tails:

1. **Netting add-down is fused into one trade.** `0.01 + 0.02 + 0.04 + 0.08` on one `PositionId` is one `ReconstructedTradeResult` with `WasAveragedDown=true` and `MaxVolumeLots=0.15`. Downstream `BaselineScorer` martingale is **adjacent completed trades** (`prior NetPnl < 0` **and** next `MaxVolumeLots > 1.25×`). A single recovered basket never enters that loop. `Martingale=false`. Averaging adds **+20** risk. `RISK_BLOCKED` needs `risk >= 80` **or** `(Martingale ∧ DD > 0 ∧ NetPnl < 0)`. Winning recovered grid: `risk=20`, can land **SHADOW** if quality `>= 70`.
2. **Hedge-account grid never even sets the averaging flag.** Reconstruction groups **only** by `PositionId`. Each grid level is a new lifecycle `Start`. `ScaleIn` is never called. `WasAveragedDown=false` on every row. If the basket is closed together as winners, the scorer’s after-loss 1.25× rule also stays false. Left tail is unlabeled.
3. **Same-price scale-in is not averaging.** Strict `<` / `>`. Adds at the VWAP (or a better price) set `WasScaledIn` only. Classic “double the lot at the same level” is invisible to the averaging latch.

Downstream (not this file; quoted so the FAIL is not a reconstructor-only nit):

- `BaselineScorer`: martingale +35, averaging +20, lot-escalation +15. A22 `baseline.v1` floors `FLAG_MARTINGALE` at risk **80** and caps behavior at 35. The stub does **neither**. C32 measured profitable martingale books at quality **70.25–85.25** and mild 1.26× after a loss + SL at **SHADOW**.
- `docs/scoring.md` says “Martingale / large sequential size-up after losses ⇒ `RISK_BLOCKED`.” That is only the **losing** 2×/2× unit fact (`Martingale_after_losses_is_risk_blocked`). Winning / intra-position / hedge-grid books are not locked.
- `RiskEngine` has `BlockMartingale` on a **caller-supplied** `MartingaleFlag`. `RiskEvaluationRequest` has **no** `AveragingDown` / `WasAveragedDown` field. Averaging is invisible to dest risk.
- `CopyTradingService` sizes dest from `trade.MaxVolumeLots` (the **basket** after adds), then passes `MartingaleFlag = score.Martingale` (inter-trade, not intra-position). `AllowFixSend` is hard-false on that path today (`NewOrderSingleImplemented = false`, `VenueReconciled = false`). That is a send lock, not a reconstruction filter.

Live census does **not** rescue the filters:

- 8463 source accounts can still run grids on the challenge side. This class reconstructs them as valid completed XAU.
- Achiever scoring can consume those reconstructions; Starwave **deals-done scored 0** means that broker’s left tail is **unscored**, therefore unfiltered by the scorer.
- SHADOW all demo + `destinationRealPnl` **0** + `REAL_COPY` **false** means dest left tail is cut by **not copying**, not by anything in `TradeReconstructor`.
- FIX **LoggedOn** is session state. Logon without a reconstruction reject is not a left-tail cut.
