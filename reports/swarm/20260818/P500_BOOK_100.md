## 2. Recalculation: how **95.50** is produced

Let `I_net = 1` iff XAU `NetPnl > 0`, `I_12 = 1` iff `PF >= 1.2`, `I_18 = 1` iff `PF >= 1.8` (implies `I_12`).

```text
quality = 50 + 15 I_net + 10 I_12 + 5 I_18 + 0.20 b − 0.25 r
```

### 2.1 `I_net = 0` cannot reach 95.50 (and cannot reach PF 1.2)

If XAU `NetPnl <= 0` then `GP <= GL`. With any losses, `PF = GP/GL <= 1 < 1.2`. With no losses and non-positive net, `GP = 0` and the stub sets `PF = 0`. So `I_net = 0` forces `I_12 = I_18 = 0`:

```text
quality = 50 + 0.20 b − 0.25 r
quality_max(I_net=0) = 70.00     at (b, r) = (100, 0)
```

**A negative XAU book cannot print 95.50.** A negative *dashboard* book can.

### 2.2 The 95.50 identity

Assume the full bonus stack (`I_net = I_12 = I_18 = 1`):

```text
80 + 0.20 b − 0.25 r = 95.50
0.20 b − 0.25 r      = 15.50
4b − 5r              = 310
r                    = (4b − 310) / 5
```

On the **actual increment lattice** (`b` is 100 minus subsets of {30, 15, 10, 10, 10}; `r` is a sum of {35, 20, 15, 10, 10, 10}, capped at 100):

| b | (4b−310)/5 | Reachable r? |
|---:|---:|---|
| 100 | 18 | no |
| 90 | **10** | **yes** (exactly one +10 risk flag that also dings behavior) |
| 85 | 6 | no |
| 80 | 2 | no |
| 70 | −6 | no |

**The only lattice point that prints 95.50 is `behavior = 90`, `risk = 10`.**

Without `I_18` the max is `75 + 20 = 95.00`. Cross-check:

```text
I_net=0                         → quality_max = 70.00     // 25.50 below 95.50
I_net=1, PF < 1.2               → quality_max = 85.00
I_net=1, 1.2 ≤ PF < 1.8         → quality_max = 95.00
I_net=1, PF ≥ 1.8, (b,r)=(100,0)→ quality     = 100.00    // unit-test path WITH SL
I_net=1, PF ≥ 1.8, (b,r)=(90,10)→ quality     = 95.50     // unused-SL / LotCv path
I_net=1, PF ≥ 1.8, (b,r)=(100,10)→ quality    = 97.50     // MaxDD>GP alone (no behavior ding)
I_net=1, PF ≥ 1.8, (b,r)=(90,0) → quality     = 98.00     // LossSizeCv or 0.3≤SL<0.5 alone
```

**Therefore 95.50 requires XAU `NetPnl > 0` and `ProfitFactor >= 1.8` and `(b,r)=(90,10)`.**

### 2.3 How `(b,r)=(90,10)` actually happens

That pair is the “one mild ding that hits **both** sides”:

| Flag | risk | behavior | Produces (90,10)? |
|---|---:|---:|---|
| `SlUseRate < 0.3` (and therefore `< 0.5`) | +10 | −10 | **yes** |
| `LotCv > 0.5` (and therefore `> 0.4`) | +10 | −10 | **yes** |
| `MaxDrawdown > GrossProfit` alone | +10 | 0 | no → 97.50 |
| `LossSizeCv > 0.8` alone | 0 | −10 | no → 98.00 |
| martingale / averaging / lot-escalation | ≥15 | ≥15 | too heavy for 95.50 |

The **dominant live path is unused stops**, and it is **forced by the ingest schema**, not merely by challenge tickets leaving SL blank:

| Layer | SL field? |
|---|---|
| `Mt5DealDto` (`Mt5Contracts.cs:24–38`) | **No.** Constructor is ticket/login/order/pos/symbol/action/entry/vol/price/profit/commission/swap/time/comment. |
| `Mt5Deal` entity | **No.** Same columns. No `PriceSl`. |
| `EfTradingStore.LoadDealsAsync` | Builds `NormalizedDeal` **without** `StopLoss` / `TakeProfit` (defaults null). |
| `TradeReconstructor` | `InitialSl = deal.StopLoss` → null. |
| `BaselineScorer` L121 | `InitialSl.GetValueOrDefault() > 0` is **false** for every ingested trade. `SlUseRate = 0`. |

```text
SlUseRate = 0
  → risk += 10, behavior -= 10
  → risk = 10, behavior = 90
NetPnl > 0, PF stub 99 (no XAU losses) or PF >= 1.8 (small XAU losses vs larger XAU wins)
quality = 50 + 15 + 10 + 5 + 90×0.20 − 10×0.25
        = 80 + 18 − 2.50
        = 95.50
N >= 3, quality >= 70, risk 10 < 40  →  SHADOW
```

Even a disciplined live trader who **did** set SL on the source ticket still scores as unused-SL 95.50, because the deal row never carried the stop. That is not skill. It is a missing column.

The unit-test “three disciplined winners” (`BaselineScorerTests.Three_disciplined_winners_go_to_shadow_not_live`) set `InitialSl = 2290` **on the reconstructed DTO**, so `SlUseRate = 1`, `(b,r)=(100,0)`, quality **100.00**, still `SHADOW`. That is **not** the 95.50 lattice and is **not** reachable from the live ingest path. 95.50 is the unused-SL cousin of the same SHADOW hole.
