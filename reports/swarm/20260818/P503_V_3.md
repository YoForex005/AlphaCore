## 1. What “on the roster” means in HEAD

There is no roster table. Membership is a `CopyIntent` row:

| Key | On roster? |
|---|---|
| `IdempotencyKey == roster:{brokerId}:{login}` **and** `Status == "ADMITTED"` | **Yes** (`TickRosterAsync` L134–136; hopper L228–232; demo send L542–544) |
| Missing row | No |
| `REMOVED:{reason}` | No **this tick** — but `Decide(..., alreadyOnRoster:false)` may **Admit** next tick |
| Any other status | No |

`GenerateShadowIntentsAsync` and `ExecuteDemoCopyAsync` both treat exact `ADMITTED` as the license to open dest risk. Leaving a loser in that status **is** leaving them on the roster.

Hosted order every **20 s** after an 8 s boot delay:

1. `TickRosterAsync` — admit / remove / paper flatten
2. `GenerateShadowIntentsAsync` — new `copy:` opens if `ADMITTED`
3. `ExecuteDemoCopyAsync` — **real demo FIX send** for every `ADMITTED` seat with an open source XAU ≤ `MaxAutoLots`

A re-ADMIT in step 1 is live in steps 2–3 of the **same** cycle.
