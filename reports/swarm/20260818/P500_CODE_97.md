public sealed class VolumeConverter

    public const decimal ManagerVolumeScale = 10_000m;
    public const decimal ExtendedVolumeScale = 100_000_000m;
    public const decimal HundredthsScale = 100m;

    public decimal Scale { get; }

    public VolumeConverter(decimal scale = ManagerVolumeScale)
    {
        if (scale <= 0)
            throw new ArgumentOutOfRangeException(nameof(scale), "Volume scale must be positive.");
        Scale = scale;
    }

    public decimal ToLots(ulong native) => native / Scale;

    public ulong ToNative(decimal lots)
    {
        if (lots < 0)

        return (ulong)decimal.Round(lots * Scale, 0, MidpointRounding.AwayFromZero);
    }

## Profit implication

Hard-false **blocks** live dest profit realization. It does **not** protect profit. It also does **not** sit on a proven dest edge.

- 8463 catalog accounts cannot become destination LIVE books through this pin (and the pin is not even on the persist path).
- Achiever scores that land `SHADOW` (quality ≥ 70 and risk < 40) stay paper / `SHADOW_ONLY`. Winner tape is not copied as real cTrader exposure.
- Starwave `deals-done scored 0` means that book is not even in the scorer loop; zero chance of a live harvest from that cohort this pass — **independent of `CanPromoteToLive`.**
- Dashboard dest real P&L is **structurally 0**, independent of source PnL quality. Shadow P&L is Σ `SourceVsShadowSlippage`, not destination realized.
- `VolumeConverter` cannot create profit: it only scales MT5 native volume → lots for reconstruction. Wrong scale (hundredths `100` vs Manager `10_000`) would 100× mis-lot a **future** send and also flip martingale / escalation features **today**. That send path is **not armed**.
- Even if someone flipped `CanPromoteToLive` to `true` without adding a `FromBaseline` LIVE branch, persist would still never write `LIVE`. Binding profit blockers remain: no LIVE token from the scorer, `NewOrderSingleImplemented = false`, no `35=D` builder, assigned `REAL_COPY` false.
- `CopyTradingService` already lists `LIVE` / `LIVE_CANDIDATE` as copyable states. That is a **dead branch**: `FromBaseline` never emits those tokens, and the LIVE conjunction still only writes `LIVE_SEND_BLOCKED_UNIMPLEMENTED`.
- Synthesis of the scored XAU book (parent swarm) is **net negative**. SHADOW is **100% demo**. Copying that set live would not be “unlocking withheld profit”; it would be spraying a challenge book onto Pepperstone.

If the question is “does hard-false keep us from giving back open profit?” — no live book exists to protect. Opportunity cost is the entire destination book, and that book is currently **zero by construction**, not a parked winner.

## Lower-loss implication

- N=3 early evidence cannot auto-promote. Architecture / `docs/scoring.md` require SHADOW max. The pin is **stricter than required** (false for every state / every N).
- Application never calls `CanPromoteToLive`. Persist will copy whatever `SuggestedState` is. Safety today is “LIVE is not in the reachable set,” not “a gate evaluated LIVE then denied.”

- Do **not** flip `CanPromoteToLive` to harvest dest P&L. The left tail (martingale / demo pass-target) is larger than the SHADOW head. Lower loss means **keep the pin and keep NOS unimplemented** until a filtered, quote-marked, dest-costed shadow book exists.
