## No-loss implication

This class does not send orders. The no-loss failure is **false flat books on the live desk**. Destination PnL, XAU gross/net, daily PnL, drawdown, and dest XAU long/short/net are always `0`, so a later-armed dest book (or a real shadow slip that only exists off the overview SUM) would look riskless. `/api/risk` would not show a losing day or a growing XAU net. `ShadowPnl=0` on every trader row hides per-login shadow P&L even when `shadow_orders` has rows. Seeded catalog / disconnected FIX / `KillSwitch=None` from `BrokerCatalogSeed` appear as live dashboard truth on first boot (and forever on the in-memory fallback). Halt / size-down decisions that depend on these tiles would be made from **painted zeros**, not venue exposure.
