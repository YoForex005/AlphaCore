## 0. Verdict (binding)

**YES. Peak-to-trough completed-XAU drawdown ≥ 40% of peak → REMOVE the trader and dest-only FLATTEN that login. Do not ADMIT (and do not KEEP) on that curve.**

## 1. Why this gate exists (and why net>0 is not enough)

Roster remove order in `Decide` (first match wins after state / size-pattern / demo):

| Order | Condition | Reason | Catches |
|---|---|---|---|
| 1 | `alreadyOnRoster && Σ NetRealizedPnl <= 0` | `XAU_BOOK_TURNED_NEGATIVE` | Book went red / flat |
| 2 | `alreadyOnRoster &&` last N completed XAU all `Net < 0`, N ≥ 3 | `CONSECUTIVE_LOSSES_N` | Still-green L-L-L |
| 3 | `alreadyOnRoster && peak > 0 && dd/peak >= 0.40` | `DRAWDOWN_FROM_PEAK` | Still-green **give-back** |
| 4 | else `IsTraderEligible` | `AUTO_ADMIT` / `KEEP` | — |

T3 is the only line that ejects a **still-profitable** book that did not print three consecutive losses. That is the whole point.

Independent walk of the unit fixture (`Peak_drawdown_removes`):

| k | pnl | equity | peak | dd | dd/peak |
|---:|---:|---:|---:|---:|---:|
| 1..20 | +50 each | 50 → **1000** | 1000 | 0 | 0 |
| 21 | −700 | **300** | 1000 | **700** | **0.70** |

- Net = **+300** → T1 does **not** fire.
- Consecutive losses = **1** → T2 does **not** fire.
- `0.70 >= 0.40` and `alreadyOnRoster=true` → **REMOVE** `DRAWDOWN_FROM_PEAK`.
- Policy `IsTraderEligible` would still return true (`XauNetPnl=300`, n=21, SHADOW, no size pattern). **Eligibility is not this control.**

Boundary (same 20×+$50 peak = 1000):

| Last pnl | equity | dd/peak | Domain |
|---:|---:|---:|---|
| −399 | 601 | 0.399 | **KEEP** (if still eligible) |
| −400 | 600 | **0.40** | **REMOVE** (`>=`) |
| −700 | 300 | 0.70 | **REMOVE** (fixture) |

P503_S03 T3 text said **strict** `> 0.40`. HEAD is **`>= 0.40`**. This slot reports the SUT.

`peak` is initialized at **0**. A never-green book never divides (no `peak > 0`). T1 / `XAU_BOOK_NOT_PROFITABLE` own that case. Do not invent a 40% of a zero peak.

    public static (decimal peak, decimal drawdown) DrawdownFromPeak(IReadOnlyList<ReconstructedTradeResult> closed)
    {
        var equity = 0m;
        var peak = 0m;
        var maxDd = 0m;
        foreach (var t in closed)
        {
            equity += t.NetRealizedPnl;
            if (equity > peak)
                peak = equity;
            var dd = peak - equity;
            if (dd > maxDd)
                maxDd = dd;
        }
        return (peak, maxDd);
    }

## 8. Answer to the question

> Peak-to-trough XAU drawdown should remove the trader?

**Yes.**

**ADMIT / REMOVE / FLATTEN implication (slot 17):**

- **ADMIT:** do **not** admit a trader whose completed XAU equity path has already given back ≥40% of peak. HEAD still admits first-seen names on that path. Treat that as a defect, not as policy.
- **REMOVE:** if they are on the roster, **remove** them (`DRAWDOWN_FROM_PEAK`). Do not wait for the book to go red. Do not KEEP because quality is 95.50 or net is still positive.

Wanting the book to “come back” is not an edge. A 40% XAU give-back on a name we already copied is dest inventory we should stop adding to and, when a sender exists, exit.
