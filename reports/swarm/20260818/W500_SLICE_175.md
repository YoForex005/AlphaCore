## 1. What the assigned file actually does

`NativeMt5BrokerConnector` is the in-process MetaQuotes Manager loader. It is the only production type that `using MetaQuotes.MT5CommonAPI` / `using MetaQuotes.MT5ManagerAPI` and calls `SMTManagerAPIFactory.Initialize`.

```1:4:D:/Prop/src/Mt5/Connectors/NativeMt5BrokerConnector.cs
using System.Runtime.InteropServices;
using MetaQuotes.MT5CommonAPI;
using MetaQuotes.MT5ManagerAPI;
using TraderIntelligence.Application.Contracts;
```

Connect is Windows-gated, then factory-init from `NativeDllDirectory` or `AppContext.BaseDirectory` (the host output dir):

```66:75:D:/Prop/src/Mt5/Connectors/NativeMt5BrokerConnector.cs
            if (!RuntimeInformation.IsOSPlatform(OSPlatform.Windows))
                throw new PlatformNotSupportedException("Native MT5 Manager API is Windows x64 only.");

            var dllDir = _opt.NativeDllDirectory ?? AppContext.BaseDirectory;
            var init = SMTManagerAPIFactory.Initialize(dllDir);
            if (init != MTRetCode.MT_RET_OK && init != MTRetCode.MT_RET_ERR_DUPLICATE)
            {
                LastError = Describe(init, "Factory.Initialize");
                throw new InvalidOperationException(LastError);
            }
```

After `CreateManager` it `Connect`s with pump, then falls back to `PUMP_MODE_NONE`. There is no `SendTrade`, `DealerSend`, `OrderAdd`, `TradeRequest`, or FIX `35=D` in this file (grep: no matches). Reads are Manager request APIs only (`GroupRequestArray`, `UserRequestArray`, `DealRequest` / `DealRequestByGroup`, `PositionRequest` / `PositionRequestByGroup`). `Ensure()` refuses work when not connected.

## 4. No-loss implication

**None from this angle on the current Windows API host.** This connector is a Manager **collector**: connect + group/user/deal/position **reads**. It does not send FIX `NewOrderSingle`, does not call MT5 `DealerSend` / `OrderAdd` / `TradeRequest`, and does not size live copy.

Because the API **is** `net8.0-windows` x64 and the MetaQuotes trio **is** next to `TraderIntelligence.Api.exe`, the hypothesized “DLL cannot load → empty/stale book → bad live state” blocker is **not** present on the intended Windows process. Load can still fail for other reasons (wrong OS, leftover `net8.0` exe, Linux compose, missing passwords, broker TCP / IP-block 1012), but those are not “API TFM is not net8.0-windows x64.”

A failed `Factory.Initialize` throws `InvalidOperationException` and leaves `_connected = false`. `Ensure()` then refuses all reads. Failed load does not invent positions or place capital.
