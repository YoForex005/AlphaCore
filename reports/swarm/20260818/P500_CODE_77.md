```10:35:D:\Prop\src\Domain\Volume\VolumeConverter.cs
public sealed class VolumeConverter
{
    public const decimal ManagerVolumeScale = 10_000m;
    public const decimal ExtendedVolumeScale = 100_000_000m;
    public const decimal HundredthsScale = 100m;

    public decimal Scale { get; }

    public VolumeConverter(decimal scale = ManagerVolumeScale)
    {
        if (scale <= 0)
            throw new ArgumentOutOfRangeException(nameof(scale), "Volume scale must be positive.");
        Scale = scale;
    }

    public decimal ToLots(ulong native) => native / Scale;

    public ulong ToNative(decimal lots)
    {
        if (lots < 0)
            throw new ArgumentOutOfRangeException(nameof(lots));
        return (ulong)decimal.Round(lots * Scale, 0, MidpointRounding.AwayFromZero);
    }

    public static VolumeConverter Manager => new(ManagerVolumeScale);
    public static VolumeConverter Extended => new(ExtendedVolumeScale);
}
```

## Profit implication

Hard-false **blocks** live profit. It does **not** protect it.

- 8463 catalog accounts cannot become destination LIVE books through this pin (and the pin is not even on the persist path).
- Achiever scores that land `SHADOW` (quality ≥ 70 and risk &lt; 40) stay paper / `SHADOW_ONLY`. Winner tape is not copied as real cTrader exposure.
- Starwave `deals-done scored 0` means that book is not even in the scorer loop; zero chance of a live harvest from that cohort this pass — independent of `CanPromoteToLive`.
- Dashboard dest real P&amp;L is **structurally 0**, independent of source PnL quality.
- `VolumeConverter` cannot create profit either: it only scales MT5 native volume → lots for reconstruction. Wrong scale (hundredths `100` vs Manager `10_000`) would 100× mis-lot a **future** send and also flip martingale/escalation features today. That send path is **not armed**.
- Even if someone flipped `CanPromoteToLive` to `true` without adding a `FromBaseline` LIVE branch, persist would still never write `LIVE`. The binding profit blockers are: no LIVE token from the scorer, `NewOrderSingleImplemented = false`, no `35=D` builder, measured `REAL_COPY` false.

If the question is “does hard-false keep us from giving back open profit?” — no live book exists to protect. Opportunity cost is the entire destination book.

## Lower-loss implication

Hard-false **does** lower loss (capital protection), together with other off-switches — **not** because `VolumeConverter` refuses LIVE.

- N=3 early evidence cannot auto-promote. Architecture / `docs/scoring.md` require SHADOW max. The pin is **stricter than required** (false for every state / every N).
- Application never calls `CanPromoteToLive`. Persist will copy whatever `SuggestedState` is. Safety today is “LIVE is not in the reachable set,” not “a gate evaluated LIVE then denied.”
- `REAL_COPY=false` (measured) + `NewOrderSingleImplemented=false` + no `35=D` builder: FIX may be LoggedOn and still cannot debit destination capital. Risk to capital from this process: **NONE** (`SAFE_BY_ABSENCE` of send plus flags).
- Copy persist forces `AllowFixSend = false` and `SHADOW_ONLY` unless an impossible conjunction (`AllowFixSend && LIVE && NOS && VenueReconciled`) holds — and that conjunction still only writes `LIVE_SEND_BLOCKED_UNIMPLEMENTED`.
- Demo SHADOW only: shadow PnL is Σ `SourceVsShadowSlippage`, not real P&amp;L. A bad Achiever book cannot lose live money through this path.
- VolumeConverter residual: if promotion were later flipped true **and** a NOS builder were added **and** dest-grid conversion were skipped, Manager `10_000` vs Extended `1e8` vs leftover hundredths would mis-lot a send. That loss path is **not armed**. Today the class only protects reconstruction/score integrity (correct 10_000 scale vs the false “hundredths” comment).

Net: **protecting against live loss, blocking live profit, not protecting profit.** Assigned file is the wrong SUT for the angle.
