## 1. What was read

`DealIngestionService.cs` is the whole `Application/Ingestion` folder. It defines `ITradingStore`, `DealIngestionService` (`SyncCatalogAsync` / `SyncBrokerAsync`), `BrokerSyncResult`, and `ReconstructionScoringService`.

The assigned type **does not** reference MetaQuotes, P/Invoke, `DllImport`, `LoadLibrary`, or a TFM. Ingest is connector-driven:

```37:50:D:/Prop/src/Application/Ingestion/DealIngestionService.cs
    public async Task<BrokerSyncResult> SyncCatalogAsync(string brokerCode, CancellationToken ct)
    {
        var connector = _registry.Get(brokerCode);
        await connector.ConnectAsync(ct);
        var brokerId = await _store.ResolveBrokerIdAsync(brokerCode, ct);
        var now = DateTimeOffset.UtcNow;

        var groups = await connector.GetGroupsAsync(ct);
        await _store.UpsertGroupsBatchAsync(brokerId, groups, now, ct);

        var accounts = await connector.GetAccountsAsync(null, ct);
        await _store.UpsertAccountsBatchAsync(brokerId, accounts, now, ct);

        return new BrokerSyncResult(groups.Count, accounts.Count, 0, 0);
    }
```

`SyncBrokerAsync` then calls `GetGroupDealsAsync` / `GetDealsAsync` / `GetGroupPositionsAsync` / `GetPositionsAsync` on whatever `IBrokerRegistry.Get` returns. DLL load, if any, happens **inside** that connector, not in this file.

Application TFM is portable by design:

This is **not** an empty PASS: the angle is about the **API process** that hosts this type. That host **is** `net8.0-windows` + `PlatformTarget` x64, and the MetaQuotes trio is already staged next to the API exe.

## 4. No-loss implication

**None from this angle on the current Windows API host.** `DealIngestionService` does not send FIX `NewOrderSingle`, does not call MT5 `DealerSend`, and does not size live copy. It only pulls catalog/deals/positions through `IMt5BrokerConnector` and upserts them.

Because the API **is** `net8.0-windows` x64 and the MetaQuotes trio **is** next to `TraderIntelligence.Api.exe`, the hypothesized “DLL cannot load → empty/stale book → bad live state” blocker is **not** present on the intended Windows process. Load can still fail for other reasons (wrong OS, leftover `net8.0` exe, Linux compose, missing passwords), but those are not “API TFM is not net8.0-windows x64.”

No capital is placed by a successful or failed Manager `Initialize` in this file.
