## Angle

Do negative-`netSourcePnl` `SHADOW` rows (served by this host) prove that scoring is **not** a profit gate?

**Yes.** This compilation unit never inspects source PnL. It rebuilds scores for every `ListLoginsAsync` login and maps `/api/traders` straight through to `GetTradersAsync`. That query stamps `State` from `TraderScore` and `NetSourcePnl` from a separate Σ of **all** completed reconstructed trades. `SHADOW` + `netSourcePnl < 0` is a legal row. Same-wave live book already has those rows (Achiever **302252** / **303174**). A profit gate would have refused them.

## Profit implication

**None from treating SHADOW as “copy these winners.”**

- Destination profit requires a live fill. This host never builds `35=D`. Measured `destinationRealPnl` is **0**.
- SHADOW on this API means “early-quality + low risk label,” not “positive source expectancy after costs.”
- Negative-`netSourcePnl` SHADOW rows are **already** in the served book. Copying the SHADOW set (if send were armed) would include those names **and** every losing XAU ticket inside the positive-aggregate names (`PersistDemoShadowAsync` / `GenerateShadowIntentsAsync` iterate all completed XAU).
- Same-wave SHADOW **aggregate** source PnL can still be positive while individual rows are negative, because the scorer never ranks or floors `NetSourcePnl`. Aggregate ≠ gate.
- Starwave scored 0 contributes **no** SHADOW edge. Achiever SHADOW is 100% demo challenge — pass-target selection, not a live prop book.
- `FEATURE_COPY_TRADING_ENABLED=true` on `/api/settings` must not be read as “profit mode.”

Do not copy `netSourcePnl` into dest PnL. Do not send the 8463-login catalog. Do not send the SHADOW slice as if it were a profit screen.
