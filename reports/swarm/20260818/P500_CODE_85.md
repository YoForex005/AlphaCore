## Angle (answered)

**Q:** Would gold scalp holds under 3 minutes survive FIX latency plus spread?

**A:** **No.** Three stacked facts:

1. **This file cannot copy a scalp at all.** The only outbound MsgType is Logon `A`. The TCP/TLS objects die at the end of `TryLogonAsync`. There is no heartbeat loop despite advertising `108=30`, no MarketDataRequest, no bid/ask, no ClOrdID, no `35=D`.
2. **If send were later hung off this probe, the latency budget is already larger than the trade.** Reconnect + TLS + 20 s cancel window + `141=Y` sequence reset + 15 s `MaxSourceSignalAge` + 5 s `MaxQuoteAgeMs` + two-sided dest spread consume a 163–180 s gold hold. Measured SHADOW example in the profit synthesis: login **322947**, avg hold **~163 s** — “Gold scalps die in spread + 15 s `MaxSourceSignalAge`.”
3. **Live capital is not being lost today.** `REAL_COPY=false`, `destinationRealPnl=0`, Starwave scored **0**, SHADOW is 100% demo. Absence of send is the only reason dest PnL is not already the left tail of those scalps.

## Why <3 min XAU holds die here

Round-trip cost of copying one scalp through **this** stack, even after a hypothetical sender:

| Hop | What this file / adjacent code actually does | Budget vs 180 s hold |
|---|---|---|
| Source deal → collector | Not in this file. Ingest is separate; no §36 hop clocks. | Unmeasured. |
| Decision | Scorer ignores hold time. Short gold can be SHADOW. | False positive “good”. |
| FIX session up | This file: TCP + TLS + Logon + one read, **then socket death**. Next send = full reconnect. | **0–20 s** per `CancelAfter`. |
| Seq / resend | `seq = 1`, `141=Y`. Every reconnect looks new. No gap-fill. | Missed ER = unknown fill on a 3-min ticket. |
| Heartbeat | `108=30` written, never sent. cServer will drop a kept socket in ~90 s. | Session cannot outlive the hold. |
| Quote / spread | Session has no MD. Live cards: bid/ask **null**. Shadow fills abort without `DestinationQuotes`. | Cannot even **see** dest spread. |
| Signal age | `MaxSourceSignalAge = 15s` on OPEN. | A late copy of a 163 s scalp is rejected **or** filled after the source is already flat. |
| Venue cost | Pepperstone XAU spread + commission, **two sides** (in and out). Scorer uses source `Profit+Commission+Swap`. | Typical dest spread already ≈ the whole scalp target. |
| Exit | No close path in this file. | Even a lucky entry has no timed exit. |

Architecture §36 (A73): stale XAU copy **destroys expected edge**. This session implements **none** of the five required instants (`source_event_time`, `collector_receive_time`, `decision_time`, `fix_send_time`, `execution_time`). You cannot prove a 3-minute hold “survived” latency you do not record.

P500 synthesis already named the loser: **copy-all and scalp-copy lose.** Login 322947 (SHADOW, +$4,950 source, avg hold ~163 s) is the textbook case — source PnL looks fine; dest spread + 15 s age + this reconnect probe would eat it.

`MaxAllowedSpread = 2.0` on gold is ~$200/lot if the unit is dollars — far too loose to save a scalp. It is also **unreachable** from this session because no quote is attached.

## Profit implication

**Do not copy gold holds under 3 minutes onto the Pepperstone / cTrader book.**

- Higher dest profit is **not** “send the SHADOW scalpers.” It is **exclude** them until a persistent FIX session + live bid/ask + measured source-to-fill p95 ≪ dest half-spread × 2.
- Starwave is **deals-done / scored 0**. Do not promote those names as scalp candidates.
- Achiever SHADOW is **all demo**. Demo profit-target scalps are adverse selection, not edge.
- `destinationRealPnl` is **0**. There is no dest tape proving any short-hold name is +EV after Pepperstone costs.
- `AverageHoldSeconds` must become a **hard filter** (e.g. reject OPEN when mean hold < 180 s or min hold < 5 s) before any sender exists. Today the scorer will SHADOW a 163 s book.

Profit path consistent with this file: keep `35=A` probe only; keep `REAL_COPY=false`; require a real quote tape and shadow after dest spread **before** any name with hold < 180 s is even discussed.

## Lower-loss implication

**Lowest loss is the current state: no `35=D`.**

- This file cannot place capital. Risk to capital from `CTraderFixSession` itself is **NONE** (`SAFE_BY_ABSENCE`).
- The **highest-frequency loss path**, if someone later adds send onto this probe, is exactly the angle: sub-3-minute XAU scalps. Two spreads + reconnect 20 s + 15 s stale reject / late fill + no exit session.
- Do **not** keep a socket “LoggedOn” and spray market orders. `LoggedOn` here is a **disposed** probe.
- Do **not** treat HeartBtInt 30 as a session that can babysit a 3-minute ticket. Nothing sends `35=0`.
- Do **not** raise `MaxSourceSignalAge` to 180 s to “let scalps through.” That copies stale gold. Lower loss = **tighter** age, not looser.
- Cert callback `(_, _, _, _) => true` is a security smell; it is not a trading edge. Do not expand this probe into a sender.

If send is ever implemented: persistent QuickFIX (or equivalent) with seq store, heartbeat soak, dest quotes, spread cap in **gold dollars that actually reject**, hold-time pre-filter, and dest lot cap far below source. Until then, not sending **is** the loss-reduction.
