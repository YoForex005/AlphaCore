## 1. Why this is lower-loss, not higher-profit

### 1.1 The failure mode (architecture §34, measured as a dest-ruin constructor)

```text
send 35=D (or maybe send — TCP write returned / process died / SSL dropped)
   ↓
did cServer receive it?
   ↓
ILLEGAL: SendNewOrderSingle(same ClOrdID)     // second NOS for a live IOC
ILLEGAL: SendNewOrderSingle(new  ClOrdID)     // two gold tickets if the first filled
LEGAL:   persist already done → EXECUTION_STATE_UNKNOWN
         → 35=H / 35=AF / 35=AN / positions
         → only then a NEW intent if venue never saw the first
```

Official cTrader market `OrdType=1` is **IOC**. A filled (or expired) market order often **does not remain** in the working-order book that mass status returns. That is the hard unknown case (A42 §1.4 / A34). Blind retry with a **new** tag 11 is how you open **two** dest gold positions for one source event.

cTrader Logon resets sequence (`141=Y` is what this repo already advertises in `BuildLogon`). FIX resend **cannot** recover the original `35=D` after reconnect. Persist-before-send + status/position query is the **only** recovery. There is **no** `35=H` / `OrderStatusRequest` / `MassStatus` implementation under `D:\Prop\src` this pass (`grep` = **0**).

### 1.2 Crash order is the whole point

| Crash moment | If persist is **after** send | If persist is **before** send |
|---|---|---|
| After persist, before socket write | n/a (no persist yet) | Row `NotSent`. Same `ClOrdID` may be sent **once**. | 
| After socket write, before persist | **No row.** Restart mints a **new** 11. If cServer filled the first: **double gold**. | Row already `sent_ack_unknown` (A42 T3) or at least has tag 11. Restart **must not** emit another `35=D`. |
| After write, session dead, no ER | Same double-send hole if the worker “retries” | `AfterDisconnectWithUnknownAck()` → `ExecutionStateUnknown`. `MayRetry` = **false**. |

The dest loss from the second ticket is **not** “the source was −EV.” It is **unintended extra lots** on Pepperstone. With HEAD `XauUsdOneToOneCopyPolicy.AllocationFactor = 1m` (1:1 source lots, dest clip only at `GoldLots.MaxQuantity=5`), a single duplicate 1.00 lot XAU open is **100 oz** extra. That is a **loss-cut** problem. It is not a profit model.

## 2. Law (quoted, not paraphrased away)

### 2.1 Architecture §33 — Idempotent Order Submission

> Every destination order must have a unique client order ID.

Persist before sending (`execution_intent_id`, `cl_ord_id`, source ids, dest account, symbol, side, qty, `created_at`, `status`). Distinguish `not sent` / `sent but acknowledgement unknown` / accepted / partial / filled / rejected / cancelled.

> Never simply retry a NewOrderSingle because the TCP connection broke.  
> First reconcile.

### 2.2 Architecture §34 — Unknown Execution State

> Do NOT blindly send the order again.

Set `EXECUTION_STATE_UNKNOWN`. Then `OrderStatusRequest` / `OrderMassStatusRequest` / ExecutionReports / position reconciliation.

> Only after reconciliation may the system decide whether another order is required.

### 2.3 Product docs (`docs/ctrader-fix.md` L65–73)

1. On reconnect, `35=H` for **all pending ClOrdIDs**.  
2. If the order exists, apply the ER.  
3. If unknown, mark failed and alert.  
4. **Never re-submit** a trade in unknown state — manual intervention required.  
5. `REAL_COPY_EXECUTION_ENABLED=false` disables live execution.

### 2.4 Official RoE (A42 pin)

> For a correct interaction, it is very important to have unique client order identifiers (`ClOrdID`) for all orders.

`35=D` tag 11 is required. `35=H` tag 11 is the **order’s** ClOrdID (a query, not a new allocation). Cancel/replace allocate a **new** 11 and reference `OrigClOrdID` (41).

### 2.5 A42 T0–T5 (the only legal send path)

Two commits, then a write: insert `not_sent` + unique `cl_ord_id` → re-check gates → **arm** `sent_ack_unknown` in a compare-and-set → **then** socket `35=D`. Zero rows armed → another worker owns it → **STOP**. Local throw after arm still counts as possibly-sent. **Do not revert to `not_sent`.**

This slot did **not** implement T0–T5. It measures that they are still **MISSING** on the product hop.

```3:16:D:\Prop\src\Domain\Execution\ClOrdIdFactory.cs
public sealed class ClOrdIdFactory
{
    public string Next(string executionIntentId, DateTimeOffset now, int sequence)
    {
        if (string.IsNullOrWhiteSpace(executionIntentId))
            throw new ArgumentException("Execution intent id is required.", nameof(executionIntentId));
        if (sequence < 0)
            throw new ArgumentOutOfRangeException(nameof(sequence));

        var compact = executionIntentId.Replace("-", "", StringComparison.Ordinal);
```

A42 required: pure `From(execution_intent_id)` → 26-char Crockford `[0-9A-Z]`, **no** attempt/sequence/clock in tag 11.

What `Next` actually does:

1. Embeds `now` to the second. Restart one second later → **different** 11 for the same intent.
2. Embeds `sequence`. A retry helper that does `sequence++` → **different** 11. That is the illegal “new ClOrdID for unknown” path.
3. Keeps lowercase (`intent-1` → `intent1`). A42 charset forbids it.
4. Truncates the intent id to 16 chars after hyphen strip. Collision surface is not UUID uniqueness.
5. Unit test (`ClOrdId_is_deterministic_and_unique_per_sequence`) only proves same `(intent, now, seq)` is stable and `seq=0` ≠ `seq=1`. It **rewards** the sequence footgun.

`ClOrdIdFactory` is **not** called from `CopyTradingService`, FIX session, or the worker. It cannot save a sender that does not exist, and it cannot stop a future sender from minting a second 11 after a drop.
