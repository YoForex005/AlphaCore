public sealed class VolumeConverter
{
    public const decimal ManagerVolumeScale = 10_000m;
    public const decimal ExtendedVolumeScale = 100_000_000m;
    public const decimal HundredthsScale = 100m;

    public decimal Scale { get; }

    public VolumeConverter(decimal scale = ManagerVolumeScale)
    {
        if (scale <= 0)
            throw new ArgumentOutOfRangeException(nameof(scale), "Volume scale must be positive.");
        Scale = scale;
    }

    public decimal ToLots(ulong native) => native / Scale;

    public ulong ToNative(decimal lots)
    {
        if (lots < 0)
            throw new ArgumentOutOfRangeException(nameof(lots));
        return (ulong)decimal.Round(lots * Scale, 0, MidpointRounding.AwayFromZero);
    }

    public static VolumeConverter Manager => new(ManagerVolumeScale);
    public static VolumeConverter Extended => new(ExtendedVolumeScale);
}

## Profit implication

Hard-false **blocks** live profit. It does not protect it.

- 8463 catalog accounts cannot become destination LIVE books through this pin. The pin is unused by Application, but `FromBaseline` also never emits LIVE, so persist cannot copy a LIVE state today.
- Achiever books that land `SHADOW` (quality ≥ 70 and risk < 40) stay paper / `SHADOW_ONLY`. Winner tape is not copied as real cTrader exposure. That is forgone destination P&L, not a hedge of existing dest P&L.
- Starwave `deals-done scored 0` means that cohort is not even in the scorer loop this pass — zero harvest, zero dest risk.
- Dashboard dest real P&L is **structurally 0**, independent of source quality. Shadow P&L is Σ `SourceVsShadowSlippage`, not venue P&L.
- `VolumeConverter` cannot create or defend profit. It only scales MT5 native volume → lots for reconstruction. A wrong future scale (Manager `10_000` vs Extended `100_000_000` vs the rejected hundredths `100`) would mis-size a send; today there is no send.

If the question is “does hard-false keep us from giving back open profit?” — no live book exists to protect. Opportunity cost is the entire destination book.

## Lower-loss implication

Hard-false **does** lower loss (capital protection), together with other off-switches — **not** because `VolumeConverter` refuses LIVE.

- N=3 early evidence cannot auto-promote. Architecture / `docs/scoring.md` require SHADOW max. The pin is **stricter than required** (false for every state / every N).
- Application never calls `CanPromoteToLive`. Persist will copy whatever `SuggestedState` is. Safety today is “LIVE is not in the reachable set,” not “a gate evaluated LIVE then denied.” That is a vacuous lock, not A22 R5-before-R6.
- `REAL_COPY=false` + no NewOrderSingle builder: FIX may be LoggedOn and still cannot debit destination capital. Risk to capital from this process: **NONE** (`SAFE_BY_ABSENCE` of `35=D` plus flags).
- Demo SHADOW only: a bad Achiever book cannot lose live money through this path.
- VolumeConverter residual: if promotion were later flipped true without dest-grid conversion, Manager vs Extended vs hundredths would mis-lot a send (10 000× or 100× error). That loss path is **not armed**.

Net: **protecting against live loss, blocking live profit, not protecting profit.** Assigned file is the wrong SUT for the angle.
