### Latent (not a hide bug on this slice)

The seeder (and `apps/mt5-worker/Worker.cs`) hardcode the four logins instead of `ITradingStore.ListLoginsAsync`. If the fake catalog later grows without updating that array, extra `Mt5Accounts` would be **unscored until** `/api/ops/resync` or `LiveIngestHostedService` (those paths score every listed login). Even then `GetTradersAsync` would still emit the account as `INSUFFICIENT_DATA`. That is a score-freshness gap, not dashboard hiding.

Empty PASS is **not** claimed: the file was fully read; the scored login set matches the seeded account set; the dashboard left-join keeps no-score accounts visible.

## No-loss implication

No-score / N=0 accounts stay on the trader list as `INSUFFICIENT_DATA`. `TraderStateMachine.CanPromoteToLive` is hardcoded `false`, so an empty 10003 (or a live account that has not been scored yet) cannot be treated as a LIVE copy source from this seed path. DemoSeeder does not send orders, does not flip kill-switch off-safe, and FIX rows are `Disconnected` with “NewOrderSingle off.” Capital is not at risk from this file; hiding those accounts would be the worse desk failure (incomplete book, false “all traders scored”).
