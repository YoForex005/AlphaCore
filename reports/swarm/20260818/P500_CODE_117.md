## Profit implication

Hard-false **blocks** live profit. It does **not** protect it.

- 8463 catalog accounts cannot become destination LIVE books through this pin. Application never even calls it; `FromBaseline` also has no LIVE branch, so persist cannot write `LIVE` from the scorer.
- Achiever scores that land `SHADOW` (quality ≥ 70 and risk < 40) stay paper / `SHADOW_ONLY`. Winner tape is not copied as real cTrader exposure.
- Starwave `deals-done scored 0` means that broker is not in the scorer loop this pass — zero harvest from that cohort, independent of the pin.
- Dashboard dest real P&L is **structurally 0** (literal), independent of source PnL quality. Shadow PnL is Σ `SourceVsShadowSlippage`, not destination money.
- `VolumeConverter` cannot create profit: it only scales MT5 native volume → lots for reconstruction. Wrong scale would mis-size a **future** send; today there is no send. Copy dest size, if ever armed, goes through `QuantityNormalizer`, not this class.
- Opportunity cost is the entire destination book. There is no open dest P&L to “protect.”

If the question is “does hard-false keep us from giving back open profit?” — no live book exists to protect.

## Lower-loss implication

Hard-false **does** lower loss (capital protection), together with other off-switches — **not** because `VolumeConverter` refuses LIVE.

- N=3 early evidence cannot auto-promote. Architecture / `docs/scoring.md` require SHADOW max. The pin is **stricter than required** (false for every state / every N).
- Application never calls `CanPromoteToLive`. Persist will copy whatever `SuggestedState` is. Safety today is “LIVE is not in the reachable set,” not “a gate evaluated LIVE then denied.”
- Measured `REAL_COPY=false` + `NewOrderSingleImplemented=false` + persist `AllowFixSend=false`: FIX may be LoggedOn and still cannot debit destination capital.
- Demo SHADOW only: a bad Achiever book cannot lose live money through this path.
- VolumeConverter residual: if promotion were later flipped true without dest-grid conversion, Manager `10_000` vs Extended `100_000_000` would mis-lot a send. That loss path is **not armed**. Copy already sizes via `QuantityNormalizer` (passthrough risk remains a **future** defect if wired to `35=D`).

Net: **protecting against live loss, blocking live profit, not protecting profit.** Assigned file is the wrong SUT for the angle.

Risk to capital from this file + this pin: **NONE** (`SAFE_BY_ABSENCE` of `35=D`). Residual: env can now arm `REAL_COPY`; sender is still unimplemented.
