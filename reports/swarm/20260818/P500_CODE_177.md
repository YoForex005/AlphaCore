```1:36:D:/Prop/src/Domain/Volume/VolumeConverter.cs
namespace TraderIntelligence.Domain.Volume;

/// <summary>
/// Converts MT5 native integer volume to lots.
/// IMTDeal::Volume() / SMTMath::VolumeToDouble uses MTAPI_VOLUME_DIV = 10_000
/// (4 decimal places). IMTDeal::VolumeExt() uses 100_000_000.
/// The comment in mt5-sdk mt5_types.h ("hundredths of lots") is incorrect.
/// Existing mt5_manager.cpp copies deal-&gt;Volume(), so the default scale is 10_000.
/// </summary>
public sealed class VolumeConverter
{
    public const decimal ManagerVolumeScale = 10_000m;
    public const decimal ExtendedVolumeScale = 100_000_000m;
    public const decimal HundredthsScale = 100m;

    public decimal Scale { get; }

    public VolumeConverter(decimal scale = ManagerVolumeScale)
    {
        if (scale <= 0)
            throw new ArgumentOutOfRangeException(nameof(scale), "Volume scale must be positive.");
        Scale = scale;
    }

    public decimal ToLots(ulong native) => native / Scale;

    public ulong ToNative(decimal lots)
    {
        if (lots < 0)
            throw new ArgumentOutOfRangeException(nameof(lots));
        return (ulong)decimal.Round(lots * Scale, 0, MidpointRounding.AwayFromZero);
    }

    public static VolumeConverter Manager => new(ManagerVolumeScale);
    public static VolumeConverter Extended => new(ExtendedVolumeScale);
}
```

## Profit implication

Hard-false **blocks** live profit. It does **not** protect it.

- Protecting profit would mean locking realized dest gains or hedging an open dest book. There is no dest book. `destinationRealPnl` is structurally 0.
- 8463 catalog accounts cannot become destination LIVE books through this pin. Application never calls it, and `FromBaseline` cannot emit LIVE anyway.
- Achiever scores that land SHADOW (quality ≥ 70 ∧ risk < 40) stay paper / `SHADOW_ONLY`. Winner tape is not copied as real cTrader exposure.
- Starwave scored-0 is not a harvest refuse — that cohort is not in the scorer loop.
- `VolumeConverter` cannot create dest profit. It only scales MT5 native volume → lots for reconstruction. Wrong scale would mis-size a *future* send; today there is no send.
- Opportunity cost is the entire destination book. If the question is “does hard-false keep us from giving back open profit?” — no live book exists to protect.

## Lower-loss implication

Hard-false **does** lower dest loss (capital protection), together with other off-switches — **not** because `VolumeConverter` refuses LIVE.

- N=3 early evidence cannot auto-promote. Architecture / `docs/scoring.md` require SHADOW max. The pin is **stricter than required** (false for every state / every N).
- Application never calls `CanPromoteToLive`. Persist will copy whatever `SuggestedState` is. Safety today is “LIVE is not in the reachable set,” not “a gate evaluated LIVE then denied.”
- `NewOrderSingleImplemented=false` + persist `AllowFixSend=false` + no `35=D` builder: FIX may be LoggedOn and still cannot debit destination capital. Risk to capital from this process: **NONE** (`SAFE_BY_ABSENCE`).
- Demo SHADOW only: a bad Achiever book cannot lose live money through this path. Shadow PnL is Σ slippage, not dest cash.
- VolumeConverter residual: if promotion and send were later armed without dest-grid conversion, Manager `10_000` vs Extended `100_000_000` (or treating hundredths as default) would mis-lot a ticket. That loss path is **not armed**. Copy dest qty already goes through `QuantityNormalizer` + `AllocationFactor=0.05`, not this type.

Net: **protecting against live loss, blocking live profit, not protecting profit.** Assigned file is the wrong SUT for the angle.
