## 0. Verdict

**PASS.** Remove/flatten is **not missing**. A loser who is currently `ADMITTED` is evicted on the next `TickRosterAsync` (`Status = REMOVED:{reason}`, `Action = CloseExposure`, dest `FLATTEN_LOSS_CUT` intents). New dest opens require `Status == "ADMITTED"`. They are **not** left on the roster as a member.

**One-line:** Losers are stamped `REMOVED:{reason}` and dest-flatten intents are minted. That is the roster off-switch. Do not confuse it with a live dest fill, and do not confuse a next-tick re-ADMIT of a still-green streak/DD book with “remove missing.”

`CopyRosterEngine.Decide` auto-removes losers. `Remove(reason)` always sets `Action=RemoveAndFlatten`, `FlattenDestination=true`, `AllowNewOpens=false`.

| Loser class | Predicate | Reason | On-roster only? |

| Blocked state | `RISK_BLOCKED` / `DISQUALIFIED` / `PAUSED` | `STATE_{state}` | No (always Remove) |

## 3. Flatten is present (hop persist)

On `RosterAction.RemoveAndFlatten` (`CopyTradingService` L165–191):

1. Insert or update the roster seat to `Status = "REMOVED:" + decision.Reason`, `Action = CloseExposure`.
2. If `decision.FlattenDestination` (always true from `Remove()`), call `FlattenOpenCopiesAsync`.

`FlattenOpenCopiesAsync` L416–449 walks prior dest-copy **opens** (`Action == OpenExposure` and `IdempotencyKey.StartsWith("copy:")`) and inserts a dest-only close:

| Field | Value |
|---|---|
| `Action` | `CloseExposure` |
| `Status` | `FLATTEN_LOSS_CUT` |
| `IdempotencyKey` | `copy:{broker}:{login}:{sourcePositionId}:close` |
| Qty | prior open `RequestedQuantity` |
| `ExpiresAt` | now + 15 s |
| Risk / `Evaluate` | **not called** (intentional bypass so REMOVE cannot trap Close) |
| MT5 source | **never touched** (engine comment L31; no Manager close) |

Hosted loop (`CopyTradingHostedService` L28–30, every 20 s after 8 s): `TickRosterAsync` **then** `GenerateShadowIntentsAsync` **then** `ExecuteDemoCopyAsync`. Tick writes REMOVE before the open hop can copy the same loser.

`SaveChanges` runs when `changed > 0` (L195–196). A Remove always increments `changed`.

## 4. Adversarial residuals (do not flip this slot’s FAIL rule)

These are holes. They are **not** “remove/flatten missing.”

### 4.1 Streak / DD re-ADMIT (loser can bounce back)

`CONSECUTIVE_LOSSES_*` and `DRAWDOWN_FROM_PEAK` fire only when `alreadyOnRoster`. `onRoster` requires `Status == "ADMITTED"`. After REMOVE:

- Tick N: `ADMITTED` + streak/DD → `REMOVED:…` + flatten intents. **Off roster.**
- Tick N+1: `onRoster=false`. If `IsTraderEligible` is still true (net XAU > 0, n ≥ 20, demo/contest, clean size, SHADOW+), `Decide` returns **`Admit` / `AUTO_ADMIT`**. L160 sets `Status = "ADMITTED"` again.

Negative book does **not** bounce: `XAU_BOOK_NOT_PROFITABLE` → `NOT_YET_…` Keep, not Admit. Blocked state / size pattern / real group always Remove.

First-seen admit also **ignores** streak and DD. A still-green 3-loss or 40% give-back book can enter as `ADMITTED` and only be cut on a later tick.

This is oscillation, not a missing `RemoveAndFlatten` symbol.

### 4.2 `ShouldFlattenOpenCopy` is dead

`CopyRosterEngine` L95–96 / unit `Open_unrealized_loss_beyond_cap_flattens_that_copy`: unrealized ≤ −$150. **0** callers in `src/`. `Decide` and `TickRosterAsync` never read dest MTM. A single open dest loser does **not** eject the login (correct per sibling P503_R_13 / R_23). That is not “loser left on roster”; the login is still a completed-book winner.

### 4.3 Venue flatten is not the roster flatten

`ExecuteDemoCopyAsync` closes dest only when the **source ticket is completed** (`CopyLifecycle.ShouldCloseDest(sourceCompleted, destFilled, destAlreadyClosed)` L525). It does **not** consume `FLATTEN_LOSS_CUT` rows. A removed login with **still-open** source positions keeps dest inventory until the source closes (or until a human closes dest). Roster membership is still `REMOVED`. Dest leftover risk ≠ leftover roster seat.

`GenerateShadowIntentsAsync` after `REMOVED` `continue`s the whole trader (L231–232), including the source-close mirror. Flatten of known `copy:` opens is the TickRoster path, which bypasses `Evaluate`. Policy `Evaluate` would reject Close once the snapshot fails `IsTraderEligible` — latent trap if someone later routes flatten through policy.

### 4.4 No `TickRosterAsync` test

`tests/` has **0** references to `CopyTradingService` / `TickRosterAsync`. Engine facts lock Decide. Hop persist of `REMOVED:` + `FLATTEN_LOSS_CUT` is untested. That is coverage, not absence of the code.
