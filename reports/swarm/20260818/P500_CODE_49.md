## Angle

Do negative `netSourcePnl` SHADOW rows prove `BaselineScorer` / `ReconstructionScoringService` is **not** a profit gate?

A profit gate would require `NetPnl > 0` (or dashboard `netSourcePnl > 0`) **before** `SuggestedState = SHADOW` and before `ShadowOrders` / `CopyIntent` persist. If a losing book can still land `SHADOW`, scoring is a **behavior / risk labeler**, not an “only winners copy” filter.

        if (features.CompletedXauTrades == 0)

## Profit implication

**None from treating SHADOW as a winners list.** Negative `netSourcePnl` SHADOW rows are a **designed-reachable** outcome: quality can hit 70 on a disciplined losing tape. `/api/ops/resync` will stamp those logins `SHADOW` and, if a dest quote exists, persist demo shadow fills. That does **not** book Pepperstone P&L.

- `destinationRealPnl` stays **0** while `REAL_COPY` is false and `NewOrderSingle` is off (this file’s recon note).
- Scoring 8463 Achiever accounts (and Starwave at deals-done / scored 0) is **observation**. It cannot turn a losing source book into destination profit.
- Do **not** rank or auto-size off `EarlyQualityScore` / `SHADOW` as if `netSourcePnl > 0` were implied.
- Do **not** copy `netSourcePnl` into dest / live fields. Shadow slippage Σ is also not dest P&L.
- A later “copy the SHADOW book” policy would include **net-negative** disciplined XAU tapes as first-class candidates. That is a **negative-expectancy** source set on one dest gold book.

Profit capture, if it is ever built, needs an **explicit** `netSourcePnl > 0` (and more) conjunct that **does not exist** on this path.

## Lower-loss implication

**Today: capital not at risk from this file.** `FEATURE_COPY_TRADING_ENABLED` is a literal `false`. `REAL_COPY_EXECUTION_ENABLED` is a read-only echo. Recon text states NewOrderSingle is still off. SHADOW persist is demo `SHADOW_ONLY`. FIX LoggedOn does not become a send because of `Program.cs`. Grep of this file found no `35=D` builder.

**Honesty on loss reduction:** the scorer does **not** keep losers off the copy-eligible set. If a later change wired `SHADOW` → live `35=D`, a **net-negative** disciplined book (`quality = 70`, `risk = 0`) would be first-class eligible. `RISK_BLOCKED` only catches `risk >= 80` or **martingale ∧ DD ∧ NetPnl < 0** — not clean losers.

Lower-loss vs live copy is therefore **“do not send”** (`REAL_COPY` false + no `NewOrderSingle` in this file), **not** “scorer filtered unprofitable traders.” Do not enable `REAL_COPY` to “use the SHADOW list.” Do not add a profit gate in chat; if one is required it belongs in `FromBaseline` / persist, versioned, tested with a three-loser SHADOW fixture that today would **pass into SHADOW**.
