## Angle

Would XAUUSD / gold scalp holds **under 3 minutes** (source position life ≤180 s) still have dest-side edge after (a) the FIX / TLS / logon latency implied by this session and (b) destination bid/ask spread, if copied to Pepperstone / cTrader?

## Verdict

**FAIL — NO. Gold scalp holds under 3 minutes would not survive FIX latency plus dest spread on this path.**

`CTraderFixSession` is a **one-shot TLS Logon probe**. It connects, writes one FIX 4.4 `35=A`, reads one 4096-byte chunk, returns `LoggedOn=true` if the reply MsgType is `A`, then **disposes the socket**. It never:

- keeps a session alive for 180 s
- runs the advertised `HeartBtInt=30` loop
- subscribes to XAUUSD market data
- measures bid, ask, or spread
- sends `NewOrderSingle` (`35=D`)
- receives an ExecutionReport
- times source-to-fill

A sub-3-minute gold scalp needs dest entry, dest exit, and remaining hold after copy delay that still covers **2× dest spread + slippage**. This compilation unit provides none of those. Adjacent gates make the economics worse: `MaxAllowedSpread = 2.0` can consume a whole scalp target; `MaxSourceSignalAge = 15 s` is already 8.3% of a 180 s hold; a 20 s logon timeout is 11% of the hold *before any order exists*.

FIX **LoggedOn** in the slot brief is this MsgType-A snapshot, not a live quote tape and not a TRADE socket that can flatten a 3-minute gold position. Hosted service immediately pins `_runtime.RealCopyEnabled = false`.

### 1. One-shot connect + TLS + single read, 20 s budget, cert check off

The whole probe is bounded by a **20-second** linked cancel. That is **11% of a 180 s hold** before any dest order exists. `using var tcp` / `await using var ssl` **kills the socket when `TryLogonAsync` returns**. There is no long-lived initiator.

            timeoutCts.CancelAfter(TimeSpan.FromSeconds(20));
            await tcp.ConnectAsync(host, sslPort, timeoutCts.Token);
            await using var ssl = new SslStream(tcp.GetStream(), false, (_, _, _, _) => true);

                TargetHost = host,

Password is accepted as a method argument and placed in tag **554**. Values are **not** quoted here.

## Lower-loss implication

**If this session were used as a live send path, lower-loss would FAIL:**

- Worker marks TRADE `Disconnected` / “NewOrderSingle remains off” every 15 s.

- Architecture §63: a 3-minute FIX outage must expire the 20 source opens, not catch them up. Those scalps **die unhedged**. That is lower *dest* loss and **higher leftover source exposure**.
- Enabling live copy of holds <3 minutes would **raise** dest loss: fill after source already banked, or chase after source already stopped; pay dest spread on both open and close.

The only honest loss-reduction for sub-3-minute gold on this stack: keep `REAL_COPY` false; do not copy holds whose remaining life is ≤ 2× measured dest spread + measured source-to-fill; keep `SIGNAL_STALE` at **15 s** (or tighter); keep A53 **0 NOS** after a 3-minute TRADE gap. That measurement is **not** in `CTraderFixSession.cs`.
