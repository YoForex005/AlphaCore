## 2. Why the answer is NO (even if a sender existed)

### 2.1 It is not 1:1 copy

`XauUsdOneToOneCopyPolicy` class law: copy the **next** XAU event 1:1 (lots, SL/TP, side). Close when the **source** closes, not at a predicted time, not because dest MTM flipped.

Independent dest flatten while the source ticket is still open:

1. Dest goes flat; source stays in the trade.
2. Open idempotency key `copy:{broker}:{login}:{position}:open` already exists → hopper will **not** re-open that ticket.
3. If source later recovers, dest has **locked the loss** and missed the copy. That is a dest stop overlay, not copy.
4. If a later author deletes the open key to “retry,” dest re-enters at a worse price (chase / scale-in). Forbidden size-pattern adjacent.
5. Close loop only runs after source `Completed`; flatten already consumed `:close` → source-close is a no-op. Tracking error is permanent for that ticket.

P502: lookahead-banned. Cutting dest because *this* dest print is red is the dest-side twin of “only copy winners.”

### 2.2 $150 is not lot-scaled — both unit interpretations are broken

`GoldOuncesPerLot = 100`. True dest USD ≈ `Δ$ × lots × 100`.

| Dest lots (HEAD 1:1, max 5) | True-USD $150 = Δ$ | Shadow `MarkToMarket` = 150 |
|---|---|---|
| 0.01 | **$150 / oz** | $15,000 / oz (`$1.5M` real) |
| 0.05 (roster test fixture) | **$30 / oz** | $3,000 / oz |
| 1.00 | **$1.50 / oz** | $150 / oz (`$15,000` real) |
| 5.00 (`GoldLots` / `MaxPositionQuantity`) | **$0.30 / oz** | $30 / oz (`$15,000` real) |

Risk engine `MaxAllowedSpread = 2.0` ($/oz). A legal dest spread of $0.40 already exceeds the 5-lot true-USD cap. **Flatten-on-spread.**

If the caller passes `MarkToMarket` (no ×100), the cap almost never fires on retail size and fires at a **$15,000** 1-lot hole — larger than `MaxDailyExecutionLoss=2000` and `MaxLossPerTrader=500`. The helper then does **not** protect the account; the daily/trader caps (which **Reject including CLOSE** at L117–124) would freeze the exit.

`P500_BOOK_13` / A45: MAE is `FeatureQuality.Unavailable`. **Do not claim this $150 is an MAE stop.**

### 2.3 Loss caps are not an edge

Same honesty as `P500_BOOK_8` / `48` / `68` on `$500` / `$2,000`: the print has **already happened**. Flattening dest after −$150 realizes the loss, pays dest spread/slip, and **removes the only path that could offset it** (source still in the trade). Wanting a smaller red number does not create expectancy.

Copy-all 8463 would still import `RISK_BLOCKED` **−$241,580** inside scored XAU **−$154,425**. A per-ticket $150 cut does not filter that tail. The tail is a **trader-selection** problem (do not ADMIT martingale / negative book), not a dest MTM problem.

### 2.4 Flatten send is not a control

D102 / A48 / P503_R_18:

- `KillSwitchMode.EmergencyFlatten` only blocks `IsIncreasing`. It does **not** flatten.
- `docs/risk.md` “total loss → Emergency Flatten all positions” is **not** product law and must **not** be implemented as auto-`35=D`.
- Loss/DD predicates apply to **every** action. Wiring flatten through `Evaluate` **freezes** the exit (A71 G21–G22 FAIL).
- `AllowFixSend` requires `KillSwitch==None` + `Real` + `Reconciled` + healthy. Flatten under `EmergencyFlatten` **cannot** send.
- `FLATTEN_LOSS_CUT` rows expire in **15 s** on a **20 s** poll. Even a future sender would race the expiry.

### 2.5 What a later dest-side ruin cap *would* have to be (not this slot’s yes)

|---|---|---|---|---|
| STOP_NEW | dest daily / trader realized / DD latch | no new OPEN/INCREASE | n/a | RiskManager |

A dest-ticket stop, if ever wanted, must be **lot-scaled** (e.g. $ / oz or % of dest equity), conservative-marked, dest-id known, must **not** REMOVE the trader, must **not** recopy the same source ticket, and must **not** be $150 flat. That is a new product (dest overlay), not HEAD 1:1 copy. Do not build it to “use” the helper.
