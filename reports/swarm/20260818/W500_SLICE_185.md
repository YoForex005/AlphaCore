## 4. No-loss implication

**None from this angle on the current Windows API host.** `EfDashboardQueries` does not send FIX `NewOrderSingle`, does not call MT5 `DealerSend` / `OrderSend`, and does not size live copy. It only reads persisted rows and `LiveRuntimeStatus` for dashboard tiles.

The hypothesized failure mode was: API TFM is not `net8.0-windows` x64 → MetaQuotes / `MT5APIManager64.dll` cannot load → Manager never connects → empty or stale source book while live accounts keep trading. That TFM blocker is **not** present on the intended Windows process. Load can still fail for other reasons (wrong OS, leftover `net8.0` exe, Linux compose, missing passwords, broker 1012), but those are not “API TFM is not net8.0-windows x64.”

No capital is placed by a successful or failed Manager `Initialize` in this file. A TFM-blocked Manager load would be fail-closed (no live census), not a send path. `DependencyInjection` still hardcodes `RealCopyEnabled = false`.
