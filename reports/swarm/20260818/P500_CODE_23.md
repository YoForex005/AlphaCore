## Verdict

**FAIL — not strong enough. This file does not implement a martingale filter at all, and the averaging “filter” is a boolean latch with no size, count, or open-book severity. Downstream scoring cannot close the hole the reconstructor leaves.**

`TradeReconstructor` is a **netting book + flagger**, not a tail gate. It:

1. Reconstructs same-`PositionId` scale-ins.
2. Sets `WasScaledIn` on every same-side add.
3. Latches `WasAveragedDown` when the add is **strictly worse** than the pre-fill entry VWAP.
4. Emits `MaxVolumeLots` / `InitialVolumeLots` and stops.

It never rejects, never caps, never emits a martingale event, never measures intra-lifecycle lot ratio, and never withholds an averaged-down lifecycle from scoring or shadow copy. Classic XAU recovery (add on the same ticket as price runs against you, then close as one “trade”) is therefore **invisible as martingale** and only **optionally** visible as a single `true` bit.

That is not a left-tail filter. A filter that cuts the left tail would (at minimum) treat intra-position size-up-in-loss as a **severe** event, grade it by add-count and `Max/Initial` ratio, include **still-open** pyramids, and force `RISK_BLOCKED` / block `INCREASE_EXPOSURE` before any copy. None of that lives in this file. What lives downstream is also too weak to compensate (A22 floors are not implemented; averaging never blocks state by itself; `RiskEngine` has no averaging rule).

**Empty PASS is refused.** The SUT was read in full (347 lines). Tests lock one long add-lower happy path. They do not prove tail control.

## What the file actually does

### No filter surface

`Reconstruct` scopes by broker + login, groups by `PositionId`, applies IN / OUT / INOUT, and returns **every** lifecycle. The only exclusion is `lots <= 0` (skip the deal) and non-trading actions (already dropped). Canceled tickets only flip `EligibleForFirstThree` on that `PositionId`; they do not suppress averaging flags or scoring.

    public IReadOnlyList<ReconstructedTradeResult> Reconstruct(
        string brokerId,
        long login,
        IReadOnlyList<NormalizedDeal> deals)
    {
        // ... broker + login filter, dirtyPositions = BuyCanceled|SellCanceled ...
        foreach (var group in trading.GroupBy(d => d.PositionId))
        {

            if (dirtyPositions.Contains(group.Key))

### Averaging detector (the entire “filter”)

```248:264:D:\Prop\src\Domain\Reconstruction\TradeReconstructor.cs
        public void ScaleIn(NormalizedDeal deal, decimal lots)
        {
            // Averaging down: add to a long after price fell, or to a short after price rose.
            var worse = Direction == TradeDirection.Long
                ? deal.Price < EntryVwap
                : deal.Price > EntryVwap;
            if (worse)
                WasAveragedDown = true;

            WasScaledIn = true;
            RemainingLots += lots;
            if (RemainingLots > MaxVolumeLots)
                MaxVolumeLots = RemainingLots;
            _entryNotional += deal.Price * lots;
            _entryLots += lots;
            ApplyCommon(deal);
        }
```

Polarity matches A21 §4.1 (long add-lower / short add-higher, compare **before** VWAP update). That is detection correctness, not filter strength.

What this latch does **not** do:

| Hole | Why it fails to cut the left tail |
|---|---|
| No add-count | 1 tick below VWAP ≡ 12 recovery adds. |
| No distance | 0.01 below VWAP ≡ $80/oz crash. |
| No lot ratio | `InitialVolumeLots` and `MaxVolumeLots` are stored; **never compared**. 0.01 + 10.00 is one `true`. |
| Strict inequality | Add **at** VWAP (grid same price) is not averaging. |
| Same `PositionId` only | Hedging-mode gold grid = new tickets = **no** `ScaleIn` = `WasAveragedDown` stays false. A21 §1.6 is correct for reconstruction identity and **wrong** as a tail screen if you stop there. |
| Pyramiding in profit | Add above VWAP on a long: `WasScaledIn=true`, averaging false. Size still explodes. |
| No SL coupling | Averaging with `InitialSl == null` is the blow-up. Reconstructor only copies SL from deals. |
| No reject / cap | `RemainingLots += lots` is unbounded. |
| Boolean only | Downstream `trades.Any(t => t.WasAveragedDown)` — one bit for 8463 books. |

There is no `Martingale` field on `OpenTrade` / `ReconstructedTradeResult`. Intra-lifecycle doubling after unrealized loss is **not named**.

## Profit implication

- **Selection leakage, not alpha.** Achiever is being scored today. A profitable netting recovery book (high win rate, fat right tail after adds, rare wipe) will often land `SHADOW` / `WATCH` with `AveragingDown=true` and `Martingale=false`. Ranking by early quality **rewards** the same process that prints the left tail. That is the opposite of a profit filter: you keep the traders whose edge is “gold mean-reverted this week.”
- **Starwave deals-done scored 0.** Those ~1.9k logins contribute **no** reconstructed flags. You cannot harvest or reject tail from an empty book. Profit from Starwave copy/selection is **zero** until deals exist.
- **Shadow demo PnL is not a profit signal.** Peak-lot / VWAP simulation does not replay scale-ins. It will **overstate** fill quality vs a live add-down path and will **not** show the open-pyramid MAE. Do not treat `SHADOW` quality as evidence the book is copyable.
- **8463 accounts, one boolean.** `Any(WasAveragedDown)` cannot rank severity. Capital allocated by “not flagged martingale” will concentrate in the **intra-position** recovery cluster — the cluster that blows up on the first one-way XAU trend.
- **No destination profit today.** `destinationRealPnl 0` + `REAL_COPY false` means these weak filters are not making money. They are also not losing money. They are a **classification error** waiting on a flag flip.

- **Do not flip `REAL_COPY` on Achiever SHADOW names** until (1)–(4) exist. The 8463-account census is a **population of unfiltered left tails**, not a proven book.
