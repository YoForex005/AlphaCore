## 0. Verdict in one paragraph

**No.** `TradeReconstructor` does not cut the left tail. It rebuilds position lifecycles, latches `WasScaledIn` / `WasAveragedDown`, and **never excludes** recovery, grid, or size-up books from the first-three / completed-XAU set. Classic left-tail structure — add size on a losing position, or open a **new** `PositionId` after a loss — is either a boolean or invisible. Martingale is not computed here; it is a later adjacent-trade `MaxVolumeLots > prev * 1.25` flag that still does not hard-block a **profitable** martingale. On the measured live posture (`REAL_COPY` false, dest PnL 0) this is a **ranking / queue-poison** defect, not a live dest blowup today. If copy ever flips, these filters will not keep recovery books out of the intent path.

`Reconstruct` scopes deals by broker/login, marks canceled-deal `PositionId`s dirty, groups by `PositionId`, and emits completed + still-open lifecycles. The only hard exclusion from early-score input is dirty/canceled:

`WasAveragedDown`, `WasScaledIn`, and `MaxVolumeLots / InitialVolumeLots` are **not** in that predicate. An averaged-down or doubled-in lifecycle remains `EligibleForFirstThree = true` and is counted by `CountCompletedXauUsdTrades` / `IsEarlyScoreEligible`.

### 1.2 No martingale symbol in this file

`grep` over `D:\Prop\src\Domain\Reconstruction` for martingale: **zero hits**. The SUT never compares consecutive completed trades, never ratios `MaxVolumeLots` vs prior loser, never sets a martingale flag. Intra-position doubling is recorded only as volume + scale-in:

```248:264:D:\Prop\src\Domain\Reconstruction\TradeReconstructor.cs
        public void ScaleIn(NormalizedDeal deal, decimal lots)
        {
            // Averaging down: add to a long after price fell, or to a short after price rose.
            var worse = Direction == TradeDirection.Long
                ? deal.Price < EntryVwap
                : deal.Price > EntryVwap;
            if (worse)
                WasAveragedDown = true;

            WasScaledIn = true;
            RemainingLots += lots;
            if (RemainingLots > MaxVolumeLots)
                MaxVolumeLots = RemainingLots;
```

A 0.10 lot long that adds 1.00 after price drops is the same boolean as a 0.01 add. There is no add-ratio, no event count, no unrealized-loss martingale, no revenge flag.

### 1.3 Averaging detector: polarity OK, filter missing

Same-side `DealEntry.In` calls `ScaleIn`. Worse-than-current-VWAP (compared **before** `_entryNotional` / `_entryLots` update) latches `WasAveragedDown`. That matches A21 F07/F08 polarity (long add-lower / short add-higher). C51 already confirmed the working-tree flip.

What it does **not** do:

| Left-tail pattern | SUT behavior | Cuts tail? |
|---|---|---|
| Same-position add at worse price | `WasAveragedDown = true`; trade still completed + eligible | **No** |
| Same-position add at **better** price (pyramid / add-in-profit) | `WasScaledIn` only | **No** (not averaging; also not filtered) |
| Same-position **double size** after unrealized loss (classic martingale) | volume + boolean only; no size-ratio | **No** |
| New `PositionId` after a closed loser (grid / recovery / hedge account) | new `OpenTrade`; no cross-id link | **Invisible here** |
| Multi-symbol / non-XAU recovery | reconstructed but dropped later only if not XAU | N/A for XAU left tail |
| Tiny worse add (noise) vs 10× recovery add | same bool | **No severity** |
| Opposite `IN` on same id | treated as reverse remainder (`ApplyIn` unexpected path) | not averaging |
| Partial close then re-add | re-add is another `ScaleIn`; still one lifecycle flag | **No** |

`ToResult` copies the booleans out. `Fees` is hard-coded `0m`. No reject, no `EligibleForFirstThree = false` on avg-down, no drop from `CompletedXauUsdTrades`.

### 1.4 Position grouping hides the real left tail

`trading.GroupBy(d => d.PositionId)` means a hedging/grid book that opens **new** tickets after each loss is a sequence of “clean” single-entry trades. That is exactly how many XAU recovery EAs look on MT5 netting/hedging. The reconstructor will emit many small completed trades with `WasAveragedDown = false` and growing `MaxVolumeLots`. Martingale, if detected at all, is **only** later in `BaselineScorer` on **adjacent completed** XAU trades.

## 4. Profit implication

These are **not** filters that protect expected dest PnL. They **preserve** recovery books in the Achiever scoring universe (8463 accounts). A grid/average-down EA that ends the first three XAU lifecycles green will:

1. Count as `IsEarlyScoreEligible` (N≥3).
2. Carry `WasAveragedDown` into `FeatureSnapshot.AveragingDown`.
3. Take only +20 risk / −15 behavior — still eligible for WATCH/SHADOW if the book looks “pretty.”
4. If the same book uses **new positions** after each loss and sizes up 1.26×, C32 already showed **SHADOW** is reachable.

That **inflates the SHADOW queue with left-tail styles**. Starwave scored 0 deals-done in the given live snapshot, so this slot is not claiming a measured dest profit today (`destinationRealPnl` 0). The profit path that **is** at risk is future copy selection: when `REAL_COPY` is still false, ranking still trains operators and any later enable-copy on “high quality” recovery books. Those books make money until one XAU run does not mean-revert; that is the entire left tail. The reconstructor will have already fused that run into one lifecycle with a boolean, or split it into “clean” tickets.

There is **no** dest profit to harvest from tightening this SUT while `REAL_COPY` is false. There **is** negative expected dest profit if these flags are treated as sufficient and copy is later enabled on SHADOW Achiever names.

## 5. Lower-loss implication

To actually cut the left tail, this file would need to emit **severity**, not just polarity, and the completed-XAU gate would need to **fail closed** on recovery structure:

1. **Intra-position size-up after worse price** should be a first-class feature: add-count, `MaxVolumeLots / InitialVolumeLots`, lots added while `worse==true`. A 10× scale-in is the blowup, not a 1-tick 0.01 add.
2. **`EligibleForFirstThree = false`** (or a separate `EligibleForCopyScore = false`) on any lifecycle with `WasAveragedDown` **or** `MaxVolumeLots / InitialVolumeLots` above a hard ratio. A21 already calls one avg-down in a 3-trade book severe.
3. **Martingale does not belong only in the scorer.** Reconstruction is the only place that sees deal order **inside** a position. Without `WasMartingaledIn` / add-after-unrealized-loss, the scorer’s adjacent-trade 1.25× test **misses the primary XAU recovery pattern**.
4. Cross-`PositionId` recovery (grid/hedge) cannot be solved inside one `GroupBy(PositionId)`. The SUT should at least expose per-lifecycle `InitialVolumeLots`/`MaxVolumeLots`/`WasScaledIn` with enough fidelity that a later detector can see vol-span; it already exposes those, but it **must not** present a 20-add recovery as a single “normal” completed trade for first-three eligibility.

Until those exist, averaging/martingale “filters” do **not** reduce dest left-tail loss. They only label some same-id worse adds. Live dest loss is currently **0** because `REAL_COPY` is false and all SHADOW is demo — that is a **copy-gate**, not this SUT. Do not credit TradeReconstructor with loss reduction it does not implement.
