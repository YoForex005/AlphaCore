## Angle (answered)

**Q:** Would copying every scored XAU trader lose money if `RISK_BLOCKED` dominate the book?

**A:** **Yes, expected dest loss**, conditional on a live send path. Reasons, in order:

1. **`RISK_BLOCKED` is a loser-shape, not a rank.** Baseline law: `risk >= 80` **or** `(Martingale ∧ MaxDrawdown > 0 ∧ NetPnl < 0)` → `RISK_BLOCKED`. The unit fixture is three doubling losers (`0.10 → 0.20 → 0.40` lots, −100/−200/−400). Copying that book copies the **losing side** of size-up-after-loss onto one dest gold book.
2. **`risk.md` does not exclude those names.** “Every trade request is evaluated against all limits **before** submission.” Limits are % DD, lot/position/trade counts, slip — not `CurrentState`. Dominated book ⇒ the 100-trade daily circuit breaker fills **FIFO with blocked-quality names**, not SHADOW.
3. **The documented stop is too late.** Daily-loss kill switch = 5% from day-start equity, positions **stay open**. Total-loss flatten = 10% from initial balance, then market-close everything. Copy-all of a martingale-majority book eats the first 5–10% **by design**, then either sits in open losers (kill) or crystallizes them at the worst print (flatten).
4. **Timing + slip make XAU copy-all worse.** 100–2000 ms delay on gold martingale adds = late fill. 30-point slip tolerance is large vs code `MaxSlippage = 1.5`. Stale trades after 2000 ms are “logged but not executed,” which is **not** a quality filter — it is a latency reject that still lets the first 2 s of a size-up through.
5. **Limits in this file are looser than the unused / adjacent engine.** `risk.md` allows **50 lots / 25 positions**. `RiskLimits` defaults are **5 lots / 20 positions / $500 per-trader / $2_000 daily / $3_000 portfolio / 20 gross / 10 net XAU**. Following the assigned doc would let more of a `RISK_BLOCKED` book through than the code stub would.
6. **Volume note in the assigned file is internally inconsistent.** “Hundredths of lots (50000 = 5.0 lots)” cannot coexist with `MT5_VOLUME_SCALE=10000`. Blind copy-all with the wrong scale would **size** the martingale book wrong (another loss channel).
7. **Product does not copy-all today.** `PersistDemoShadowAsync` returns without a `CopyIntent` unless `state == SHADOW`. `CopyTradingService.GenerateShadowIntentsAsync` allow-lists `{SHADOW, LIVE_CANDIDATE, LIVE}` — `RISK_BLOCKED` is not copyable. SHADOW in this wave is **all demo**. Starwave is **deals-done scored 0**, so it is not in the scored-XAU set. `destinationRealPnl` is `0`. `REAL_COPY` is false. Hypothetical loss is **not** realized dest PnL.

This slot did **not** re-query `/api/traders` to re-count `RISK_BLOCKED` vs `SHADOW` on the 8463-row catalog. Dominance is taken as the assigned live measurement. The demo seed alone is **not** dominance (historically 1 `RISK_BLOCKED` / 2 `SHADOW` / leftover `INSUFFICIENT_DATA`). The live Achiever scored set is the relevant book; Starwave contributes **0** scores. Catalog size **8463** ≠ scored-XAU count.

Architecture §2398 already forbids treating correlated gold books as 50 independent edges: “Do not copy 50 different traders if they are effectively the same XAUUSD strategy.” Copy-all of a blocked-majority Achiever book is that failure mode at catalog scale.
