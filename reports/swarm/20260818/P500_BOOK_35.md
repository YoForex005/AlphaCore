## 3. Why a live book cannot run on this store

A live copy book is not “who looks good on this dashboard refresh.” It is:

| Requirement | InMemory today |
|---|---|
| Remember `RISK_BLOCKED` across restarts | **No** — 29 / −$241,580 vanish until rescoring finishes |
| Shared book between API (dashboard / resync) and a future send host | **No** — three isolated InMemory names |
| Idempotent ClOrdID / execution intent / reject memory | **No** — rows die with the process |
| Sync checkpoints so you do not double-copy a reopen | **No** |
| Outbox so a crash cannot lose “signal accepted → send” | Table exists; dispatcher does not; store is still RAM |
| Audit why a size was sent | `audit_logs` / score history vanish |
| Survive a recycle during a session | new empty store + possible duplicate send **if** a sender existed |

`CopyTradingHostedService` ticks every 20s and calls `GenerateShadowIntentsAsync`. After a wipe that method sees **zero** `TraderScores` in `{SHADOW, LIVE_CANDIDATE, LIVE}` and returns 0. That is fail-closed **only** on the hosted path. It is not a live book. It is an empty RAM set.

`CanPromoteToLive` is hard-`false`. `NewOrderSingleImplemented` is `false`. Persist path forces `AllowFixSend = false`:

```211:211:D:\Prop\src\Infrastructure\Copy\CopyTradingService.cs
                    AllowFixSend = false,
```

Those keep capital safe **today** only if the env flag stays unarmed **and** the sender stays absent. They are **not** a license to arm send on InMemory later.

`REAL_COPY_EXECUTION_ENABLED` is **env-read** in DI L41. This slot **did not** flip it. Synthesis addendum already recorded the process bit can be `true` while `NewOrderSingleImplemented=false`. Armed ≠ fill. Armed **on RAM** is a **loss path** the moment a sender lands.

### 3.1 The post-restart window is how you copy the tail by accident

`LiveIngestHostedService` order is **catalog → deals → score**:

1. `SyncCatalogAsync` upserts **all** groups/accounts (8460–8463).
2. `SyncBrokerAsync` inserts deals (synthesis: Achiever **260352**, Starwave **91966**).
3. Scoring walks `ListLoginsWithDealsAsync` one login at a time (synthesis: Achiever scoring through 225+, **Starwave scored = 0**).

If anyone ever copies from the **catalog** (all `Mt5Accounts`, no state gate) during that window, they copy **everyone**, including the 29 names that will later score `RISK_BLOCKED`, plus thousands of `INSUFFICIENT_DATA` challenge logins. That is copy-all **8463**.

Starwave scored **0** on the synthesis pin. Copy-all would spray an **unscored** broker onto dest. That is not an edge.
