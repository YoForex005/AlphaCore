## 4. REMOVE / FLATTEN implication (after the auto-add)

Once `ADMITTED`, later failure is **not** a silent hopper drop (that was the pre-`TickRosterAsync` hole documented in stale P503_R_*).

`Decide` **RemoveAndFlatten** when:

1. State `RISK_BLOCKED` / `DISQUALIFIED` / `PAUSED` → `STATE_*`
2. Martingale / averaging / lot-escalation → `SIZE_PATTERN`
3. `demo\` / `contest\` → `DEMO_OR_CONTEST_GROUP` (even if never admitted)
4. `alreadyOnRoster &&` reconstructed XAU net `<= 0` → `XAU_BOOK_TURNED_NEGATIVE`
5. `alreadyOnRoster &&` ≥3 consecutive closed XAU losses → `CONSECUTIVE_LOSSES_*`
6. `alreadyOnRoster &&` drawdown/peak ≥ 0.40 → `DRAWDOWN_FROM_PEAK`
7. Else no longer eligible → `NO_LONGER_ELIGIBLE_*`

`TickRosterAsync` then:

- writes `Status = "REMOVED:" + reason` (or inserts that row);
- if `FlattenDestination` (always true on `Remove(...)`) calls `FlattenOpenCopiesAsync`.

Flatten writer: dest-side `CloseExposure` intents, `Status=FLATTEN_LOSS_CUT`, idempotency `copy:{broker}:{login}:{pos}:close`, only for existing `copy:` **OpenExposure** rows. Comment on the engine: *“Flatten is destination-only. Never touches the MT5 source book.”*

It is **not**:

- a live Pepperstone flatten (`35=D` still absent);
- a mark-to-market of unrealized dest (`ShouldFlattenOpenCopy(-151)` exists; **0 product callers**);
- a delete of `shadow:` demo-seed keys (`PersistDemoShadowAsync` uses `shadow:{broker}:{login}:{pos}`, which flatten does not scan).

`XauUsdOneToOneCopyPolicy` itself still has **no** REMOVE/FLATTEN. After admit, `XauNetPnl<=0` is only `XAU_BOOK_NOT_PROFITABLE`. The **engine + tick** are what REMOVE/FLATTEN. Policy + hopper still `continue` the trader for **new** opens once the roster row is no longer `ADMITTED`.
