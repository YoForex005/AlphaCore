## 4. ADMIT implication (this slot)

When the trigger fires (ex-WATCH, now SHADOW, N≥20, XAU net > 0, clean, real group, `alreadyOnRoster=false`):

1. `Action = Admit`, `Reason = AUTO_ADMIT`.
2. `FlattenDestination = false` — **do not close dest** just because a winner was added.
3. `AllowNewOpens = true`.
4. Persist hack: a long-lived `CopyIntent` (`ExpiresAt = now+20y`, `Action=OpenExposure`, qty 0) with `Status=ADMITTED`. There is **no** `CopyRoster` table.
5. Next intent pass may mint `SHADOW_ONLY` opens for **still-open** source XAU (lookahead closed winners still rejected).
6. `RiskEngine` still runs; persist forces `AllowFixSend=false`. LIVE send stays unimplemented.
7. Delay: up to one scoring rebuild + **~20 s** roster poll. Not millisecond.

**ADMIT does not mean:** dest size, Pepperstone fill, LIVE state, or profit.

Demo / contest SHADOW (the measured Achiever `demo\yo-2step` book) hits `Remove("DEMO_OR_CONTEST_GROUP")` **before** the eligible Admit branch — including when `alreadyOnRoster=false`. Those names are **REMOVE**, not ADMIT. Auto-add is **not** “copy the current 70 SHADOW rows.”
