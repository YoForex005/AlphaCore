## 0. Verdict

**LOSS_CAPS_NOT_EDGE.** `RiskLimits.MaxDailyExecutionLoss = 2_000m` and `MaxLossPerTrader = 500m` bound how much dest can *already have lost* before `Evaluate` returns `GlobalStop` / `PauseTrader`. They do **not**:

- pick winners,
- change source expectancy,
- haircut dest spread/commission,
- exclude `RISK_BLOCKED`,
- or turn a net-negative XAU book into a profitable cTrader book.

If those latches were live and honestly wired, the dest still **donates up to $2,000/day** (and **$500 per copied login**) of the same −EV process, then stops *new* tickets — and the current predicates also **freeze exits** (worse than a proper kill switch).

**Today dest capital is unharmed** (`SAFE_BY_ABSENCE`): no `35=D`, `NewOrderSingleImplemented=false`, `VenueReconciled=false`, `AllowFixSend` persisted `false`, `destinationRealPnl` constructor literal **0**. The product copy path also **zeros** `DailyExecutionPnl` on every intent, so the $2,000 latch **never even sees a dest day**.

## 4. Why a $2,000 / $500 latch is not an edge (math)

### 4.1 Edge vs stop

An **edge** is positive dest expectancy **after** venue costs, **before** the first lot: filter + size + proven shadow tape.

A **loss cap** is: “keep running the same process until the account is down $X, then stop new.” Expected dest PnL of a −EV copier with a stop at −$2,000 is **about −$2,000**, not +EV. The stop changes the **left tail of the dest equity path**. It does not change the **sign**.

```text
E[dest | copy-all, daily latch $2000]  ≈  −min($2000, |copy-all EV|)
                                        <  0
E[dest | copy RISK_BLOCKED]            ≈  −$241,580 × dest_scale  (uncapped)
                                        or −$2000/day until the latch
Neither is a profit path.
```

Wanting “higher profit and lower loss” does not move that expectation. It is not a feature flag.

### 4.2 $2,000 is a blow-up ceiling vs approved size

Lot law in this lab: **1.00 lot XAU = 100 oz**. `MaxPositionQuantity = 5` is **APPROVED** (strict `>`).

| Ticket the engine will approve | Physical | $4 / oz routine gold swing | vs daily latch |
|---|---:|---:|---|
| 1 × **5.00** lots | 500 oz | **$2,000** | **equals** `MaxDailyExecutionLoss` |
| Net **10** lots (`MaxXauNet`) | 1,000 oz | **$4,000** | **2×** the daily latch |
| 70 SHADOW names × 0.10 dest (0.05 × 2.00 source, login 303310 class) | 700 oz | **$2,800** | **already through** $2,000 |

So the “kill switch” and the **working size catalog disagree**. One legal 5-lot gold print can spend the entire daily latch on a **$4** ounce move. That is not a trading edge. It is a **ruin ceiling** (P500_S055). Synthesis Stage D already says the working dest daily stop should be **$200–500**, not $2,000, and dest working size **0.05 lot**, not 5.00.

### 4.3 $500 per trader × 8,463 logins is not a book

If someone treated `MaxLossPerTrader` as “safe to copy everyone”:

| Naive reading | Dollar |
|---|---:|
| 8,463 × $500 | **$4,231,500** theoretical dest bleed before every name is paused |
| Daily latch first | **$2,000** stops **new** opens first (if wired) |
| 29 `RISK_BLOCKED` × $500 | **$14,500** dest if each blocked name is allowed to hit the per-trader floor |
| Scored-XAU copy-all uncosted | Source **−$154,425** (dest worse after spread) |

The daily latch is the only number that would matter, and it is **unwired** (`DailyExecutionPnl = 0`). Even if wired, **losing $2,000 then stopping** is still a loss. It is not “the system found an edge.”
