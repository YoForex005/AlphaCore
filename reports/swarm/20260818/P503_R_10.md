## 1. Assigned file: `XauUsdOneToOneCopyPolicy` has no remove/flatten

Class law (L57–61) is trader **selection** then 1:1 next-event copy. It does not mention roster, remove, or flatten:

> Live copy selects **traders** with a measured XAUUSD edge, then copies their next XAUUSD events 1:1 (lots, SL/TP, side). It does not wait until a ticket is profitable — that is lookahead and cannot be traded live. Close is copied when the source closes, not at a predicted time.

Grep of this file: **0** hits for `Remove`, `Flatten`, `Roster`, `Admit`, `alreadyOnRoster`, `XAU_BOOK_TURNED_NEGATIVE`.

The only PnL gate is **eligibility**:

```99:103:D:\Prop\src\Domain\Copy\XauUsdOneToOneCopyPolicy.cs
        if (trader.XauNetPnl <= 0)
        {
            reason = "XAU_BOOK_NOT_PROFITABLE";
            return false;
        }
```

That is an **ADMIT / stay-eligible** predicate. Zero is treated as not profitable (`<= 0`). It does not emit a dest-close instruction. It does not change trader state. It does not write a roster row.

`Evaluate` re-runs that predicate on **every** signal, including `CloseExposure`:

```117:120:D:\Prop\src\Domain\Copy\XauUsdOneToOneCopyPolicy.cs
    public CopyInstruction Evaluate(CopyTraderSnapshot trader, CopySignal signal)
    {
        if (!IsTraderEligible(trader, out var traderReason))
            return Reject(traderReason);
```

So after admit, if the caller rebuilds `CopyTraderSnapshot.XauNetPnl` from completed XAU and that sum is now ≤ 0:

1. `IsTraderEligible` = false.
2. `Evaluate` returns `Accept=false`, `Reason=XAU_BOOK_NOT_PROFITABLE`.
3. **No** `CopyIntentAction.CloseExposure` is minted by this reject.
4. **No** flatten of dest inventory.

That is the opposite of auto-remove: dest closes are **blocked** by the same ADMIT gate that blocked new opens.

## 5. ADMIT vs after-admit (policy only)

| Moment | Policy behavior |
|---|---|
| First time `IsTraderEligible` = true (`XauNetPnl > 0`, N≥20, not demo, not size-pattern, state not blocked) | Eligible to copy next **open** XAU event. This is **ADMIT** in spirit. The policy does not persist a roster flag. |
| Later snapshot `XauNetPnl <= 0` | **Not REMOVE.** Eligibility false. `Evaluate` reject. Caller `continue`. Dest **not** flattened. Source MT5 **not** touched (correct — dest-only law lives on the unused engine). |
| Later snapshot still green | `Evaluate` may accept 1:1 open/close. `AllocationFactor=1m`. |

There is **no** hysteresis: the same `<= 0` gate that blocked first admit also blocks after-admit. There is **no** “once admitted, stay until flatten” path in the assigned file.

## 6. Honesty / residual holes

1. **Policy ADMIT and roster ADMIT are not the same object.** Policy has no `RosterAction.Admit`. Roster `AUTO_ADMIT` is dead code.
2. **Close freeze after red book.** Eligibility-first `Evaluate` means dest cannot be reduced via this policy once the source XAU book is ≤ 0. That is worse than REMOVE+FLATTEN if send were armed.
3. **Unrealized dest PnL is invisible** to the policy. Only completed source XAU net is inspected. An open dest loser with a still-green source book stays copyable.
4. **Zero PnL** (`== 0`) is ineligible — same as negative. Untested as a distinct case.
5. No `35=D`. Flatten implication is **latent**. Dest PnL today is **$0** by absence.
