## Profit implication

**You cannot rank or size copy for Pepperstone profitability from the current “Shadow P&L” or dest P&L tiles.**

- Dest real P&L **0** is an unwired constant, not a flat live book. There is no dest fill / dest position rollup (`destination_positions` / `shadow_performance` tables are spec-only).
- Overview shadow is **Σ source-vs-shadow entry slippage** against whatever `destination_quotes` row exists. That row is the **demo seed 2399.45 / 2399.85** (or empty → no shadow fills). It is **not** a live cTrader QUOTE snapshot. Against a ~2400 seed, any live XAU print near 3300–3500 (2026) makes the “slippage” a **fantasy gap**, not dest cost.
- Architecture §24 required `shadow_pnl` **and** `source_vs_shadow_slippage` as separate persisted facts. Product aliases the second as the first. `SimulateExit` never runs, so there is **no** dest-touch round-trip P&L.
- Achiever is scored on **source** reconstructed MT5 PnL. Starwave deals-done scored **0** → no live Starwave shadow sample. SHADOW is **all demo**.
- §3 target is **future execution-venue-net P&L**, not “who made the most on the source book.” Enabling copy later on this number would select traders by **source-book / demo-touch**, not by measured venue-net. That is **false expected profit**.
- §69 item 11 and Phase 5 are **not met**. FIX LoggedOn does not close that gate.

## Lower-loss implication

**Capital is not at risk from dest fills today.** That is absence, not a proven dest book.

- `destinationRealPnl` **0** + `REAL_COPY` **false** + copy-hop `NewOrderSingleImplemented=false` + persist `AllowFixSend=false` ⇒ Pepperstone cannot receive a copy `35=D` from this pipeline. This slot did not send and did not build NewOrderSingle.
- Architecture §41 **allows** QUOTE logon while real send stays off. Logon-up / dest-PnL-0 is **consistent with no dest positions**, not with a measured hedge.
- Loss-reduction from shadow is **unavailable**: you cannot reject a future live copy on dest drawdown, dest slippage, dest spread, or dest MTM because those series do not exist. The §23 gate “minimum shadow net P&L / maximum shadow DD” cannot fire on real venue data.
- Decision risk (not capital risk): an operator who reads “Dest. real P&L 0.00” + QUOTE/TRADE healthy + 8463 accounts may believe the dest book is live-flat and shadow is venue-priced. Both beliefs are **false**. That is how a later `REAL_COPY=true` plus a new sender would lose money **without** a dest-quote sample.
- Honest dest-real **0** while live send is off is **safer** than copying source MT5 P&L into `destinationRealPnl`. Do not “fix” the tile by aliasing `shadowPnl` or source net.

Keep `REAL_COPY_EXECUTION_ENABLED=false`. Do not add NewOrderSingle until Phase 4 persists a live XAU book, Phase 5 marks shadow on that book (entry **and** exit), and `DestinationRealPnl` is a dest-fill rollup (honest 0 only when dest positions are actually empty).
