## What the file actually is

Four types, no I/O:

1. `FeatureSnapshot` — completed-XAU counts, net/gross PnL, profit factor, lot/loss CVs, martingale / averaging-down / lot-escalation flags, hold seconds, SL use rate, max drawdown, trade frequency, unused MAE/MFE placeholders (`FeatureQuality.Unavailable`, `PriceSource.Unknown`).
2. `BaselineScore` — features + risk/behavior/early-quality + `SuggestedState` + `EarlyScoreEligible`.
3. `BaselineScorer` — `ComputeFeatures`, `Score`, `CoefficientOfVariation`.
4. `TraderStateMachine` — maps scores to `{INSUFFICIENT_DATA, RISK_BLOCKED, WATCH, EARLY_SCORE, SHADOW}` only.

`Score()` path:

1. Features from completed XAUUSD reconstructed trades (`t.Completed && t.IsXauUsd`).
2. `EarlyScoreEligible` iff `CompletedXauTrades >= EarlyScoreTradeCount` (const 3).
3. Risk 0–100 from martingale (+35), averaging-down (+20), lot-escalation (+15), lot CV > 0.5 (+10), SL use < 0.3 (+10), max DD > gross profit (+10).
4. Behavior starts at 100 and subtracts the same family of flags.
5. Quality blends net PnL, profit factor, behavior, and risk; capped at 40 when ineligible; clamped 0–100.
6. State = `TraderStateMachine.FromBaseline(...)`.
7. Return a record. Stop.

No side effects. No broker. No FIX.

    public static TraderState FromBaseline(bool earlyEligible, decimal quality, decimal risk, FeatureSnapshot features)
    {
        if (features.CompletedXauTrades == 0)
            return TraderState.INSUFFICIENT_DATA;

        if (risk >= 80 || (features.Martingale && features.MaxDrawdown > 0 && features.NetPnl < 0))
            return TraderState.RISK_BLOCKED;

        if (!earlyEligible)
            return TraderState.INSUFFICIENT_DATA;

        if (quality >= 70 && risk < 40)
            return TraderState.SHADOW;

        if (quality >= 55)
            return TraderState.WATCH;

        return TraderState.EARLY_SCORE;
    }

## Profit implication

Scoring 8463 accounts (Achiever included; Starwave at 0 completed XAU) can only change leaderboard / `TraderScore` / demo shadow rows. A high Achiever score (`quality >= 70 && risk < 40`) is the *best* outcome this file can produce, and that outcome is still `SHADOW`, not a live ticket.

## Lower-loss implication

**Capital-protective by non-participation, not by measured edge.** Lower-loss on Pepperstone is preserved because this file cannot open a losing destination trade:

- live promotion is unconditionally false
- `LIVE` / `LIVE_CANDIDATE` are unreachable from `FromBaseline` / `AfterHighEarlyScore`
- empty / Starwave-0 books stay `INSUFFICIENT_DATA`
- martingale + drawdown + negative net → `RISK_BLOCKED` (still no send)
- production consumer writes demo shadow only

This does **not** reduce losses on trades that were never sent. It is a vacuous lock (live branch never written), not a tested refuse-path on a live socket. It also does not prevent some *other* file from sending if `REAL_COPY` were armed later — that path is not in `BaselineScorer.cs`.

Loss reduction vs live copy remains “do not send,” not “size down.”
