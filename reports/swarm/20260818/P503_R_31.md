| Word | What happens when a previously **ADMITTED** name later becomes `RISK_BLOCKED` |
|---|---|
| **ADMIT** | `RISK_BLOCKED` is **never** admitted. `CopyRosterEngine.Decide` returns `Remove("STATE_RISK_BLOCKED")` **before** the eligibility/Admit branch. Policy `IsTraderEligible` also returns `TRADER_BLOCKED_RISK_BLOCKED`. Hopper `GenerateShadowIntentsAsync` excludes the state and requires roster `Status == "ADMITTED"`. |
| **REMOVE** | **Yes.** Hosted 20 s tick calls `TickRosterAsync` on **all** `TraderScores` (not just copyable). `onRoster` is the `roster:{broker}:{login}` row with `Status == "ADMITTED"`. Later `RISK_BLOCKED` → `RosterAction.RemoveAndFlatten` → that row becomes `REMOVED:STATE_RISK_BLOCKED` and `Action = CloseExposure`. New opens stop. |
| **FLATTEN** | **Intent-layer dest flatten, not venue dest flatten.** `FlattenDestination=true` calls `FlattenOpenCopiesAsync`, which inserts a `CopyIntentAction.CloseExposure` with `Status = "FLATTEN_LOSS_CUT"` for each prior `copy:…:open`. No `RiskEngine.Evaluate`, no `ExecutionIntent`, no `35=D`, no dest position table, no `ShadowOrder` close. Hosted log: *“Dest flatten is SHADOW/intent only; NewOrderSingle still unimplemented.”* Never flattens MT5 source. |
