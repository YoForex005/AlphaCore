### 1.1 Two connections, two ports — trading cannot ride QUOTE

Quoted from https://help.ctrader.com/fix/getting-credentials/ (this fetch):

> “In our case we create two clients, since price quotation messages and trade messages are handled by different ports on the server.”

### 1.3 Official session vs application vs fill

Quoted from https://help.ctrader.com/fix/specification/ — Logon (this fetch):

> “A Logon message is sent from the client side application to begin a cTrader FIX session, and a response is sent by cTrader to the client side application. Once the logon is complete, quote and trade flows can proceed for the lifecycle of the session.”

> “If an invalid Logon message is received by cTrader (with invalid fields), cTrader sends a Logout message in response.”

Communication-model (this fetch) classifies Logon as a **system (admin)** message: “client authentication message.” New order single is an **application** message: “used to electronically submit the orders to a broker for execution.” Execution report is the fill/status path: “confirmations, fills and unsolicited changes.”

“Can proceed” is not “have proceeded.” Official fill pair after a TRADE-session market `35=D` is Execution Report `150=0` / `39=0` (New) then `150=F` / `39=2` (Trade / Filled), with `AvgPx` / `CumQty` / `LastQty`. A lone inbound `35=A` has **none** of those tags.

RoE application catalog (same spec page, this fetch):

| Message | MsgType | Official role vs fill |
|---|---|---|
| Logon | `A` | Begin session. Auth. |
| Market Data Request | `V` | QUOTE subscribe. Not a fill. |
| Market Data Snapshot | `W` | Bid/offer print. Not a fill. |
| New Order Single | `D` | Submit order on **TRADE**. Still not a fill. |
| Execution Report | `8` | `150=F` / `39=2` is the fill. |
| Request for Positions | `AN` | Inventory. Not a fill. |

Official RoE market-order example (same spec page, this fetch) is explicit about the **two-step fill** after `35=D`:

```text
Request:  35=D  ... 40=1 38=10000
Response: 35=8  150=0 39=0   (New / accepted)
Response: 35=8  150=F 39=2 6=1.0674 14=10000 32=10000  (Trade / Filled)
```

RoE also: trading ops cannot be sent on the price connection. Opening `:5211` and seeing `35=A` cannot produce a dest fill even if someone later added a `35=D` builder on that socket.

Failed Logon is `35=5` (Logout) with `58=InternalError: …` — still not a fill.
