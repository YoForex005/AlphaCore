## Angle

Are the martingale and averaging **filters** in (or produced by) `TradeReconstructor` strong enough to **cut the left tail** of XAU books — same-position double-down, hedge-mode grids, recovered baskets that look like winners until they blow — given live census 8463 accounts, Achiever scoring, Starwave deals-done scored 0, SHADOW-all-demo, dest real P&L 0, FIX LoggedOn, `REAL_COPY` false?

“Filter” means a gate that **removes** that book from first-three, scoring input, dest size, or copy. A boolean that still flows downstream is **detection**, not a cut.

The left tail that matters on gold prop books is not the already-busted loser (easy to see). It is the **recovered grid**: many small winners from adding at worse prices, then one unbounded add sequence.

---

## Verdict

**FAIL — no. The filters are not strong enough to cut the left tail, because this file does not implement filters.**

Three independent holes, all visible after a full read of this file plus the two consumers that would have to do the cutting:

1. **No martingale at reconstruction.** Intra-position doubling (`0.01 → 0.02 → 0.04` on one `PositionId`) is one lifecycle. `MaxVolumeLots` grows. There is no `WasMartingale`, no add-count, no `Max/Initial` ratio. `BaselineScorer` only compares **adjacent completed trades**. A recovered basket is one row. The scorer never sees a size-up-after-loss pair.

2. **Averaging is a latch, not a reject.** `ScaleIn` sets `WasAveragedDown` when a same-side fill is strictly worse than pre-fill VWAP (long `price < EntryVwap`, short `price > EntryVwap`). The trade still completes, still counts toward first-three, still is XAU-eligible. `CompletedXauUsdTrades` does **not** mention the flag. Magnitude is discarded: a 1-tick worse 0.01 add equals a 10-level dump.

3. **Hedge-mode grids never set the flag.** Reconstruction is `GroupBy(PositionId)`. A21 F09-style hedge (each add is a new ticket / new position) emits N independent trades, each `WasAveragedDown=false`. That is the common retail XAU left tail on Achiever-style books. This class cannot see it as averaging.

Downstream does not rescue the file:

- `BaselineScorer`: `AveragingDown = trades.Any(t => t.WasAveragedDown)` → **+20 risk, −15 behavior**. `Martingale` = prior `Net < 0` **and** next `MaxVolumeLots > 1.25×`. `RISK_BLOCKED` only if `risk >= 80` **or** `(Martingale ∧ MaxDrawdown > 0 ∧ NetPnl < 0)`. Averaging-only winning book: `risk=20`, `behavior=85`, quality can exceed **70** with `risk < 40` → **`SHADOW`**. Winning martingale-only: `risk=35` → also **`SHADOW`** (C32 measured 70.25–85.25).
- `WasScaledIn` is **never read** by the scorer.
- `RiskEngine` blocks increasing actions only if the caller sets `MartingaleFlag`. `RiskEvaluationRequest` has **no** averaging field.
- `CopyTradingService` sizes dest from `trade.MaxVolumeLots` (the **basket** after adds) and passes `MartingaleFlag = score.Martingale` (inter-trade only). Averaging is invisible to dest risk.

Live census does **not** make the filters adequate:

- 8463 source accounts can still run grids on the challenge side. This class reconstructs them as valid completed XAU.
- Achiever scoring can consume those reconstructions. Starwave **deals-done scored 0** means that broker’s left tail is **unscored**, therefore unfiltered by the scorer.
- SHADOW all demo + `destinationRealPnl` **0** + `REAL_COPY` **false** means dest left tail is cut by **not copying**, not by anything in `TradeReconstructor`.
- FIX **LoggedOn** is session state. Logon without a reconstruction reject is not a left-tail cut.

Do **not** claim averaging detection is a left-tail filter. Do **not** claim martingale is handled here. Do **not** treat dest PnL 0 as proof the flags work.

## Left-tail holes (this file)

| Pattern | What this class does | Does it cut the tail? |
|---|---|---|
| Same-position 2×/4×/8× then close green | One completed trade; `WasAveragedDown=true` if adds were worse; `MaxVolumeLots` = peak remaining | **No.** Counts as one winner for first-three. Scorer sees no martingale pair. |
| Hedge-mode grid (new `PositionId` per add) | N independent trades, flags false | **No.** Invisible as averaging. |
| Same-price / limit-grid adds (`price == VWAP`) | `WasScaledIn=true`, `WasAveragedDown` stays false | **No.** |
| 1-tick worse micro-add vs 10-level dump | Same boolean | **No magnitude.** |
| Partial close then re-add | `MaxVolumeLots` is peak remaining, not Σ adds | **Understates** risk. |
| Open, still-running grid | `Completed=false`; dropped from `CompletedXauUsdTrades` | **Blind** to the live tail. |
| Same-order partial fills (A21 F10) | `WasScaledIn=true` (possible false-positive scale) | Noise, not a cut. |
| `ApplyReverse` leftover | Fresh `OpenTrade`, flags reset | **Loses** history. |
| `WasScaledIn` (pyramid or grid) | Emitted | **Unused** by scorer. |
| Cancel on a ticket | `EligibleForFirstThree=false` | Dirt cut, not a behavior cut. |

Algebra on a **winning recovered grid** at N=3 (one averaged lifecycle + two clean winners, SL present, PF≥1.8): `risk=20`, `behavior=85`, `quality = 50+15+10+5 + 17 − 5 = 92` → **`SHADOW`**. That is the left-tail shape: pretty recovered books rank high until the next add sequence.

Algebra on **intra-position 8× martingale** closed green as one trade: `Martingale=false`, `AveragingDown=true` if worse fills, same `risk=20` path.

Algebra to actually hit `RISK_BLOCKED` via the additive stack: need `35+20+15+10+10` (martingale + avg + escalation + lot CV + no-SL) or the losing-martingale clause. A clean-looking recovered grid does not get there.

**These flags do not create destination profit and do not protect a profit process.**
