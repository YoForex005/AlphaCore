- martingale / averaging / lot-escalation
- `demo\` / `contest\` group
- completed XAU book `net <= 0` (already on roster)
- consecutive-loss streak ≥ 3
- drawdown-from-peak ≥ 40 %
- `XauUsdOneToOneCopyPolicy.IsTraderEligible` (20 completed XAU, `XauNetPnl > 0`, …)

`GenerateShadowIntentsAsync` only considers scores in `{SHADOW, LIVE_CANDIDATE, LIVE}` **and** roster row `Status == "ADMITTED"`. ## 3. ADMIT / REMOVE / FLATTEN map (this slot)

```text
20 s poll
  TickRosterAsync
    CopyRosterEngine.Decide          ← ADMIT / KEEP / RemoveAndFlatten
      MaxLossPerTrader?  NO
    Admit  → CopyIntent Status=ADMITTED
    Remove → Status=REMOVED:<reason>
             FlattenOpenCopiesAsync → CloseExposure Status=FLATTEN_LOSS_CUT
               RiskEngine.Evaluate?  NO
  GenerateShadowIntentsAsync
    skip unless roster ADMITTED
    OPEN new ticket → RiskEngine.Evaluate
      MaxLossPerTrader?  YES in source, UNREACHABLE (recon short-circuit)
      TraderRealizedLoss = min(0, this source ticket)  ← not per-trader book
    CLOSE / FLATTEN intents → Evaluate?  NO
```

| Verb | Owner today | `MaxLossPerTrader` role |
|---|---|---|
| **ADMIT** | `CopyRosterEngine` + eligibility (20 XAU, book > 0, not demo, not size-pattern) | **None.** `$500` cannot admit or refuse a login. |
| **REMOVE** | `Decide` → `RemoveAndFlatten` (`STATE_*`, `SIZE_PATTERN`, `DEMO_OR_CONTEST_GROUP`, `XAU_BOOK_TURNED_NEGATIVE`, `CONSECUTIVE_LOSSES_*`, `DRAWDOWN_FROM_PEAK`, `NO_LONGER_ELIGIBLE_*`) | **None.** `PauseTrader` does not write `REMOVED:…` and does not change `TraderScores.CurrentState`. |
| **FLATTEN** | `FlattenOpenCopiesAsync` (intent-only; no NOS) | **None today.** **If** those `CloseExposure` rows later go through `Evaluate` as written, `$500` **rejects the flatten** (G21 violation / trapped dest). |

§40 `KillSwitchMode.EmergencyFlatten` is a **different** bit: it only blocks **new** exposure (`IsIncreasing`) and **does not emit** dest flatten orders. Dollar caps never write the `KillSwitch` row.

## 4. What would have to be true for “yes, per copied trader on each tick”

None of these exist in HEAD:

1. A dest (or at least **trader-lifetime**) realized+unrealized accumulator keyed by `(BrokerId, SourceLogin)`.
2. That accumulator passed as `TraderRealizedLoss` (not `min(0, this ticket)`).
3. A price-tick or dest-MTM loop that re-calls `Evaluate` (or a dedicated stop) **without** waiting for a new OPEN idempotency miss.
4. `PauseTrader` persisting a roster **REMOVE** (and **not** freezing CLOSE).
5. Flatten remaining dest via a path that `Approve`s reduce/close (G21), never `Reject`s them.

Until those five are measured, the sentence “`MaxLossPerTrader` is applied per copied trader on each tick” is **false**.
