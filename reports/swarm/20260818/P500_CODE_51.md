## Verdict

**YES — live copy-all of a `RISK_BLOCKED`-dominated scored book is expected to lose money.**

Reasons, in order:

1. **`RISK_BLOCKED` is a loser-shape, not a rank.** `FromBaseline`: `risk >= 80` **or** `(Martingale ∧ MaxDrawdown > 0 ∧ NetPnl < 0)` → `RISK_BLOCKED`. The unit fixture is three doubling losers (`0.10 → 0.20 → 0.40` lots, −100/−200/−400). Copying that class copies the **losing side** of size-up-after-loss onto one dest gold book.
2. **`risk.md` never excludes those names.** “Every trade request is evaluated against all limits **before** submission.” Limits are % DD, lot/position/trade counts, slip — not `CurrentState`. A dominated book fills the 100-trade daily circuit breaker **FIFO with blocked-quality names**, not SHADOW.
3. **The documented stop is a designed loss budget, not a quality gate.** Daily-loss kill = **5%** from day-start equity, **positions stay open**. Total-loss flatten = **10%** from initial balance, then market-close everything. Copy-all of a martingale-majority XAU book **eats the first 5–10% by design**, then either sits in open losers (kill) or crystallizes them at the worst print (flatten).
4. **Caps in this file are a wide pipe.** 50 lots / 25 positions / 100 trades/day is enough gold to realize that 5–10% before the breaker. Code `RiskLimits` (5 lots / 20 pos / $500 per-trader / $2_000 daily / $3_000 portfolio / `BlockMartingale`) is tighter — and **not** what this doc specifies. Following `risk.md` as written lets **more** of a blocked book through than the engine stub.
5. **Timing + slip make copy-all worse, not better.** 100–2000 ms delay on gold martingale adds = late fill. 30-point slip tolerance is large. Stale >2000 ms is “logged but not executed” — a latency reject, not a `RISK_BLOCKED` skip. The first 2 s of a size-up still go through.
6. **Product does not implement copy-all today.** `CopyTradingService` copyable set is `{SHADOW, LIVE_CANDIDATE, LIVE}` only — **not** `RISK_BLOCKED`. `PersistDemoShadowAsync` returns without an intent unless `state == SHADOW`. `CanPromoteToLive => false`. `NewOrderSingleImplemented = false`. Persist records `AllowFixSend = false`. `VenueReconciled` is a const **false**. `destinationRealPnl` is a constructor literal **0**.
7. **Live dest is not losing.** Orchestrator pin: `REAL_COPY` false, SHADOW all demo, dest real PnL 0, Starwave scored 0. FIX LoggedOn ≠ fill. This markdown cannot send `35=D`.

**Not an empty PASS.** The assigned file was read. It does **not** answer “don’t copy `RISK_BLOCKED`.”

- Trades outside the window are logged but not executed
```

## Position Sizing Normalization

MT5 and cTrader use different volume conventions. The risk engine normalizes before comparison:

- MT5: volume in hundredths of lots (50000 = 5.0 lots)
- cTrader: volume in units specific to the symbol contract
- All internal calculations use standard lots as the canonical unit
- `MT5_VOLUME_SCALE=10000` converts MT5 native → lots
```

“Hundredths” and `50000 = 5.0` / scale `10000` cannot both be true (hundredths of 50000 would be **500** lots). Blind copy-all with the wrong scale would **size** the martingale book wrong — a second loss channel.
