## Angle (answered)

**Q:** Are martingale and averaging filters strong enough to cut the left tail?

**A:** **No.** They detect a thin slice of the process and then **score/copy through it**.

### 1. Intra-position martingale is the left tail — and this file fuses it

Classic XAU blowup is **one ticket**: 0.10 → 0.20 → 0.40 → 0.80 into a loser, then one OUT. `ScaleIn` raises `RemainingLots` / `MaxVolumeLots` and maybe sets `WasAveragedDown`. The book emits **one** `ReconstructedTradeResult`. `BaselineScorer` martingale is **adjacent completed trades**, not `Max / Initial` on the same lifecycle. A lone averaged nuke is **not** `Martingale`. Risk from the bit is **+20**, not a block.

Open grids (`Completed = false`) are excluded from scoring until **after** the source left tail has already printed.

### 2. Averaging is a bit, not a severity

No `avg_down_n`, no add-count, no worse-fill distance, no volume on the worse add. A21 stores the bit; A22 wants `avg_down_n / N` and marks `FLAG_AVERAGING_DOWN` **severe** at `N <= 3` with a single averaged lifecycle. Product: `trades.Any(t => t.WasAveragedDown)` then `risk += 20`. Cap to `RISK_BLOCKED` is 80. Averaging alone cannot get there.

### 3. Winning process is promoted, not cut

A22 / `docs/scoring.md` want martingale / large size-up-after-loss → `RISK_BLOCKED`. Implemented block is **losing** martingale only (`NetPnl < 0`) or a stacked `risk >= 80`. Algebra (C32, re-checked against current `Score`):

- Averaging-only, net > 0, PF ≥ 1.8, SL used: `risk = 20`, `behavior = 85`, `quality ≈ 92` → **`SHADOW`** (`quality >= 70 && risk < 40`).
- Mild sequential martingale 1.26–1.49× after a loss, then recover: `risk = 35` → **`SHADOW`**.
- One fat averaged loser after two small winners: sequential martingale **false** (prior PnL > 0); escalation may fire; still often **not** `RISK_BLOCKED`.

Those are exactly the names whose **next** add is the dest left tail.

### 4. Copy path ignores averaging

`CopyTradingService` sets `MartingaleFlag = score.Martingale` and `AbnormalSizing = score.LotEscalation`. `WasAveragedDown` / `AveragingDown` never reach `RiskEngine`. A SHADOW averaged book can `APPROVE` an `OpenExposure` (and would `AllowFixSend` only if real-copy + reconciled + healthy — all false this wave).

### 5. Detection holes that miss the tail

| Pattern | Reconstructor | Scorer / risk |
|---|---|---|
| Same-position 2×/4× add into MAE | One trade, bit maybe true | Not `Martingale` |
| Add at **equal** VWAP (grid level) | `WasAveragedDown` stays false | Invisible |
| Add in profit then give it back | `WasScaledIn` only | Scorer ignores `WasScaledIn` |
| 1.00–1.25× after a loss | N/A (not sequential here) | Strict `>` 1.25 — miss |
| Hedge / second `position_id` | Separate books, no net-risk | No portfolio martingale |
| Still-open averaging bomb | `completed: false` | Not in feature universe |
| INOUT money double-count (B11 C1) | Inflates net / PF | Can **hide** `Net < 0` block |

Unit lock is one fused long add-lower (`Scale_in_and_partial_close`) plus one **losing** 2×/2× sequential book. Winning martingale / averaging-only SHADOW / intra-position span are **unlocked**.
