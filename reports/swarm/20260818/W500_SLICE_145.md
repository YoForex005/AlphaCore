export function useTraders(filters: { broker?: string; state?: string }) {
  return useQuery({
    queryKey: ['traders', filters],
    queryFn: () => client.get('/api/traders', { params: filters }).then(r => r.data),

}

## No-loss implication

This page cannot lose capital.

1. **No native load.** A browser bundle cannot load `MT5APIManager64.dll`. TFM/RID mistakes that block MetaQuotes belong to `apps/api` / `apps/mt5-worker` on Windows x64, not to `apps/web`.
2. **Read-only GET.** `useTraders` polls `/api/traders`. There is no POST, no SignalR invoke, no FIX send, no dealer answer, no `OrderAdd` / `DealPerform` / `DealerBalance`.
3. **Display of scores, not execution.** Flags (MG/AVG/ESC) and `Net P&L` are rendered numbers. They do not size lots or arm copy.
4. **Fail-closed for the hypothesized DLL miss.** If the API *were* a portable `net8.0` host and MetaQuotes failed to load, ingest/connect would fail in the **server** process. This page would show loading / empty / HTTP error. Equity on Achiever / cTrader would not move because this UI never issues a trade.
5. **Independent of the (absent) TFM bug.** Current API **is** `net8.0-windows` + x64, so the slot-145 load-blocker story does not fire on the intended Windows API process either.

**Honest limit:** this slice does not prove a live Manager session, does not re-hash the DLL trio on disk, and does not claim `/api/traders` lists every ingested login (that is a dashboard-completeness issue, not a MetaQuotes-load / no-loss issue). It only proves this file is not a loader and has no live-send path.
