## Binding law (this angle)

Architecture v2 §7: `demo\Maxmaster` is not the only group. Startup/resync must dynamically enumerate **all groups accessible to the Manager login** (`Connect → enumerate groups → upsert → accounts → history`).

Architecture v2 §9 / A39: discovery is Manager API set A (`GroupRequestArray("*")`, then `GroupTotal` + `GroupNext`). Plan maps and hardcoded `demo\yo-*` / `contest\yo-*` / `real\standard` names are **not** the enumerator.

Phase 1 gate: empty or partial list is not “all groups discovered.”

## No-loss implication

This file does not emit FIX `NewOrderSingle`, Manager `OrderSend`, or any other destination send. Seeded FIX rows are `Disconnected` with `LastError` stating no live socket / NewOrderSingle off. The capital path is **indirect**: no-loss / RISK_BLOCKED / shadow / copy-eligibility can only see accounts that were ingested. A four-name Fake snapshot omits every other manager-visible group. Hidden source logins keep trading; their drawdown never reaches `BaselineScorer` or kill-switch. Dashboard `mt5_groups` after a `SeedAsync` looks like a complete book while the live manager set is larger.

On **current** api / mt5-worker / fix-worker boot this seeder is not invoked, so the live host no longer plants the Fake four-group universe by default. Residual capital risk is re-wire, a test or tool calling `SeedAsync` against a shared live DB (first-writer `Brokers.Any()` latch then blocks this file from retrying Manager discovery), or an operator treating the Fake four names as the Manager census.
