## 3. Later-`RISK_BLOCKED` sequence (measured code path)

Assume name was SHADOW, hop already wrote `copy:{broker}:{login}:{pos}:open` (SHADOW_ONLY). Scorer then writes `CurrentState = RISK_BLOCKED`.

| Tick / event | What happens | Dest flatten? |
|---|---|---|
| Next 20 s poll | Score not in `copyable[]`. Trader skipped before snapshot. | **No** |
| Same poll if row were still loaded | `IsTraderEligible` → `TRADER_BLOCKED_RISK_BLOCKED` → `continue` | **No** |
| Source later closes | Close loop never reached (or `Evaluate` rejects) | **No** — dest orphan |
| Prior open intent / shadow fill | No delete / cancel writer | **Stays** |
| Live dest book | No NOS sender | **Empty today** (`SAFE_BY_ABSENCE`) |

**ADMIT implication:** admission is sticky only as “last tick’s filter.” There is no roster row to revoke. A later `RISK_BLOCKED` is **not** an Admit reversal action; it is invisibility.

**REMOVE implication:** product REMOVE ≠ `RemoveAndFlatten`. It is “stop emitting new opens **and** stop copying source closes.” That is **worse** than dest flatten: it also kills the exit mirror.

**FLATTEN implication:** dest flatten is specified on a dead domain type. Product hop does not flatten dest when the trader is later `RISK_BLOCKED`.
