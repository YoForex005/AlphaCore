## 3. Ruling

**PASS.** `MT5APIManager.h` is the official Manager/Admin surface any Achiever hop must use. It:

1. Exposes HTTP as a first-class pre-connect setting (`PROXY_HTTP = 2`, `ProxySet` on manager **and** admin).
2. Returns `MTAPIRES` from `Connect`, with `MT_RET_AUTH_MANAGER_IPBLOCK` (1012) in-scope via `MT5APIConstants.h` — “IP address unallowed for manager.”
3. Does not auto-connect, does not embed Achiever host/login, does not skip proxy, does not invent a default hop.
4. Puts capital-mutating APIs (`DealerBalance`, `DealAdd`, `OrderAdd`, …) **after** auth. 1012 is fail-closed: no session, no mutator.

`ProxySet` being `void` and optional is vendor design, not a hole that can send size. A missed hop on this LAN is the measured **1012** path (R012: desktop egress ≠ allow-list). That is operational, not a silent trade.

## 4. No-loss implication

`MT_RET_AUTH_MANAGER_IPBLOCK` (1012) is an **authentication deny**. The broker rejects the Manager TCP identity **before** a session exists. No pump, no `DealRequest`, no `DealerAnswer`, no `DealerBalance`, no `DealAdd`, no `OrderAdd`, no `PositionDelete`. Equity cannot move on a connection that never authenticated.

Achiever HTTP proxy, in this header, is only `MTProxyInfo` + `ProxySet`. It changes the **source IP the server sees**. It does not place orders, size positions, confirm dealer requests, or credit balances. On a workstation whose public NAT is not `81.29.145.69`, omitting `PROXY_HTTP` is expected to yield 1012 (R012, both pump and no-pump). That failure is **no-loss**: live Achiever books stay untouched because there is no Manager session.

If proxy **is** applied and `Connect` returns `MT_RET_OK`, the mutators in this same header become reachable. That is a later-slot / live-wiring concern, **not** 1012. Slot 164 therefore has **no live capital-loss path on the proxy / 1012 contract**. A missed hop fails closed; it cannot silently trade.

**Honest limit:** this vendor file cannot *prove* a live Achiever session or that the HTTP hop is currently enabled on this desktop. It only proves the official API exists, that HTTP is a first-class `ProxySet` type, and that 1012 is fail-closed. Do not treat this PASS as “Achiever is connected.”
