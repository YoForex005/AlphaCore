## 2. What “on the roster” means (HEAD)

There is no `CopyRoster` table. Membership is a `CopyIntent` row:

| Field | Value |
|---|---|
| `IdempotencyKey` | `roster:{BrokerId}:{Login}` |
| On roster | `row != null && Status == "ADMITTED"` (`TickRosterAsync` L134–136) |
| Off roster | missing row, or `REMOVED:{reason}` |

`ExecuteDemoCopyAsync` and `GenerateShadowIntentsAsync` both treat **only** `ADMITTED` as a live seat. A `REMOVED:*` name cannot open a new dest copy on that tick.

## 5. Residuals (do not flip the FAIL-if-missing gate)

These are real defects. They are **not** “remove/flatten missing.”

### 5.1 Re-ADMIT oscillation (still-green losers return)

T4–T6 (`net≤0`, streak≥3, dd/peak≥0.40) are gated on `alreadyOnRoster`. After REMOVE, `onRoster` is false (`Status` is `REMOVED:*`, not `ADMITTED`). | Tick | `onRoster` | 20×+$50 then −$700 (net +300, dd 70%) |
|---|---|---|
| 1 (first seen) | false | **ADMIT** (DD check skipped) |
| 2 | true | **REMOVE** `DRAWDOWN_FROM_PEAK` + dest flatten intents |
| 3 | false | **ADMIT** again |
| 4 | true | **REMOVE** again |

Same shape for a still-green 3-loss streak. A **red** book (`net≤0`) cannot re-enter: policy `XAU_BOOK_NOT_PROFITABLE` + off-roster `Keep`/`NOT_YET_*` (no Admit). Blocked / size-pattern / real-group names also cannot re-enter because those `Remove`s fire **without** `alreadyOnRoster`.

**Residual, not FAIL-gate:** losers are not *left* `ADMITTED` after a remove tick; some still-green losers are *returned* on the next tick. Latch is missing. P503_R_17 / R_27 already named this.

### 5.2 First-seen AUTO_ADMIT of a 40%+ / 3-loss curve

One poll of dest opens is possible in the **same** hosted cycle: TickRoster writes ADMITTED, then `ExecuteDemoCopyAsync` copies open XAU for that seat.

### 5.3 Send hop does not flatten on REMOVE

`CopyLifecycle.ShouldCloseDest` requires **source completed**. `ExecuteDemoCopyAsync` L517–526 only closes ledger dest fills when the reconstructed source ticket is `Completed`. It never reads `FLATTEN_LOSS_CUT`.

So: roster REMOVE while source tickets are still open → dest lots (if any were sent on demo) **stay open** until the source closes. Paper flatten exists; dest-send flatten-on-eject is **not** wired. That is dest inventory risk **only** when `DemoDest` is true (HEAD now sends on the 20 s tick). Live `1369850` is excluded by `DemoDest`.
