public sealed class RiskEngine
{
    private readonly RiskLimits _limits;

    public RiskEngine(RiskLimits? limits = null)
    {
        _limits = limits ?? new RiskLimits();
    }

    public RiskDecision Evaluate(RiskEvaluationRequest request)
    {
        if (request.KillSwitch == KillSwitchMode.StopNewExecution && IsIncreasing(request.Action))
            return Reject(request, RiskDecisionOutcome.GlobalStop, "STOP_NEW_EXECUTION");

        if (request.KillSwitch == KillSwitchMode.EmergencyFlatten && IsIncreasing(request.Action))

## 4. No-loss implication

**None from this angle on the current Windows API host.** `RiskEngine` does not send FIX `NewOrderSingle`, does not call MT5 `DealerSend`, and does not `LoadLibrary`. It only returns `RiskDecision`. Rejects force `ApprovedQuantity = 0` and `AllowFixSend = false`. Approves still require `RealExecutionEnabled` (DI hard-sets `LiveRuntimeStatus.RealCopyEnabled = false` and comments that live NOS is not implemented).

Because the API **is** `net8.0-windows` x64 and the MetaQuotes trio **is** next to `TraderIntelligence.Api.exe`, the hypothesized “DLL cannot load because API TFM is wrong” blocker is **not** present on the intended Windows process. Load can still fail for other reasons (wrong OS, leftover `net8.0` exe, Linux compose, missing passwords), but those are not “API TFM is not net8.0-windows x64,” and they are not caused by `RiskEngine.cs`.

No capital is placed by evaluating or failing to evaluate this class.
