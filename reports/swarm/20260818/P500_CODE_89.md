    {
        if (features.CompletedXauTrades == 0)

## Profit implication

**None from treating SHADOW as a winners list.** Negative `netSourcePnl` SHADOW rows are a **designed-reachable** outcome: quality can hit 70 on a disciplined losing tape. `/api/ops/resync` will stamp those logins `SHADOW` and, if a dest quote exists, persist demo shadow fills. That does **not** book Pepperstone / cTrader destination P&L.

- `destinationRealPnl` stays **0** while `REAL_COPY` is false and `NewOrderSingle` is off (this file’s recon note).
- Scoring 8463 Achiever accounts (and Starwave at deals-done / scored 0) is **observation**. It cannot turn a losing source book into destination profit.
- Do **not** rank or auto-size off `EarlyQualityScore` / `SHADOW` as if `netSourcePnl > 0` were implied. Overview sort is already early-score, not PnL.
- Do **not** copy `netSourcePnl` into dest / live fields. Shadow slippage Σ is also not dest P&L.
- A later “copy the SHADOW book” policy would include **net-negative** disciplined XAU tapes as first-class candidates. That is a **negative-expectancy** source set on one dest gold book.
- Extra trap: even a **green** XAU tape can paint red `netSourcePnl` because the dashboard sums **all** symbols. Copying SHADOW blindly is not +EV on either tape.

Profit capture, if it is ever built, needs an **explicit** `netSourcePnl > 0` (and more) conjunct that **does not exist** on this path.
