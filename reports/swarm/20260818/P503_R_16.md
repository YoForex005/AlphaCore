## 0. Verdict (binding) — ADMIT / REMOVE / FLATTEN implication

**REMOVE + DEST_FLATTEN; DO_NOT_ADMIT; NOT_A_PAUSE_STATE.**

The assigned rule is the right **loss-cut**: after `MaxConsecutiveXauLosses` (default **3**) completed XAU losers, stop copying that login and unwind **destination** copies. ## 2. Pause vs remove (architecture)

| Law | Token | Meaning |
|---|---|---|
| Arch §39 | `pause trader` | Risk-engine **decision** on one login: stop new copy |
| A22 §9.1 | `TraderState.PAUSED` | Manual/ops pause. Copy = **none**. Flatten/reduce is **risk-engine**, not scorer |
| A23 §4 | `PAUSE_TRADER` | Reject this intent + stop new copy for `source_login` |
| Arch §40 / A71 | `STOP_NEW` vs flatten | Stop-new leaves dest standing. Flatten is dest `CLOSE_EXPOSURE` under stronger auth |
| This engine | `RemoveAndFlatten` | Drop fake roster + request dest flatten |

`RiskEngine` **does** emit `RiskDecisionOutcome.PauseTrader`, but only for:

- `TraderRealizedLoss <= −500` → `MAX_LOSS_PER_TRADER` (**all** actions, including close — freeze-exit defect)
- `MartingaleFlag && IsIncreasing` → `MARTINGALE_BLOCK`

There is **no** consecutive-loss field on `RiskEvaluationRequest`. Streak cannot become `PauseTrader`.

`CopyTradingService` never assigns `score.CurrentState = TraderState.PAUSED`. `TraderScore` has no streak column.

If the trader is **already** `PAUSED` / `RISK_BLOCKED` / `DISQUALIFIED`, `Decide` hits the first branch and `Remove("STATE_" + state)` — so a human pause is **re-encoded as remove+flatten**, not preserved as pause.

**Implication:** the topic’s “pause the trader” is **implemented as REMOVE**, not as `PAUSED`. That is stronger (membership dropped) and weaker (next tick can AUTO_ADMIT again; see §4).

## 4. ADMIT hole + REMOVE oscillation

Streak is **not** a first-admit gate. Sequence for a SHADOW book with net > 0, 20+ XAU, last 3 losers, no ADMITTED row:

| Tick | `onRoster` | `Decide` | Hopper |
|---|---|---|---|
| T0 | false (`row` null or `REMOVED:*`) | streak skipped → **AUTO_ADMIT** | same tick: `GenerateShadowIntentsAsync` sees `ADMITTED` → may mint `:open` for still-open source tickets |
| T1 | true | streak ≥ 3 → **RemoveAndFlatten** + `FLATTEN_LOSS_CUT` | hopper `continue`s |
| T2 | false (`REMOVED:CONSECUTIVE_LOSSES_n`) | streak skipped again → **AUTO_ADMIT** | opens again |

`onRoster` is **only** `Status == "ADMITTED"`. `REMOVED:*` is off-roster. On-roster-only gates (streak, peak DD, negative book after a prior admit) therefore **do not stick**.

Negative book does **not** oscillate: off-roster `IsTraderEligible` fails `XAU_BOOK_NOT_PROFITABLE` → `Keep` / `NOT_YET_*`. Streak **does** oscillate because lifetime net can stay green.

**ADMIT implication (binding):** streak ≥ 3 must be evaluated **before** Admit, not only after. Until that exists, “pause on streak” is a one-tick lie.
