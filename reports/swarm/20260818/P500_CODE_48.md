## Angle

A demo / prop-challenge reconstructed book of **+$100** is **not** a tradable edge on the destination venue (cTrader / Pepperstone) after:

- dest bid/ask (buy ask, sell bid)
- dest commission + dest swap
- copy-latency adverse (`ShadowCopyEngine.DefaultLatencySlippagePoints = 0.05` after 250 ms)
- challenge-broker fill quality that does not exist on the live book

The +$100 figure is the **normative first-three / simple-round-trip fixture**, not a live dest fill:

- Unit reconstruction (`TradeReconstructionTests.Reconstructs_simple_round_trip`): 0.10 lot XAU, 2320 → 2330, `NetRealizedPnl` asserted **100m**.
- Gold identity: 0.10 lot × $10/oz = **$100 of source** mark-to-market. That identity is paper on the challenge book.
- Reconstruction formula: `NetRealizedPnl = Gross + Commission + Swap + fees` with **`fees = 0m` always**. Those commission/swap fields are **source deal** fields.

Question this slot answers: **does `EfDashboardQueries` prove +$100 source PnL survives venue costs?**

Answer: **No. It cannot. It does not try.**

## Verdict

**CONFIRMED_NOT_EDGE — +$100 demo challenge PnL is not an edge after venue costs.**

Reasons, all from the file that was actually read:

1. **Dest money is a painted zero.** `GetOverviewAsync` writes `DestinationRealPnl`, `XauGross`, `XauNet` as positional `0, 0, 0`. That matches the live measurement `destinationRealPnl 0`. It is not a computed “after costs = 0”; it is **no dest ledger**.
2. **The only ranking money is source challenge dollars.** `GetTradersAsync` groups completed `ReconstructedTrades` and sums `NetRealizedPnl` into `TraderRowDto.NetSourcePnl`. Web `TradersPage` labels that column **“Net P&L”**. Sort is `OrderByDescending(t => t.EarlyScore)`. `BaselineScorer` adds **+15** quality when source `NetPnl > 0`. A +$100 challenge book wins the sort without a dest-cost haircut.
3. **Source net is demo-broker economics.** Reconstruction `Fees = 0`. This query class never subtracts dest spread, dest commission, dest swap, or `SourceVsShadowSlippage` from the painted +$100.
4. **Per-trader dest / shadow $ is hardcoded 0.** Even if shadow rows exist, the leaderboard cannot show venue-adjusted PnL. Overview “Shadow P&L” is a **sum of slippage scalars**, not dest realized dollars.
5. **Live book does not corroborate.** 8463 accounts are counted (`Mt5Accounts.CountAsync`) and listed (`foreach (var account in accounts)`). Achiever is the scoring plane. Starwave **deals-done scored 0** — those logins paint `pnl = 0`, `EarlyScore = 0`, `INSUFFICIENT_DATA`. SHADOW is **all demo**. FIX may be LoggedOn (QUOTE/TRADE tiles can show healthy); `REAL_COPY` is **false**. There is **zero** dest realized to validate +$100.
6. **Risk page cannot veto on dest bleed.** `GetRiskAsync` returns `DailyPnl=0, Drawdown=0, XauLong=0, XauShort=0, XauNet=0, RealCopyEnabled=false`. A +$100 source winner copied later would not show dest drawdown here.
7. **FIX LoggedOn is not execution.** `GetFixSessionsAsync` sets `ExecutionEnabled = false` regardless of session status. `GetOverviewAsync` ORs DB `LoggedOn`/`ReadyFor*` with `_runtime.Quote.LoggedOn` / `_runtime.Trade.LoggedOn` for health only.

This file does **not** send `NewOrderSingle`. Capital is not at risk from the query class itself. The **operator risk** is treating the painted +$100 as permission to copy.

## Profit implication

- **No dest profit exists to claim.** Overview `DestinationRealPnl` is a constructor `0`. Live measurement agrees. FIX LoggedOn does not write a dest fill ledger this class can sum.
- A painted **+$100** on an Achiever challenge / first-3 book is **source** `SUM(NetRealizedPnl)`. After dest venue costs it is **not** expectancy:
  - Seed book spread **0.40 USD/oz**. On the 0.10-lot fixture (10 oz) a round-trip cross is **~$4** before dest commission.
  - Three A22 first-3 trades (`+80 / −40 / +60` = +$100 source) would pay that spread about **three times** (~$12) plus dest commission plus `0.05` latency points on delayed entries.
  - Source `Fees = 0`. Dest fees are **never applied**. `+$100 − dest spread − dest commission − dest swap − latency slip` is **unmeasured** and cannot be treated as edge.
- Ranking leak: `EarlyScore` sort plus `NetPnl > 0` → +15 quality inflates SHADOW rank for challenge winners. Copying those names **if** send were later armed would **overstate** dest profit by the full venue stack.
- Starwave **deals-done scored 0**: those of the 8463 accounts contribute **$0** source tape and **cannot** produce dest profit. Achiever scoring of challenge dollars still is not dest edge.
- Shadow “P&L” on overview is `SUM(SourceVsShadowSlippage)` — a **price-difference sum**, not `(mark − entry) × qty × contract`. It cannot prove dest profit on +$100 source.

**If this dashboard were read as a P&L system of record, profit would be a lie.** Dest real is 0. Source +$100 is paper.
