| Key | `roster:{brokerId}:{login}` |

A loser is “left on the roster” iff that login can have `Status==ADMITTED` after the book has already failed a loser rule.

## 3. Why losers are still left on the roster (confirmation FAIL)

### 3.1 Re-ADMIT undoes REMOVE (primary hole)

```72:80:D:\Prop\src\Domain\Copy\CopyRosterEngine.cs
        if (_policy.IsTraderEligible(trader, out var reason))
        {
            return new RosterDecision
            {
                Action = alreadyOnRoster ? RosterAction.Keep : RosterAction.Admit,
                Reason = alreadyOnRoster ? "KEEP" : "AUTO_ADMIT",
                FlattenDestination = false,
                AllowNewOpens = true
            };
        }
```

`net<=0` / streak / DD checks are all `alreadyOnRoster && …`. After REMOVE, `onRoster` is false, so those checks **do not run**. A SHADOW demo name with n≥20, net still +$365, and three newest losers:

```text
t0  ADMITTED
t+20s  Decide(on=true)  → RemoveAndFlatten CONSECUTIVE_LOSSES_3
       Status=REMOVED:CONSECUTIVE_LOSSES_3
t+40s  Decide(on=false) → AUTO_ADMIT (streak skipped)
       Status=ADMITTED   ← loser is back on the roster
```

Same oscillation for `DRAWDOWN_FROM_PEAK` while net stays `> 0`. `TickRosterAsync` L160–161 **rewrites** `row.Status = "ADMITTED"`.

`ExecuteDemoCopyAsync` then copies **new** dest opens for that seat (L546–598) without calling `Decide` again.

### 3.2 20 s lag: loser stays ADMITTED until the next tick

Host order: `TickRosterAsync` then hopper then demo send. A book that turns red **between** ticks remains `ADMITTED`. Hopper L233–234 re-checks `IsTraderEligible` (blocks net≤0 / blocked / size-pattern) but **does not** re-check streak or DD. `ExecuteDemoCopyAsync` does **not** call `IsTraderEligible` at all — only `Status==ADMITTED`. A just-printed 3-loss tail that is still net-green is **copied to dest** until TickRoster runs.

### 3.3 Sub-threshold losers never leave

1–2 consecutive XAU losses, or DD `< 40%` of peak, with net `> 0` → `KEEP`. By design they stay `ADMITTED`. The confirmation “losers are not left on the roster” has no extra eject for them.

### 3.4 `Keep` + `NOT_YET` vs `ADMITTED`

Off-roster ineligible names get `Keep` / `NOT_YET_*` (L86–92). That is **not** a remove. If a previous `ADMITTED` row exists and `Decide` somehow returned `Keep` without going through REMOVE, the hop **does not clear** `ADMITTED` (only Admit and RemoveAndFlatten mutate the row). Today KEEP only happens when still eligible, so this is latent, not the live hole.

### 3.5 No `PAUSED` writer

Grep of `src/` assignments of `TraderState.PAUSED`: **0**. Ingest copies `SuggestedState` from the scorer (`INSUFFICIENT_DATA` / `EARLY_SCORE` / `WATCH` / `SHADOW` / `RISK_BLOCKED`). Roster cannot latch a loser off via state.
