## 1. Domain — `Remove` is a first-class action

`RosterAction` includes `RemoveAndFlatten`. Every eject path goes through a single helper:

```128:135:D:\Prop\src\Domain\Copy\CopyRosterEngine.cs
    private static RosterDecision Remove(string reason) =>
        new()
        {
            Action = RosterAction.RemoveAndFlatten,
            Reason = reason,
            FlattenDestination = true,
            AllowNewOpens = false
        };
```

`Decide` (L44–93) ejects, in order:

| Condition | Reason | On-roster only? | Re-ADMIT possible? |
|---|---|---|---|
| `RISK_BLOCKED` / `DISQUALIFIED` / `PAUSED` | `STATE_*` | No | No (`IsTraderEligible` blocks) |
| Martingale / averaging-down / lot escalation | `SIZE_PATTERN` | No | No |
| Group not demo/contest (incl. null/blank) | `NOT_DEMO_OR_CONTEST_GROUP` | No | No |
| Completed XAU `Σ NetRealizedPnl ≤ 0` | `XAU_BOOK_TURNED_NEGATIVE` | **Yes** | No (`XAU_BOOK_NOT_PROFITABLE`) |
| Tail losses ≥ 3 (`NetRealizedPnl < 0`; scratch 0 breaks) | `CONSECUTIVE_LOSSES_n` | **Yes** | **Yes** if net still > 0 |
| Peak-to-trough ≥ 40% of peak (`peak > 0`) | `DRAWDOWN_FROM_PEAK` | **Yes** | **Yes** if net still > 0 |
| On roster and `IsTraderEligible` false | `NO_LONGER_ELIGIBLE_{reason}` | Yes | Depends on reason |

Off-roster losers with net ≤ 0 get `Keep` / `NOT_YET_XAU_BOOK_NOT_PROFITABLE` — they are **not admitted**. That is not “left on the roster.”

Class comment is explicit: *“Auto-admit eligible XAUUSD traders and auto-remove losers. Flatten is destination-only. Never touches the MT5 source book.”*

`CopyGroupFilter.IsDemoOrContest` is path-segment equality (`demo` / `contest` after `/`→`\`). Real groups are removed, not admitted.

`XauUsdOneToOneCopyPolicy.IsTraderEligible` is the **admit** lock (`XauNetPnl <= 0` → `XAU_BOOK_NOT_PROFITABLE`). It does **not** itself remove or flatten. Removal is the roster engine’s job.

`CopyLifecycle` has no roster verb. `ShouldCloseDest` requires `sourceCompleted && destFilled && !destAlreadyClosed` — a roster REMOVE does not satisfy that.

`ShouldFlattenOpenCopy(unrealized <= −150)` is unit-tested (`CopyRosterEngineTests` L120–125) and has **zero** product callers (grep: tests + definition only).

## 3. Confirmation — who is / is not left on the roster

### 3.1 Not left (PASS for the assigned question)

A name that is `ADMITTED` and then becomes a **book loser or hard-block loser** is rewritten to `REMOVED:{reason}` in the same `SaveChanges` as dest flatten intents. Next hopper/demo iteration does not see `ADMITTED`.

Unit lock: `Book_turning_negative_removes_and_flattens` (`CopyRosterEngineTests` L72–82) asserts `RemoveAndFlatten` + `FlattenDestination=true` + `XAU_BOOK_TURNED_NEGATIVE`. Same for three consecutive losses, martingale, real groups, and 40% DD.

### 3.2 Residual — still-green “losers” can sit / return (not the assigned FAIL)

Streak and peak-DD checks are gated `if (alreadyOnRoster && …)`. After REMOVE, `onRoster` is false (`Status != "ADMITTED"`). Next 20 s tick:

1. `Decide(..., alreadyOnRoster: false)` skips streak/DD.
2. If `IsTraderEligible` still true (net > 0, n≥20, demo, SHADOW+), action is **`Admit`**.
3. Hop sets `row.Status = "ADMITTED"` (L160).

That is **oscillation**, not a missing remove. A currently-losing (L-L-L) trader with a still-green book **can be back on the roster** within one tick. Same for a 40% give-back that is still net-positive.

`ShouldFlattenOpenCopy` never runs, so a dest (or source) open loser at −$151 does **not** eject the seat.

### 3.3 Residual — dest flatten on REMOVE is intent-only; demo send does not consume it

`ExecuteDemoCopyAsync` (L483–605) is a real dest path when `DemoDest` (demo host + demo sender + account ≠ `1369850`). It:

- Closes ledger fills **only** if the **source** reconstructed trade is `Completed` (L523–524 + `CopyLifecycle.ShouldCloseDest`).
- Opens new dest from **every** `ADMITTED` `roster:` seat (L542–544) with `MaxVolumeLots ≤ 0.05`.
- Never reads `FLATTEN_LOSS_CUT`.
- Never checks `IsTraderEligible` itself (trusts TickRoster).

So: **roster seat is cleared**; **demo dest lots opened while the name was ADMITTED stay open** if the source ticket is still open. That is dest-orphan risk, not “left on the roster.” `NewOrderSingleImplemented => DemoDest` — this is no longer paper-only on the demo host.

`VenueReconciled` **const false** (L20) is still what `GenerateShadowIntentsAsync` feeds `RiskEngine` (L304). Persist still forces `AllowFixSend=false` (L324). Demo send **bypasses** that evaluate.
