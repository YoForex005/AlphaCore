```1:36:D:\Prop\src\Domain\Volume\VolumeConverter.cs
namespace TraderIntelligence.Domain.Volume;

/// <summary>
/// Converts MT5 native integer volume to lots.
/// IMTDeal::Volume() / SMTMath::VolumeToDouble uses MTAPI_VOLUME_DIV = 10_000
/// (4 decimal places). IMTDeal::VolumeExt() uses 100_000_000.
/// The comment in mt5-sdk mt5_types.h ("hundredths of lots") is incorrect.
/// Existing mt5_manager.cpp copies deal-&gt;Volume(), so the default scale is 10_000.
/// </summary>
public sealed class VolumeConverter
{
    public const decimal ManagerVolumeScale = 10_000m;
    public const decimal ExtendedVolumeScale = 100_000_000m;
    public const decimal HundredthsScale = 100m;

    public decimal Scale { get; }

    public VolumeConverter(decimal scale = ManagerVolumeScale)
    {
        if (scale <= 0)
            throw new ArgumentOutOfRangeException(nameof(scale), "Volume scale must be positive.");
        Scale = scale;
    }

    public decimal ToLots(ulong native) => native / Scale;

    public ulong ToNative(decimal lots)
    {
        if (lots < 0)
            throw new ArgumentOutOfRangeException(nameof(lots));
        return (ulong)decimal.Round(lots * Scale, 0, MidpointRounding.AwayFromZero);
    }

    public static VolumeConverter Manager => new(ManagerVolumeScale);
    public static VolumeConverter Extended => new(ExtendedVolumeScale);
}
```

Header pins Manager `10_000` and calls the SDK “hundredths of lots” comment **incorrect**. That is reconstruction correctness, not a LIVE pin.

## Profit implication

Hard-false **does not protect profit.** It **would block** destination profit if it were the last refuse on a real send path. Measured dest profit is already **0** for independent reasons.

- 8463 catalog accounts cannot become destination LIVE books through this named API. Application never even calls it; `FromBaseline` also has no LIVE branch, so persist cannot write `LIVE` from the scorer.
- Achiever scores that land `SHADOW` (quality ≥ 70 and risk < 40) stay paper / `SHADOW_ONLY`. Winner tape is not copied as real cTrader exposure. That is **blocked dest profit**, not protected profit.
- Starwave `deals-done scored 0` means that broker is not in the scorer loop this pass — zero harvest from that cohort, **independent of the pin**.
- Dashboard dest real P&L is **structurally 0** (literal), independent of source PnL quality. Shadow PnL is Σ `SourceVsShadowSlippage`, not destination money.
- `VolumeConverter` cannot create profit: it only scales MT5 native volume → lots for reconstruction. Wrong scale would mis-size a **future** send and can already mis-flag martingale/escalation. Today there is no send. Copy dest size, if ever armed, goes through `QuantityNormalizer`, not this class.
- Opportunity cost is the entire destination book. There is no open dest P&L to “protect.”

If the question is “does hard-false keep us from giving back open profit?” — no live book exists to protect.

Flipping the stub to `true` **without** a send path, a persist consult, risk hop, and dest fill ledger would still leave dest P&L at 0. Do **not** flip it to “unlock profit.” There is no profit path behind the door.

## Lower-loss implication

Hard-false **does** lower loss (capital protection), together with other off-switches — **not** because `VolumeConverter` refuses LIVE.

- N=3 early evidence cannot auto-promote. Architecture / `docs/scoring.md` require SHADOW max. The pin is **stricter than required** (false for every state / every N).
- Application never calls `CanPromoteToLive`. Persist will copy whatever `SuggestedState` is. Safety today is “LIVE is not in the reachable set,” not “a gate evaluated LIVE then denied.” A future `return LIVE` in `FromBaseline` would write LIVE **without** this check.
- Measured `REAL_COPY=false` + `NewOrderSingleImplemented=false` + persist `AllowFixSend=false`: FIX may be LoggedOn and still cannot debit destination capital.
- Demo SHADOW only: a bad Achiever book cannot lose live money through this path.
- Starwave scored 0: no shadow intents from that book either (empty deal-login set).
- VolumeConverter residual: if promotion were later flipped true without dest-grid conversion, Manager `10_000` vs Extended `100_000_000` would mis-lot a send. That loss path is **not armed**. Copy already sizes via `QuantityNormalizer` (passthrough risk remains a **future** defect if wired to `35=D`).

Net: **protecting against live loss, blocking live dest profit, not protecting profit.** Assigned file is the wrong SUT for the angle.
