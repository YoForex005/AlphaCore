## 3. ADMIT implication (this file)

Admit is **not a verb here**. A trader is “admitted” only if some caller treats `IsTraderEligible == true` as “copy this login.”

Gates that must all pass (L75–114):

| Condition | Reason |
|---|---|
| `RISK_BLOCKED` / `DISQUALIFIED` / `PAUSED` | `TRADER_BLOCKED_*` |
| `INSUFFICIENT_DATA` / `EARLY_SCORE` / `WATCH` | `TRADER_NOT_SHADOW_YET` |
| Martingale / averaging / lot-escalation | `TRADER_SIZE_PATTERN_BLOCK` |
| `CompletedXauTrades < 20` | `NEED_MORE_XAU_HISTORY` |
| `XauNetPnl <= 0` | `XAU_BOOK_NOT_PROFITABLE` |
| `GroupName` starts `demo\` / `contest\` | `DEMO_OR_CONTEST_GROUP` |
| else | `TRADER_ELIGIBLE` |

Then `Evaluate` still rejects closed-winner opens (`NO_LOOKAHEAD_CLOSED_WINNER`), non-XAU, bad qty, missing limit/stop prices.

**ADMIT implication:** if XAU net is already `<= 0`, the trader is **never** eligible. There is no “admit then watch.” Profitability is a **standing** gate, re-checked each call.

## 4. REMOVE implication (this file)

**None.** After a trader was previously eligible:

1. Caller rebuilds `CopyTraderSnapshot` with a new `XauNetPnl`.
2. If that field is now `<= 0`, `IsTraderEligible` is false.
3. `Evaluate` rejects. No side effect. No roster row. No dest order.

That is **stop-accepting**, not **remove-from-roster**.

If the caller caches eligibility and does **not** re-check, the policy cannot stop anything — it is stateless.

---

## 5. FLATTEN implication (this file)

**None, and closes are blocked.** Flatten would require emitting dest `CloseExposure` (or a dedicated flatten action) **after** the book turned red. `Evaluate` cannot do that: eligibility is first.

Comment L61–62 says close is copied when the **source** closes. That path still goes through `Evaluate` → `IsTraderEligible`. Source close + dest flatten after `XauNetPnl <= 0` is **rejected by this policy**.
