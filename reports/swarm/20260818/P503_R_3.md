## 0. Verdict (binding) — ADMIT / REMOVE / FLATTEN

**YES dest-FLATTEN that one copy. NO REMOVE. NO ADMIT change.**

A single dest MTM breach is **per-copy dest risk overlay**, not trader-level roster failure and not `EMERGENCY_FLATTEN`.

| Word | Measured now | Should (policy) |
|---|---|---|
| **ADMIT** | `Decide` never looks at dest MTM. Admit is trader eligibility (SHADOW+, ≥20 completed XAU, book `> 0`, no size-pattern, not `demo\`/`contest\`). | **Unchanged.** One dest loser is variance. Do **not** refuse or revoke admit because dest MTM ≤ −cap. |
| **REMOVE** | `RemoveAndFlatten` fires on STATE / SIZE_PATTERN / DEMO / `XAU_BOOK_TURNED_NEGATIVE` / 3 consecutive realized XAU losses / 40% peak DD / no-longer-eligible. **Not** on one open dest ticket. | **Do not REMOVE.** Ejecting the trader would flatten **all** dest copies of that login (`FlattenOpenCopiesAsync`). One ticket ≠ book failure. |
| **FLATTEN** | Helper exists: `ShouldFlattenOpenCopy(unrealizedPnl) => unrealizedPnl <= -150`. **Zero product callers.** `TickRosterAsync` only flattens on **REMOVE**. No dest MTM is computed. | **YES — dest-only, that one mapped dest id, dest remaining qty.** Never MT5 source. Never the whole Pepperstone book. Never `KillSwitchMode.EmergencyFlatten`. |

## 2. Why FLATTEN that copy, not REMOVE, not ADMIT-change

### 2.1 ADMIT is trader selection

Admit answers: “does this login have a measured completed-XAU book we are willing to copy next?” One open dest print of −$151 does not flip that. Refusing admit on dest MTM would:

- churn still-green books that have one ugly ticket,
- treat dest overlay as a **selection** feature (it is not),
- confuse dest MAE with source edge.

### 2.2 REMOVE is trader failure

`CopyRosterEngine.Decide` already REMOVEs (and dest-flattens **all** that login’s dest opens) when:

| Reason | Trigger |
|---|---|
| `STATE_*` | `RISK_BLOCKED` / `DISQUALIFIED` / `PAUSED` |
| `SIZE_PATTERN` | martingale / averaging / lot-escalation |
| `DEMO_OR_CONTEST_GROUP` | `demo\` / `contest\` |
| `XAU_BOOK_TURNED_NEGATIVE` | completed XAU net `<= 0` while on roster |
| `CONSECUTIVE_LOSSES_*` | last 3 completed XAU `NetRealizedPnl < 0` |
| `DRAWDOWN_FROM_PEAK` | give-back ≥ 40% of completed-XAU peak |
| `NO_LONGER_ELIGIBLE_*` | eligibility died |

Those are **book / pattern** failures. A single dest MTM breach is not one of them.

Using `FlattenOpenCopiesAsync` for this question would flatten **winning** dest copies of the same login because one ticket is red. That is the wrong scope.

### 2.3 FLATTEN dest-only that ticket is dest ruin control

Dest is **one** Pepperstone login. Source tickets are not ours (never flatten MT5 — P500 dest-only flatten law / A48). If dest is open and dest $ is already through a hard per-copy cap, leaving it open until source SL / source close / trader REMOVE is how dest dies on a 1:1 5-lot print.

A48 still holds:

| Forbidden | This slot |
|---|---|
| Auto-flatten **account** from daily loss / DD / ML | **Still forbidden.** `GLOBAL_STOP` = stop-new only. |
| `EMERGENCY_FLATTEN` without SuperAdmin + confirm | **Not this control.** Per-copy dest-MAE is not the desk panic run. |
| Flatten source MT5 / shadow-as-if-live | **Forbidden.** |
| Size flatten from source lots | Qty = **dest remaining** (A71 §8.2). |

`docs/risk.md` “Total loss breach → Emergency Flatten” must **not** be coded as this helper.

## 3. The $150 cap is not shippable as a raw scalar

Name is `MaxUnrealizedLossLotsUsd`. Implementation is **total USD**, not per-lot. XAU = 100 oz/lot.

| Dest lots | $1 / oz | $150 cap as gold move | vs dest spread ~0.3 |
|---|---:|---:|---|
| **0.05** (working dest cap in P500 books) | $5 | **$30 / oz** | Wide. Copied source SL usually fires first. |
| 0.10 | $10 | $15 / oz | Still a dest overlay. |
| 1.00 | $100 | $1.50 / oz | Tight. |
| **5.00** (HEAD `GoldLots.MaxQuantity` × `AllocationFactor=1`) | $500 | **$0.30 / oz** | **Noise.** Would flatten every 5-lot ticket on the spread. |

HEAD 1:1 5-lot is **UNSAFE if sent** (P500_BOOK_38). A $150 total dest-MAE would then fire on **every** large ticket — a size bug wearing a flatten mask.

**Ship rule (when a later increment wires this):**

```text
cap_usd = min(configured_total, per_lot_usd * dest_lots)
         OR treat MaxUnrealizedLossLotsUsd as per-lot and multiply.

require dest MTM in real $:
  (dest_touch - entry) * sign * dest_lots * 100 oz
```

`ShadowCopyEngine.MarkToMarket` is `(px - entry) * sign * qty` with **no ounces**. P500_BOOK_57 already called this a **100× understatement** if `qty` is lots. Wiring `ShouldFlattenOpenCopy(MarkToMarket(...))` with lots would need a **$3,000 / oz** move on 0.05 lots to trip $150. The helper would be dead. Do not wire it that way.

## 4. If dest-MAE flatten is later wired — required shape

Not implemented this slot. Binding so a later coder does not call `FlattenOpenCopiesAsync` for one ticket.

1. **Identity.** Known dest position id (or shadow analog). No dest id → `MAPPING_MISSING`, **do not invent**, **do not REMOVE**.
2. **Qty.** Dest remaining, not `RequestedQuantity` re-normalized from source lots. Today’s `FlattenOpenCopiesAsync` copies `open.RequestedQuantity` — that is already the wrong qty law if allocation ever diverges.
3. **Scope.** One `source_position_id` / dest link. Not the login’s other dest copies.
4. **Key.** Consume `copy:{broker}:{login}:{position}:close` (or a dedicated `:dest_mae` that coalesces with source-close). Do **not** mint a second close when source later exits.
5. **No re-open.** Source still `!Completed` must **not** emit a new `:open`. Current open-loop idempotency (`:open` already exists) is the latch — keep it. Do **not** delete the open intent.
6. **Family.** `CLOSE_EXPOSURE` / dest-MAE reason `DEST_UNREALIZED_CAP`. Risk must **not** reject this close for `MAX_LOSS_PER_TRADER` / daily / DD (A71 G21–G22). Policy `Evaluate` must **not** require `IsTraderEligible` for this reducing action (HEAD would reject a later-red book and trap dest).
7. **Prefer copied SL.** If dest already carries source SL and that SL is tighter than the dest-MAE cap, venue SL is the 1:1 dest stop. Dest-MAE is the **ruin overlay** for missing/wide SL or oversized dest qty.
8. **Never 35=D from this report.** Persist intent only. `NewOrderSingleImplemented` stays false. Hosted log already says dest flatten is SHADOW/intent only.
