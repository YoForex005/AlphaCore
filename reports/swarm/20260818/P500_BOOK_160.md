## 2. Recalculation: how **95.50** is produced

Let `I_net = 1` iff XAU `NetPnl > 0`, `I_12 = 1` iff `PF >= 1.2`, `I_18 = 1` iff `PF >= 1.8`.

```text
quality = 50 + 15 I_net + 10 I_12 + 5 I_18 + 0.20 b − 0.25 r
```

### 2.1 PF ≥ 1.8 already implies XAU net > 0

```text
PF = GP / GL     if GL > 0
PF = 99          if GL = 0 and GP > 0
PF =  0          if GL = 0 and GP = 0
NET = GP − GL    (zero-PnL tickets drop out of both sums)
```

`PF >= 1.8` and `GL > 0` ⇒ `GP >= 1.8 GL` ⇒ `NET >= 0.8 GL > 0`.
`PF = 99` ⇒ `GP > 0 = GL` ⇒ `NET > 0`.
Therefore **`I_18 = 1` ⇒ `I_12 = 1` ⇒ `I_net = 1`**. A losing XAU book cannot fire the PF bonuses.

If `I_net = 0` then `NET <= 0` ⇒ `PF <= 1` (or 0), so both PF indicators are also 0:

```text
quality(I_net = 0) = 50 + 0.20 b − 0.25 r
quality_max(I_net = 0) = 50 + 0.20×100 − 0.25×0 = 70.00
```

70.00 is the **clean-loser-with-SL** SHADOW hole (`quality >= 70`, `risk = 0`). It is **25.50 points below 95.50**. A negative *XAU* book cannot print 95.50. A negative *dashboard* book can.

If `I_net = 1` but `PF < 1.2`: `quality_max = 50 + 15 + 20 = 85.00`.
If `I_net = 1` and `1.2 <= PF < 1.8`: `quality_max = 50 + 15 + 10 + 20 = 95.00` — **95.00, not 95.50**.

**Therefore 95.50 requires the full bonus stack:** XAU `NetPnl > 0` and `ProfitFactor >= 1.8`.

### 2.2 Unique lattice point `(b, r) = (90, 10)`

With the full stack:

```text
80 + 0.20 b − 0.25 r = 95.50
0.20 b − 0.25 r      = 15.50
multiply by 20:  4b − 5r = 310
b = (310 + 5r) / 4
```

Behavior / risk are discrete additive flags (this slot re-enumerated from L134–150):

```text
b = 100 − 30 M − 15 A − 10 C − 10 S − 10 L
r = min(100, 35 M + 20 A + 15 E + 10 C5 + 10 S3 + 10 D)
```

| Flag | Meaning | Couplings |
|---|---|---|
| `M` | martingale (`lot > 1.25×` after a loss) | risk +35, behavior −30 |
| `A` | averaging-down | risk +20, behavior −15 |
| `E` | lot escalation (`lot > 1.5×` any PnL) | risk only |
| `C` / `C5` | `LotCv > 0.4` / `LotCv > 0.5` | `C5 ⇒ C` |
| `S` / `S3` | `SlUseRate < 0.5` / `< 0.3` | `S3 ⇒ S` |
| `L` | `LossSizeCv > 0.8` | behavior only |
| `D` | `MaxDrawdown > GrossProfit` (both > 0) | risk only |

Martingale cannot reach 310: max `4b − 5r` with `M=1` is `4×70 − 5×35 = 105`.
Averaging cannot: max `4×85 − 5×20 = 240`.
Lot-escalation cannot: `4×100 − 5×15 = 325`, and no reachable `b` lands on 310 (`r=15` ⇒ `b=96.25` not on the 5-point grid).

Bound on `r` with `b ≤ 100`: `310 + 5r ≤ 400` ⇒ `r ≤ 18`. Combined with the discrete set `{0, 10, 15, 20, …}` that leaves `r ∈ {0, 10, 15}`:

| r | b required | On the 5-point behavior grid? |
|---:|---:|---|
| 0 | 77.5 | no |
| **10** | **90** | **yes** |
| 15 | 96.25 | no |

**The only lattice point that prints 95.50 is `behavior = 90`, `risk = 10`.**

`b = 90` means **exactly one** of `{C, S, L}`.
`r = 10` means **exactly one** of `{C5, S3, D}`.

Five compatible generator families (not just “no SL”):

| # | Generator | What the book looks like |
|---:|---|---|
| 1 | `S3=1`, `C=L=D=0` | **`SlUseRate < 0.3`**, flat lots, no DD>GP. **Dominant Fake + live-ingest path.** |
| 2 | `S=1`, `D=1`, `S3=C=L=0` | SL in `[0.30, 0.50)` **and** max DD > GP |
| 3 | `C5=1`, `S=L=D=0` | `LotCv > 0.5` **and** SL use `≥ 0.5` |
| 4 | `C=1`, `D=1`, `C5=S=L=0` | `LotCv ∈ (0.4, 0.5]` **and** max DD > GP, SL `≥ 0.5` |
| 5 | `L=1`, `D=1`, `C=S=0` | `LossSizeCv > 0.8` **and** max DD > GP, SL `≥ 0.5` |

The **measured** Fake / challenge fingerprint is family **1** (unused stops):

```text

  → risk += 10, behavior -= 10
```
