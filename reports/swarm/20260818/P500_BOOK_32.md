## 2. Architecture law (quoted, not wished)

### 2.1 §33 — Idempotent Order Submission

> Every destination order must have a unique client order ID.
>
> Persist before sending: `execution_intent_id`, `cl_ord_id`, … `status`.
>
> Never simply retry a NewOrderSingle because the TCP connection broke. First reconcile.

### 2.2 §34 — Unknown Execution State

```text
send order
   ↓
network disconnects
   ↓
did cServer receive it?
```

> Do NOT blindly send the order again. Set `EXECUTION_STATE_UNKNOWN`. Then use OrderStatusRequest / OrderMassStatusRequest / ExecutionReports / Position reconciliation. Only after reconciliation may the system decide whether another order is required.

cTrader RoE (A42): unique `ClOrdID` is required for Order Status to work. Logon `141=Y` **resets sequences**. The session layer will **not** retransmit the original `35=D`. The DB row **is** the memory.

## 4. Why this is lower-loss (measured mechanics, not a wish)

Lower loss here means: **do not open a second dest ticket when the first may already be live.**

### 4.1 The IOC trap (why “retry with a new id” is the ruin)

Official cTrader market (`OrdType=1`) is processed as **IOC**. After fill or expire the working-order book often **does not** still list that `ClOrdID`. After `141=Y` reconnect:

| Observation | Truth | Blind new `35=D` does |
|---|---|---|
| `35=H` `ORDER_NOT_FOUND` + dest gold qty **up** by requested size | First order **filled** | **2× dest inventory** |
| `ORDER_NOT_FOUND` + book unchanged + snapshot present | Never accepted | A **new** intent *may* be legal **after** `not_on_venue` + new risk (A42 §9) |
| `ORDER_NOT_FOUND` + book moved by a **different** qty / no snapshot | Unknown | Stay unknown. Retry = guess. |

Without persist-before-send, a crash between `Send` and the DB write looks like `not_sent`. Restart sends again. That is §34. Without a pre-send book fingerprint, recovery **cannot** legally emit `not_on_venue` for a market order (A42 §5.4 / §8.4). Stay unknown. Do not retry.

### 4.2 Dollar scale if the book is ever sent

Product `XauUsdOneToOneCopyPolicy.AllocationFactor = 1m` (1:1 lots). `GoldOuncesPerLot = 100`. `GoldLots` max **5.00**. One extra gold lot is **100 oz** of dest inventory the operator did not intend.
